### Линейная интерполяция 

Линейная интерполяция - это способ математического определения нового значения или положения, при котором оно находится между двумя уже существующими значениями. Все виды линейной интерполяции используют одну и ту же формулу:  

      p01 = (1-u) * p0 + u * p1  

Результат интерполяции точек `p0` и `p1` обычно обозначают как `p01`. В коде это выглядело бы примерно так, как показано в листинге.  

      Basic Two-Point Interpolation

```c#
Vector3 p0 = new Vector3( 0, 0, 0 );
Vector3 p1 = new Vector3( 1, 1, 0 );
float u = 0.5f;

Vector3 p01 = (1 -u) * p0 + u * p1;
Debug.Log( p01 ); // prints: ( 0.5, 0.5, 0 ), the point half-way between p0 & p1
```

В листинге кода новая точка `p01` создается путем интерполяции между точками `p0` и `p1`. Значение `u` варьируется в диапазоне от 0 до 1. Это применимо к любому количеству измерений, хотя в Unity чаще всего выполняется интерполяция векторов Vector2 и Vector3.

### Линейная интерполяция по времени

При линейной интерполяции по времени гарантируется, что процесс завершится за определенный промежуток времени, поскольку значение параметра *u* рассчитывается как отношение прошедшего времени к общей требуемой длительности интерполяции.  

**Пример для Unity - линейная интерполяция по времени**  

Чтобы создать пример для Unity, выполните следующие действия:  

1. Создайте новый проект Unity с названием *Interpolation*, используя шаблон 3D Core.
2. Создайте новую сцену на основе шаблона Built-in и сохраните её под именем *_Scene_Interp*.
3. Создайте куб в окне Hierarchy (*GameObject > 3D Object > Cube*).
    - a. Выберите Cube в окне Hierarchy и добавьте к нему компонент TrailRenderer (*Component > Effects > Trail Renderer*).
    - b. Разверните массив Materials компонента TrailRenderer и установите для элемента *Element 0* встроенный материал Default-Particle. (Нажмите на кружок справа от Element 0, чтобы найти Default-Particle в списке доступных материалов.)
4. Создайте новый C#-скрипт с названием *Interpolator* в окне Project.
Прикрепите его к объекту Cube, а затем откройте в Visual Studio и введите код из листинга.

```c# title="C# Interpolator.cs"
using UnityEngine;

public class Interpolator : MonoBehaviour {

    [Header( "Inscribed" )]
    public Vector3 p0 = new Vector3( 0, 0, 0 );
    public Vector3 p1 = new Vector3( 3, 4, 5 );
    public float timeDuration = 1;
    [Tooltip( "Set checkToStart to true to start moving." )]
    public bool checkToStart = false;

    [Header( "Dynamic" )]
    public Vector3 p01;
    public bool moving = false;
    public float timeStart;

    void Update() {
        if ( checkToStart ) {
            checkToStart = false;

            moving = true;
            timeStart = Time.time;
        }

        if ( moving ) {
            float u = ( Time.time - timeStart ) / timeDuration;
            if ( u >= 1 ) { // If u >= 1, движение завершается
                u = 1;
                moving = false;
            }

            // Вот стандартная функция линейной интерполяции
            p01 = ( 1 - u ) * p0 + u * p1;

            transform.position = p01;
        }
    }
}
```

5. Вернитесь в Unity и нажмите кнопку Play. В компоненте Cube:Interpolator (Script) установите флажок рядом с параметром checkToStart - куб переместится из точки `p0` в точку `p1` за 1 секунду. Если изменить значение `timeDuration` и снова активировать `checkToStart`, можно увидеть, что куб всегда перемещается из `p0` в `p1` за время, равное `timeDuration`. Вы также можете изменить положение `p0` или `p1` во время движения куба, и он соответствующим образом скорректирует свое перемещение.


### Линейная интерполяция с использованием парадокса Зенона

Зенон Элейский (ок. 490–430 гг. до н. э.) - древнегреческий философ, предложивший ряд парадоксов, которые указывали на философскую невозможность движения в том виде, в каком мы его воспринимаем в повседневной жизни и на основе здравого смысла.  

В парадоксе Зенона «Дихотомия» ставится вопрос о том, может ли движущийся объект когда-либо достичь неподвижной точки. Представьте себе лягушку, прыгающую к стене. С каждым прыжком она преодолевает половину оставшегося до стены расстояния. Сколько бы раз лягушка ни прыгала, после каждого прыжка ей всё равно будет оставаться преодолеть половину расстояния до стены, а значит, она никогда её не достигнет.  

Если не принимать во внимание философский подтекст (и полное отсутствие рациональности) этого подхода, то подобную концепцию в сочетании с линейной интерполяцией можно использовать для создания плавного движения с замедлением при приближении к определенной точке. Этот прием применяется в книге для реализации камер, плавно следящих за различными важными объектами (впервые этот вопрос рассматривается в главе - «Mission Demolition»).  

**Пример в Unity - Интерполяция на основе парадокса Зенона**  
Продолжайте тот же проект по интерполяции, начатый ранее:  

1. Добавьте сферу на сцену (*GameObject > 3D Object > Sphere*) и
переместите её в сторону от куба.
2. Создайте новый скрипт C# на панели Project, назовите его *ZenosFollower* и
прикрепите к сфере.
3. Откройте *ZenosFollower* в Visual Studio и введите код из листинга.

```c# title="C# ZenosFollower.cs"
using UnityEngine;

public class ZenosFollower : MonoBehaviour {

    [Header("Inscribed")]
    public GameObject poi; // Point Of Interest
    [Range(0, 1)] public float u = 0.1f;

    [Header("Dynamic")]
    public Vector3 p0;
    // p0 находится на отдельной строке, чтобы избежать трех динамических заголовков
    public Vector3 p1, p01;

    void FixedUpdate () {
        // Определите положение этого объекта и poi
        p0 = this.transform.position;
        p1 = poi.transform.position;

        // Интерполировать между двумя значениями
        p01 = (1-u)*p0 + u*p1;

        // Переместить это в новое положение
        this.transform.position = p01;
    }
}
```

4. Сохраните код и вернитесь в Unity.
5. Установите точку интереса (POI) объекта Sphere:ZenosFollower на Cube (перетащив Cube
из панели Hierarchy в слот POI объекта ZenosFollower
(Script) Inspector на Sphere).
6. Сохраните сцену!  

Теперь при нажатии кнопки Play сфера начнет двигаться к кубу. Если
выбрать куб и установить флажок checkToStart, сфера будет
продолжать следовать за кубом при его перемещении. Вы также можете
вручную перемещать куб в окне Scene и наблюдать, как сфера следует за ним.  

Попробуйте изменить значение параметра `u` в инспекторе компонента `Sphere:ZenosFollower`.
При меньших значениях сфера будет двигаться медленнее, а при больших - быстрее.
Значение 0,5 заставит сферу в каждом кадре преодолевать половину расстояния
до куба, что в точности воспроизводит парадокс дихотомии Зенона
(хотя на практике движение получается слишком уж «плотным»).
Действительно, при использовании этого кода сфера никогда не достигнет
точки, в которой находится куб, а само движение сложно контролировать,
однако этот скрипт задумывался как максимально простой и быстрый
способ реализации следования.  

В скрипте ZenosFollower вместо `Update()` используется `FixedUpdate()`, чтобы обеспечить единообразие поведения на любых компьютерах. Если бы применялся метод `Update()`, то расстояние, на котором сфера следует за объектом, менялось бы в зависимости от текущей нагрузки на процессор: из-за естественных колебаний частоты кадров количество вызовов `Update()` в секунду варьировалось бы, заставляя сферу то приближаться, то отдаляться. По той же причине при использовании `Update()` сфера следовала бы за объектом гораздо ближе на мощных компьютерах, чем на слабых. `FixedUpdate()` гарантирует стабильное поведение на любых устройствах, поскольку этот метод всегда вызывается ровно 50 раз в секунду.

>Метод `FixedUpdate()` вызывается 50 раз в секунду, поскольку значение по умолчанию для Time.fixedDeltaTime составляет 0,02 (1/50 секунды); однако частоту вызова `FixedUpdate()` можно изменить, скорректировав Time.fixedDeltaTime. Это особенно полезно, если вы изменили Time.timeScale, например, до 0,1 (замедлив работу Unity до 1/10 от обычной скорости). При Time.timeScale, равном 0,1, метод `FixedUpdate()` вызывался бы лишь раз в 0,2 секунды реального времени, что приводило бы к заметным рывкам при движении объектов, управляемых физикой. При каждом изменении Time.timeScale следует пропорционально изменять и Time.fixedDeltaTime: так, для Time.timeScale, равного 0,1, значение Time.fixedDeltaTime стоит установить на уровне 0,002, чтобы сохранить частоту в 50 вызовов `FixedUpdate()` в секунду реального времени. Это обеспечивает плавность эффектов замедленного движения.

### Интерполяция не только позиции

Можно интерполировать практически любые числовые значения. В Unity это означает, что можно с легкостью интерполировать такие параметры, как масштаб, поворот, цвет и другие.  

**Пример для Unity: интерполяция различных атрибутов**  

Это можно сделать либо в той же сцене, где выполнялись предыдущие примеры интерполяции, либо в новом проекте:  

1. Создайте новую сцену с именем _Scene_Interp2 и добавьте в её иерархию (Hierarchy) два новых куба с именами c0 и c1.
2. Создайте два новых материала (*Assets > Create > Material*) с именами *Mat_c0* и *Mat_c1*, используя для обоих стандартный шейдер (Standard shader).
3. Перетащите каждый материал на соответствующий ему куб, чтобы применить его.
4. Выберите объект c0 и задайте любые значения для его позиции, поворота и масштаба (главное, чтобы он был виден на экране, а значения масштаба по осям X, Y и Z были положительными). В окне Inspector, в разделе материала *Mat_c0*, установите желаемый цвет Albedo.
5. Выполните аналогичные действия для параметров Transform объекта c1 и цвета материала Mat_c1, убедившись, что c1 и c0 различаются по позиции, повороту, масштабу и цвету.
6. Добавьте на сцену третий куб, установите его позицию в P:[ 0, 0, 0 ] и назовите его Cube01.
7. Создайте новый C#-скрипт с именем *Interpolator2* и прикрепите его к объекту Cube01. Вставьте код из листинга в скрипт Interpolator2.

```c# title="C# Interpolator2.cs"
using UnityEngine;

public class Interpolator2 : MonoBehaviour {

    [Header("Inscribed")]
    public Transform c0;
    public Transform c1;
    public float timeDuration = 1;
    [Tooltip( "Click the checkToStart checkbox to start moving" )]
    public bool checkToStart = false;

    [Header("Dynamic")]
    public Vector3 p01;
    public Color c01;
    public Quaternion r01;
    public Vector3 s01;
    public bool moving = false;
    public float timeStart;

    private Material mat, matC0, matC1;

    void Awake() {
        mat = GetComponent<Renderer>().material;
        matC1 = c1.GetComponent<Renderer>().material;
        matC0 = c0.GetComponent<Renderer>().material;
    }

    void Update () {
        if (checkToStart) {
            checkToStart = false;

            moving = true;
            timeStart = Time.time;
        }

        if (moving) {
            float u = ( Time.time-timeStart ) /timeDuration;
            if (u>=1) {
                u=1;
                moving = false;
            }

            // This is the standard linear interpolation function
            p01 = (1-u)*c0.position + u*c1.position;
            c01 = (1-u)*matC0.color + u*matC1.color;
            s01 = (1-u)*c0.localScale + u*c1.localScale;
            // Rotations are treated differently because Quaternions are tricky
            r01 = Quaternion.SlerpUnclamped(c0.rotation, c1.rotation, u);

            // Apply these to this Cube01
            transform.position = p01;
            mat.color = c01;
            transform.localScale = s01;
            transform.rotation = r01;
        }
    }
}
```

8. Сохраните скрипт и вернитесь в Unity.
9. Перетащите объект c0 из панели Hierarchy в поле c0 компонента Interpolator2 (Script) в окне Inspector для объекта Cube01. Также перетащите объект c1 из Hierarchy в поле c1 скрипта Interpolator2.
10. Нажмите кнопку Play, а затем установите флажок checkToStart в окне Inspector для объекта Cube01 (в компоненте Interpolator2). Вы увидите, что теперь Cube01 интерполирует не только положение.  

В этом коде за вращение отвечает метод `Quaternion.SlerpUnclamped()` (название «Slerp» расшифровывается как *Spherical Linear intERPolation* - сферическая линейная интерполяция, применяемая в Unity для вращения объектов). Мы используем этот встроенный метод Unity, в частности, потому, что работа с кватернионами сопряжена со сложными математическими вычислениями (причем сложными в буквальном смысле: кватернион состоит из трех мнимых чисел и одного действительного). Вместо того чтобы независимо интерполировать каждый из компонентов кватерниона (X, Y, Z и W), алгоритм Slerp стремится выбрать кратчайший путь по поверхности сферы при переходе от одной ориентации к другой. Стандартный метод `Quaternion.Slerp()` принимает параметр `u` только в диапазоне от 0 до 1, тогда как `SlerpUnclamped()` допускает экстраполяцию.  

>Если взглянуть на документацию класса Vector3, можно заметить наличие метода `Lerp()` (сокращение от Linear intERPolation - линейная интерполяция), позволяющего интерполировать значения между векторами Vector3. Однако я практически не использую эту функцию, поскольку она ограничивает значения параметра u диапазоном [0, 1] и не допускает экстраполяции. В Unity 5 появился метод `Vector3.LerpUnclamped()`, который не ограничивает значения этим диапазоном. Хотя я и применяю версию без ограничения, я всё же считаю важным, чтобы вы научились выполнять интерполяцию (Lerp) самостоятельно; именно поэтому в коде для данного раздела мы не использовали `Vector3.LerpUnclamped()`.

### Линейная экстраполяция  

Интерполяция - это слияние двух точек с использованием значения u, которое находится в диапазоне от 0 до 1. Если значение u выходит за пределы этого диапазона, получается экстраполяция (названная так потому, что вместо интерполяции между двумя значениями она теперь
экстраполирует данные за пределы исходных двух точек).    

Если заданы две начальные точки на числовой прямой - 10 и 20, то
экстраполяция с параметром u=2 будет выглядеть так, как показано на рисунке B.

**Пример в Unity - линейная экстраполяция**  

Чтобы увидеть это в коде, дополнения в класс `Interpolator2`. Помимо экстраполяции, этот дополнительный код также обеспечивает зацикливание движения.

```c# title="C# Interpolator2.cs"
public class Interpolator2 : MonoBehaviour {

    [Header("Inscribed")]
    public Transform c0;
    public Transform c1;
    public float uMin = 0;
    public float uMax = 1;
    public float timeDuration = 1;
    public bool loopMove = false; // When true, causes the move to repeat
    [Tooltip( "Click the checkToStart checkbox to start moving" )]
    public bool checkToStart = false;
    …

    void Update () {
    …
    if (moving) {
        float u = (Time.time-timeStart)/timeDuration;
        if (u>=1) {
            u=1;
            if (loopMove) {
                timeStart = Time.time;
            } else {
                moving = false; // This line is now within the else clause
            }
        }

        // Adjust u to the range from uMin to uMax
        u = (1-u)*uMin + u*uMax;
        // ^ Look familiar? We’re using a linear interpolation here too!

        // This is the standard linear interpolation function
        p01 = (1-u)*c0.position + u*c1.position;
        …
        }
    }
}
```

Сохраните скрипт и вернитесь в Unity. Теперь, если вы нажмете кнопку Play в Unity, а затем установите флажок checkToStart у объекта Cube01, поведение системы будет таким же, как при тестировании кода из листинга B. Однако попробуйте изменить значения uMin на –1 и uMax на 2 в компоненте Interpolator2 (Script) в окне Inspector для объекта Cube01. Установите флажок checkToStart, и вы увидите, что цвет, положение, поворот и масштаб будут экстраполироваться, выходя за пределы изначально заданного диапазона. Теперь вы также можете установить флажок loopMove, чтобы зациклить процесс интерполяции.  

>В консоли может появиться предупреждение о том, что BoxCollider не поддерживает отрицательный масштаб или размер. Не обращайте на это внимания. Экстраполяция масштаба может привести к появлению отрицательных значений, однако в данном примере нас не интересует обработка столкновений.  

### Сглаживание для линейной интерполяции

Выполняемые вами до сих пор интерполяции выглядят неплохо, но в них ощущается некоторая механистичность: движение начинается резко, происходит с постоянной скоростью и так же резко прекращается. К счастью, для придания движению большей выразительности можно использовать различные функции плавности (easing functions). Проще всего это продемонстрировать на примере в Unity.  

**Пример в Unity - сглаживание интерполяции**  

Продолжите работу над проектом интерполяции, выполнив следующие шаги:  

1. Создайте новый скрипт C# с именем *Easing* и откройте его в Visual Studio, чтобы добавить код из листинга B. Обратите внимание: класс Easing не наследуется от MonoBehaviour.  

```c# title="C# Easing.cs"
using UnityEngine;

public class Easing { // Обязательно удалите «: MonoBehaviour» из этой строки! // Класс Easing не является подклассом MonoBehaviour

    public enum eType { // Перечисление eType определено внутри класса Easing, 
    // поэтому переменные типа eType за пределами этого класса должны объявляться 
    // как Easing.eType. Внутри класса Easing достаточно использовать просто eType.
        linear, easeIn, easeOut, easeInOut, sin, sinIn, sinOut
    }

    static public float Ease (float u, eType type, float val=2) { // Параметр `val` - это
    //  необязательный параметр типа `float` для статической функции `Ease()`. 
    // Он по-разному используется в качестве модификатора для многих типов интерполяции 
    // (easing). Например, для `easeIn` этот параметр определяет степень, в которую 
    // возводится `u`: если `val` равен 2, то получается `u²`, а если 3 - то `u³`. 
    // В случае синусоидальной интерполяции `val` служит множителем амплитуды синусоиды, 
    // которая добавляется к прямой линии.
        float u2 = u;

        switch (type) {
            case eType.linear: // val is ignored for Easing.eType.linear
            u2 = u;
            break;

            case eType.easeIn:
            u2 = Mathf.Pow(u, val);
            break;

            case eType.easeOut:
            u2 = 1 - Mathf.Pow( 1-u, val );
            break;

            case eType.easeInOut:
            if ( u <= 0.5f ) {
                u2 = 0.5f * Mathf.Pow( u*2, val );
            } else {
                u2 = 0.5f + 0.5f * ( 1 - Mathf.Pow( 1- (2*(u-0.5f)), val ) );
            }
            break;

            case eType.sin:
            // Try val values of 0.16f and -0.2f for Easing.eType.sin // c
            u2 = u + val * Mathf.Sin( 2*Mathf.PI*u );
            break;

            case eType.sinIn: // val is ignored for SinIn
            u2 = 1 - Mathf.Cos( u * Mathf.PI * 0.5f );
            break;

            case eType.sinOut: // val is ignored for SinOut
            u2 = Mathf.Sin( u * Mathf.PI * 0.5f );
            break;
        }

        return( u2 );
    }
}
```

На рисунке B представлено графическое изображение различных кривых сглаживания (easing curves). По горизонтальной оси отложено исходное значение u, а по вертикальной - преобразованное значение u (u2). Видно, что во всех примерах при u=0 значение u2 также равно 0, а при u=1 значение u2 равно 1. Благодаря этому, если линейная интерполяция привязана к времени, переход от p0 к p1 всегда будет занимать один и тот же промежуток времени, независимо от настроек сглаживания.  

Линейная кривая не предусматривает сглаживания (то есть u2 = u). На всех остальных представленных графиках линия u2 = u сохраняется в виде пунктирной диагонали, демонстрирующей нормальное, линейное поведение. Если вертикальная составляющая кривой оказывается ниже пунктирной диагонали, это означает, что движение отстает от линейного. И наоборот, если вертикальная составляющая кривой находится выше пунктирной диагонали, то сглаженная кривая опережает траекторию линейного движения. Наклон кривой отражает скорость интерполяции в данной точке: наклон под углом 45° соответствует скорости линейной интерполяции, тогда как более пологий наклон означает меньшую скорость, а более крутой - большую.  

Кривая EaseIn начинается медленно, а ближе к концу ускоряется (u2 = u*u). Такой тип движения называют «easing in» (плавный вход), поскольку начальный этап движения происходит «легко» и медленно, после чего скорость возрастает.

Кривая EaseOut противоположна кривой EaseIn. При её использовании
движение начинается быстро, а в конце замедляется. Этот эффект
обычно называют «easing out» (плавным замедлением в конце).  

Три синусоидальные кривые в нижней части диаграммы построены по одной и той же формуле: `u2 = u + val * sin(u*2π)`, где `val` - число с плавающей запятой (в коде это переменная `val` или `easingVal`). Умножение `u` на `2π` внутри функции `sin()` гарантирует, что при изменении `u` от 0 до 1 график проходит полный цикл синусоиды (двигаясь от центра вверх, затем через центр вниз и снова к центру). Если `val = 0`, синусоида не влияет на кривую (то есть кривая остается линейной). Чем сильнее значение `val` отклоняется от нуля (в положительную или отрицательную сторону), тем более выраженным становится это влияние.  

Кривая Sin|–0.2 представляет собой тип анимации ease-in-out с эффектом отскока. Значение –0.2 добавляет к линейному движению составляющую в виде отрицательной синусоиды: в результате объект сначала немного отступает назад от точки p0, затем быстро движется к p1, слегка проскакивает ее и, наконец, останавливается в ней. При значении, более близком к нулю (например, Sin|–0.1), объект плавно набирал бы полную скорость к середине пути, а затем замедлялся при приближении к p1, не совершая отскока за пределы конечных точек.  

В кривой Sin|0.16 к линейному изменению параметра u добавляется небольшая синусоидальная составляющая: график сначала опережает линейный, затем ненадолго приостанавливается в середине и, наконец, ускоряется, чтобы наверстать упущенное к концу движения. При перемещении объекта это позволяет подвести его к центральной точке, замедлить в середине, чтобы акцентировать на нем внимание, а затем продолжить движение.  

Кривая Sin|0.6 - это кривая плавности (easing curve), используемая объектом Enemy_2 в главе 32 («Space SHMUP - часть 2»). В данном случае к движению добавлена ​​положительная синусоидальная составляющая, заставляющая объект проскочить центральную точку и достичь положения, соответствующего примерно 80% пути к точке p1, затем вернуться к отметке 20% пути к p1 и, наконец, переместиться в точку p1.  

Обратите внимание, что функции плавности (easing functions) обеспечивают нужное поведение только при значениях параметра u в диапазоне [0, 1] и плохо справляются с экстраполяцией значений u.
