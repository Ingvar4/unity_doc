1. Создайте новый скрипт на языке C# с именем TileSwapManager в папке *__Scripts* каталога.
2. Откройте файл TileSwapManager в Visual Studio и введите код из листинга.


Вот и все. Ничего сложного, кроме определения класса TileSwap, реализующего интерфейс
Serializable, и создания списка этих объектов в TileSwapManager.  

3. Прикрепите TileSwapManager к Grid в иерархии.
4. Выберите Grid в иерархии, а затем в компоненте TileSwapManager (Script):
    - a. Нажмите на треугольник раскрытия рядом с tileSwapList.
    - b. Нажмите кнопку «+» под tileSwapList, чтобы добавить элемент в список.  

Стандартный панель свойств для TileSwaps ничем особенным не отличается; она просто показывает
каждый TileSwap, как мы видели ранее у большинства сериализуемых классов. Однако, если вы
позволите мне продемонстрировать здесь немного магии в стиле кулинарного шоу, я на самом деле
заранее подготовил пользовательскую панель свойств для класса TileSwap. Пользовательские панели
свойств позволяют разработчикам создавать настраиваемые представления редактора для своих
классов. Вы поймете, о чем я, как только мы начнем его использовать.  

5. Откройте класс TileSwapEditor в Visual Studio. Скрипт TileSwapEditor находится в папке Assets /
Scripts / ProtoTools / Editor на панели «Проект».  

В самом верху скрипта TileSwapEditor находятся две важные строки, начинающиеся с символа #, а
также одна в самом конце скрипта:  

```c#
//#define USE_TILE_SWAP_EDITOR
#if USE_TILE_SWAP_EDITOR
… // All the rest of the code is here
#endif
```

Строки, начинающиеся с символа #, называются директивами компилятора и часто используются
именно таким образом для
отключить или включить код в зависимости от определенных условий. Строка #if сообщает
компилятору: «если ты знаешь, что такое USE_TILE_SWAP_EDITOR, то скомпилируй весь код
между этой строкой и #endif». Если у компилятора нет определения для
USE_TILE_SWAP_EDITOR, то код между #if и #endif полностью игнорируется.  

6. Удалите две косые черты // из строки #define в скрипте TileSwapEditor. Теперь
первая строка должна выглядеть так:  

```c#
#define USE_TILE_SWAP_EDITOR
```

Вы также увидите, что весь код между строками #if и #endif изменит цвет с серого на обычные
цвета выделения синтаксиса, что означает, что теперь он будет компилироваться.  

>В некоторых редакторах кода это изменение цвета не происходит. Если код изначально не был серым, не беспокойтесь об этом.  

<Callout>
### Примечание [!toc]
Правильное название USE_TILE_SWAP_EDITOR (которое мы #определили) — это
символ. Символы не имеют никакого отношения к полям или переменным в C#, и
стандартный символ существует только в этом одном файле скрипта .cs, где он
#определен.  

Однако существуют также символы, которые определены как часть Unity и могут помочь
вам создать специфический код для различных ситуаций в Unity. К ним относятся:
- UNITY_EDITOR: Определяется только в редакторе
- UNITY_ANDROID: Определяется только в сборках для Android
- UNITY_2020_3: Определяется только при работе в Unity 2020.3.x
</Callout>

### Настройка TileSwaps для дверей [!toc]
Прежде чем приступить к написанию кода для выполнения TileSwaps, давайте настроим
tileSwapList для всех запертых дверей, с которыми мы можем столкнуться в игре.  

1. Выберите Grid в иерархии и в компоненте TileSwapManager (Script):
  - a. Установите значение From # в tileSwapList Tile 0 Swap равным 73. Вы увидите, что название
этого элемента изменится на Tile 7 3 Swap, а значок слева будет отображать запертую дверь,
которая может блокировать проход вправо (как показано на рисунке 36.2).
  - b. Установите значение «To К (#» № д)ля « » (Смена плитки) элемента «Tile 73 Swap» равным .07 Это
отобразит открытую дверь справа.
  - c. Продолжайте добавлять TileSwaps в tileSwapList, пока у вас не будет всех шести,
показанных на рисунке 36.2. Пока что редактируйте только поля «F rom #» и «To #» (вы еще не
создали префаб LockedDoor, который в конечном итоге будет помещен в поле «Swap Prefab
»).

>Если вы внимательно посмотрели на определение класса TileSwap в скрипте TileSwapEditor, то, возможно,
заметили, что поле toTileNum (т. е. To #) по умолчанию должно принимать значение 1 (номер базовой плитки
пола), но вместо этого по умолчанию установлено значение 0 (ноль). Это известная ошибка, над исправлением которой
работает Unity, так что, надеюсь, к моменту, когда вы это прочитаете, она уже будет исправлена.  

Как вы можете видеть, двери, ведущие вверх и вниз, состоят из двух плиток каждая. Мы
разберемся с этим, когда дойдем до разблокировки дверей. А пока давайте напишем код для
TileSwapManager, который заменит номера плиток слева на номера справа.  

2. Откройте скрипт TileSwapManager в Visual Studio и добавьте код.  
    Листинг кода TileSwapManager.cs  

```c#
public class TileSwapManager : MonoBehaviour {
    private static TileSwapManager S;
    private static Dictionary<int, TileSwap> TILE_SWAP_DICT;

    public List<TileSwap> tileSwapList;

    void Awake() {
        S = this;
    }

    public static void SWAP_TILES( int[,] map ) { // a
        if (TILE_SWAP_DICT == null) S.BuildTileSwapDict(); // b

        int fromTileNum;
        TileSwap tSwap;
        // Iterate through each tileNum in the map
        for (int i = 0; i < map.GetLength(0); i++) { // c
            for (int j = 0; j < map.GetLength(1); j++) {
                fromTileNum = map[i, j];

                if (TILE_SWAP_DICT.ContainsKey(fromTileNum)) { // d
                    tSwap = TILE_SWAP_DICT[ fromTileNum ];
                    map[i, j] = tSwap.toTileNum; // e

                    // More will be added here
                }
            }
        }
    }

    void BuildTileSwapDict() { // f
        TILE_SWAP_DICT = new Dictionary<int, TileSwap>();
        foreach (TileSwap swap in tileSwapList) {
            if (TILE_SWAP_DICT.ContainsKey( swap.fromTileNum)) { // g
                Debug.LogError("More than one TileSwap with a From # of " + swap.fromTileNum);
            } else {
                TILE_SWAP_DICT.Add( swap.fromTileNum, swap ); // h
            }
        }
    }
}
```

- a. Статический метод SWAP_TILES() будет вызван MapInfo с переданным параметром
MapInfo.MAP
.
- b. Первым делом функция SWAP_TILES() проверяет, создан ли словарь TILE_SWAP_DICT,
и, если нет, вызывает функцию BuildTileSwapDict() на синглатоне
TileSwapManager S. Дополнительную информацию см. в разделе `// f` и далее.
- c. С многомерным массивом, таким как map, можно вызвать GetLength(#), где # — это
размерность, длину которой вы хотите получить. В данном случае это используется для
итерации i по всем столбцам 0-гоизмерения и итерации j по всем строкам 1-го измерения.   

>Именно такое управление каждым измерением многомерных массивов делает их немного менее эффективными, чем
линейные (т. е. одномерные) массивы, поскольку при установке map[i, j] массив map должен убедиться, что ни i, ни j не выходят за пределы. Однако в подавляющем большинстве случаев эта неэффективность не настолько
значительна, чтобы о ней беспокоиться.  

- d. Если TILE_SWAP_DICT содержит запись для номера плитки в map[i, j], номер плитки в
map[i, j] заменяется на toTileNum из TileSwap, найденного в TILE_SWAP_DICT. В
ближайшее время будет добавлен дополнительный код для создания здесь GameObjects с
запертыми дверями.
- e. Теперь toTileNum из tSwap заменяет старый номер плитки на карте.
- f. Поскольку доступ к элементу словаря имеет постоянное время доступа, копирование всех
элементов из tileSwapList в словарь TILE_SWAP_DICT значительно ускорит замены по
всей карте.  

>Словари имеют постоянное время доступа, что означает: независимо от того, сколько элементов находится в словаре и где они в нем расположены, доступ к любому из них займет одинаковое время. Это делает их очень быстрыми для поиска информации, как обсуждается в главе 23 «Коллекции в C#».

- g. Если TILE_SWAP_DICT уже содержит TileSwap с тем же fromTileNum, что и TileSwap,
который мы пытаемся добавить, генерируется ошибка (а существующая запись остается). Это
позволит вам увидеть, не дублировали ли вы случайно запись в tileSwapList.
- h. Обмен TileSwap добавляется в TILE_SWAP_DICT с ключом
swap.fromTileNum.
