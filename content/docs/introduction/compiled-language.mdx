Фактически, каждый компьютерный чип на рынке имеет немного отличающийся набор очень простых команд, которые он понимает, известный как машинный язык. 

Этот язык очень быстро выполняется чипом, но невероятно сложен для чтения человеком. Например, строка машинного языка
`000000 00001 00010 00110 00000 100000`, безусловно, что-то будет означать для нужного компьютерного чипа, но она почти ничего не значит для человека. Однако вы могли заметить, что каждый символ этого машинного кода - это либо 0, либо 1. Это потому, что все более сложные типы данных - числа, буквы и так далее - были преобразованы в отдельные биты данных (т.е. единицы или нули).  

Если вы когда-либо слышали о людях, программирующих компьютеры с помощью перфокарт, то это именно то, что они делали: для большинства форматов двоичных перфокарт физическое пробивание отверстия в картоне представляло собой единицу, а непробитое отверстие представляло собой ноль.  

Для того чтобы людям было проще писать код, были созданы удобочитаемые языки программирования - иногда называемые языками разработки. Язык разработки можно рассматривать как промежуточный язык, предназначенный для связи между вами и компьютером.  

Языки разработки, такие как C#, достаточно логичны и просты для интерпретации компьютером, и в то же время достаточно близки к письменным человеческим языкам, чтобы программисты могли легко их читать и понимать.  

Существенное разделение также существует в языках разработки программного обеспечения между компилируемыми языками,
такими как BASIC, C++, C# и Java, и интерпретируемыми языками,
такими как JavaScript, Perl, PHP и Python.

В интерпретируемом языке создание и выполнение кода - это
двухэтапный процесс:

- Программист пишет код.
- Каждый раз, когда игрок запускает игру, код преобразуется из языка
разработки в машинный язык в режиме реального времени на
компьютере игрока.

Преимущество этого заключается в том, что это обеспечивает
переносимость кода, поскольку код может интерпретироваться специально
для того типа компьютера, на котором он запускается. Например,
JavaScript на данной веб-странице будет работать практически на любом
современном компьютере, независимо от того, работает ли на нем macOS,
Windows, Linux или одна из многих мобильных операционных систем,
таких как iOS, Android и т. д.   

Однако такая гибкость также приводит к
более медленному выполнению кода из-за времени, необходимого для
интерпретации кода на компьютере пользователя, недостаточной
оптимизации языка разработки для устройства, на котором он будет
работать, и множества других причин. Поскольку один и тот же
интерпретируемый код запускается на всех устройствах, оптимизация под
конкретное устройство, на котором он случайно запущен, невозможна.
Именно по этой причине 3D-игры, созданные на интерпретируемом языке,
таком как JavaScript, как правило, работают гораздо медленнее, чем игры,
созданные на компилируемом языке, даже при запуске на одном и том же
компьютере.

В компилируемом языке, таком как C#, процесс программирования состоит
из трех отдельных этапов:
Программист пишет код на языке разработки, таком как C#.
Компилятор преобразует код из языка разработки в
скомпилированное приложение на машинном языке для
конкретного типа машины.  

Каждый раз, когда игрок запускает игру, его компьютер
выполняет скомпилированное приложение.
Этот дополнительный промежуточный процесс компиляции преобразует
код из языка разработки в исполняемый файл (т. е. приложение или
программу), который компьютер может запускать напрямую, без
необходимости использования интерпретатора. Поскольку компилятор
полностью понимает как саму программу, так и платформу, на которой
она будет работать, он может внести в процесс множество оптимизаций. В
играх эти оптимизации напрямую приводят к более высокой частоте
смены кадров, более детализированной графике и более отзывчивому
взаимодействию. Большинство игр с большим бюджетом создаются на
компилируемом языке из-за этих преимуществ в оптимизации и скорости,
но это означает, что для каждой платформы выполнения необходимо
скомпилировать отдельный исполняемый файл.  

Во многих случаях компилируемые языки программирования подходят
только для определенных платформ выполнения. Например, Objective-C -
это проприетарный язык разработки Apple Computer для создания
приложений как для macOS, так и для iOS. Этот язык основан на C
(предшественнике C++), но включает ряд функций, уникальных для
разработки под macOS или iOS. Аналогично, XNA представлял собой
вариант C#, разработанный Microsoft несколько лет назад, чтобы дать
студентам возможность создавать игры как для персональных
компьютеров на базе Windows, так и для Xbox 360.  

В ранних версиях Unity программисты могли использовать любой из трех
различных языков разработки: C#, вариант JavaScript под названием
UnityScript или другой интерпретируемый язык под названием Boo. Unity
постепенно отказалась от Boo, а затем и от JavaScript, поскольку
сосредоточение внимания на C# позволило Unity значительно повысить
скорость выполнения скомпилированного кода.  

При компиляции кода C# Unity выполняет несколько различных шагов в
зависимости от платформы, для которой компилируется код. Сначала код
C# компилируется в промежуточный язык. Этот промежуточный язык
повышает переносимость кода Unity и может запускаться через различные скриптовые бэкэнды и процессы
компиляции для любого числа платформ, от iOS до Android, macOS,
Windows PC, интерпретируемых языков, таких как WebGL (особая форма
JavaScript, используемая на веб-страницах), и даже игровых консолей,
таких как PlayStation, Switch и Xbox.  

Возможность «написать один раз и скомпилировать где угодно» не
является уникальной особенностью Unity, но это одна из основных целей
Unity Technologies для игрового движка Unity, и она лучше интегрирована
в Unity, чем в любом другом программном обеспечении для разработки
игр, которое я видел. Однако, как игровой дизайнер, вам все равно
придется серьезно продумать различия в дизайне между игрой,
предназначенной для мобильного телефона с сенсорным управлением,
игрой, предназначенной для запуска на персональном компьютере с
управлением с помощью мыши и клавиатуры, или игрой, созданной для
виртуальной или дополненной реальности, поэтому у вас обычно будет
немного разный код для разных платформ.
