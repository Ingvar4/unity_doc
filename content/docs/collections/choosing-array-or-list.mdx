---
title: Выбор между массивом и списком
description: Массивы и списки очень похожи, поэтому люди часто не знают, что использовать в той или иной ситуации.
---

Основные различия между типами коллекций массив и List
заключаются в следующем:  

- Список имеет гибкую длину, тогда как длину массива изменить сложнее.
- Массив допускает многомерные индексы.
- Массив допускает наличие пустых элементов в середине коллекции.
- Массив работает чуть быстрее.
- Всякий раз, когда вы запрашиваете у Unity коллекцию объектов (например, при
вызове `gameObject.GetComponentsInChildren<Transform>()`), Unity
возвращает массив. Конечно, если вам нужна гибкость, вы можете легко
преобразовать его в список.  

Поскольку списки проще реализовать и они требуют меньшего предварительного
планирования (благодаря гибкой длине), я лично склонен использовать списки
гораздо чаще, чем массивы. Это особенно актуально при прототипировании игр,
поскольку прототипирование требует большой гибкости.

### Вывод

Теперь, когда вы освоили списки, словари и массивы, вы можете легко работать с большим количеством объектов в своих играх. Например, вы можете вернуться к проекту "Hello World" из главы "Hello World: Ваша первая программа" и добавить в код *CubeSpawner* список `List<GameObject>`, содержащий все новые кубы, добавленные в него в момент создания куба. Это даст вам ссылку на каждый куб, позволяя манипулировать им после его создания. Следующее упражнение покажет вам, как это сделать.  

### Итоговое упражнение

В этом упражнении вы вернетесь к проекту "Hello World" и напишете
скрипт, который будет добавлять каждый новый созданный куб в список
`List<GameObject>` с именем `gameObjectList`. В каждом кадре, в котором
куб существует, он будет уменьшаться до 95% от своего размера в предыдущем
кадре. После того как куб уменьшится до масштаба 0,1 или меньше, он будет
удален из сцены и из `gameObjectList`.  

Однако удаление элемента из `gameObjectList` во время итерации цикла
`foreach` приведет к ошибке. Чтобы этого избежать, кубы, которые необходимо
удалить, будут временно сохранены в другом списке с именем `removeList`, а
затем будет выполнена итерация по `removeList`, чтобы удалить их из
`gameObjectList`. (Вы поймете, о чем я, когда увидите код.)  

1. Откройте проект *Hello World* и создайте новую сцену (*File > New Scene* в
панели меню). В появившемся окне выберите шаблон сцены Basic (Built-in) и
нажмите кнопку Create.
2. Сохраните сцену как *_Scene_Collection (File > Save As…).*
3. Создайте новый скрипт с именем `CubeSpawnerListEx` и прикрепите его к *Main Camera* в
сцене.
4. Откройте файл `CubeSpawnerListEx` в Visual Studio и введите код, приведенный в листинге:

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class CubeSpawnerListEx : MonoBehaviour {
    public GameObject cubePrefabVar;
    public List<GameObject> gameObjectList;  
    // Will hold all the Cubes 
    [Tooltip("This is the amount that a cube will shrink each frame.")]           // a
    public float scalingFactor = 0.95f;
    public int numCubes = 0; // Total # of Cubes instantiated

    // Start is called before the first frame update
    void Start() {
        // This initializes the List<GameObject>
        gameObjectList = new List<GameObject>();
    }

    // Update is called once per frame
    void Update() {
        numCubes++; // Add to the number of Cubes                                 // b

        GameObject gObj = Instantiate<GameObject>( cubePrefabVar);                // c

        // These lines set some values on the new Cube
        gObj.name = "Cube " + numCubes;                                           // d
        Color c = new Color(Random.value, Random.value, Random.value);            // e
        gObj.GetComponent<Renderer>().material.color = c;
        // ^ Gets the Renderer of gObj & gives its Material a random color
        gObj.transform.position = Random.insideUnitSphere;                        // f

        gameObjectList.Add( gObj ); // Add gObj to the List of Cubes

        List<GameObject> removeList = new List<GameObject>();                     // g
        // ^ This removeList will store information on Cubes that should be
        // removed from gameObjectList

        // Iterate through each Cube in gameObjectList
        foreach ( GameObject goTemp in gameObjectList ) {                         // h
            // Get the scale of the Cube
            float scale = goTemp.transform.localScale.x;                          // i
            scale *= scalingFactor; // Shrink it by the
            scalingFactor
            goTemp.transform.localScale = Vector3.one * scale;

            if ( scale <= 0.1f ) { // If scale is less than 0.1f...               // j
                removeList.Add( goTemp ); // ...then add it to removeList
            }
        }

        foreach ( GameObject goTemp in removeList ) {
            gameObjectList.Remove( goTemp );                                      // k
            // ^ Remove the Cube from gameObjectList
            Destroy( goTemp ); // Destroy the Cube’s GameObject
        }
    }
}
```

**a.** Этот атрибут [Tooltip] отобразит указанное сообщение в Unity, если
навести курсор мыши на имя поля scalingFactor в панели Inspector. Это
очень полезно при работе с другими членами команды.  

**b.** Оператор инкремента (++) используется для увеличения общего количества
кубов, которые когда-либо были созданы.  

**c** Создается экземпляр cubePrefabVar. Объявление типа
"`<GameObject>`" необходимо в этом вызове Instantiate, поскольку
вы можете использовать `Instantiate()` для любого типа объекта (то
есть без объявления типа C# не имеет возможности узнать, какой тип данных
должен возвращать `Instantiate()`). "`<GameObject>`" сообщает C#, что
функция `Instantiate()` вернет GameObject.  

>В конкретном случае инстанциирования GameObjects "`<GameObject>`" теперь больше не требуется
благодаря некоторым "фокусам" Unity, но все же рекомендуется оставить его, чтобы любой, кто
читает ваш код, понимал, что происходит.  

**d.** Переменная numCubes используется для присвоения уникальных имен
каждому кубу. Первый куб будет называться Cube 1, второй — Cube 2 и так
далее.  

**e.** В строках 26 и 27 каждому кубу присваивается случайный цвет. Доступ к
цветам осуществляется через материал, прикрепленный к компоненту
Renderer GameObject, как показано в строке 27.  

**f.** `Random.insideUnitSphere` возвращает случайное местоположение
внутри сферы с радиусом 1 (с центром в точке [ 0, 0, 0 ] ). Этот код заставляет
кубы появляться в случайном месте рядом с точкой [ 0, 0, 0 ], а не все в одной
и той же точке.  

**g.** Как указано в комментариях к коду, переменная removeList будет
использоваться для хранения кубов, которые необходимо удалить из
gameObjectList. Это необходимо, поскольку C# не позволяет удалять
элементы из списка в середине цикла foreach, который выполняет итерацию
по списку. (То есть нельзя вызывать `gameObjectList.Remove()` в любом
месте внутри цикла `foreach` в строках 38–47, который выполняет итерацию
по gameObjectList.)  

**h.** Этот цикл `foreach` проходит по всем кубам в gameObjectList. Обратите
внимание, что временная переменная, созданная для цикла `foreach`,
называется `goTemp`. `goTemp` также используется в цикле `foreach` в строке
49, поэтому `goTemp` объявляется как в строке 38, так и в строке 49. Поскольку
`goTemp` имеет локальную область видимости и существует только внутри
каждого цикла foreach, конфликта, вызванного двукратным объявлением
переменной в одной и той же функции `Update()`, не возникает.  

**i.** В строках 40–42 извлекается текущий масштаб куба (путем получения x-
компоненты его `transform.localScale`), этот масштаб умножается на
95%, а затем `transform.localScale` устанавливается в это новое
значение. Умножение Vector3 на float (как это делается в строке 43) умножает каждое отдельное измерение на
это же число, поэтому `[ 2, 4, 6 ] × 0.5f` вернет `[ 1, 2, 3 ]`.  

    - localScale — это масштаб каждого `GameObject.transform` относительно его родителя (в данном случае ни у одного из кубов нет родителя, поэтому он совпадает с масштабом куба в мировой системе координат). Хотя можно установить transform.position (т. е. положение в мире, в отличие от `localPosition` (которое является положением относительно родительского объекта)), Unity не позволяет разработчикам устанавливать `transform.scale` (т. е. масштаб в мире) для Transform, поскольку это привело бы к запутанным вычислениям.  

**j.** Как упомянуто в комментариях к коду, если новый уменьшенный масштаб
GameObject goTemp меньше 0.1f, этот GameObject будет добавлен в
removeList.  

**k.** Цикл `foreach` в строках 49–53 проходит по `removeList` и удаляет из
gameObjectList любой куб, находящийся в removeList. Поскольку цикл
foreach проходит по removeList, удаление элементов из
gameObjectList не представляет никаких проблем. Удаленный GameObject
куба по-прежнему существует на экране, пока для его уничтожения не будет
использована команда `Destroy()`. Даже после этого он по-прежнему
существует в памяти компьютера, поскольку по-прежнему является элементом
removeList. Однако, поскольку removeList является локальной
переменной, область действия которой ограничена функцией `Update()`,
когда функция `Update()` завершается, removeList также перестает
существовать, и тогда любые объекты, которые хранятся исключительно в
removeList, также будут удалены из памяти сборщиком мусора C#
(процессом, управляющим памятью для C#).  

5. Сохраните скрипт CubeSpawnerListEx, а затем вернитесь в Unity.
6. Присвойте *Cube Prefab* из панели *Project* переменной *cubePrefabVar* в компоненте
*Main Camera:CubeSpawnerListEx (Script)* в инспекторе *Main Camera*.
7. Сохраните сцену и нажмите «Play» в Unity.  

Теперь вы должны увидеть, что появляется несколько кубов, как и в предыдущих
версиях Hello World. Однако теперь они со временем уменьшаются и в конечном
итоге уничтожаются (вместо того, чтобы существовать бесконечно, как в более
ранних версиях).  

Поскольку код CubeSpawnerListEx отслеживает каждый активный куб через
gameObjectList, он может изменять масштаб каждого куба в каждом кадре, а
затем уничтожать каждый куб, когда его масштаб становится меньше 0.1f. При
scalingFactor равном 0.95f каждому кубу требуется 44 кадра, чтобы
уменьшиться до масштаба `<= 0.1f;` в этот момент куб, являющийся 0-м кубом в
gameObjectList, всегда удаляется и уничтожается за то, что он слишком мал, а
счетчик в gameObjectList достигнет значения 44 и останется на этом
уровне.  

>Я сделал gameObjectList публичным, чтобы вы могли посмотреть его в Инспекторе, но стоит отметить,
что Инспектор будет отображать все 44 строки полного gameObjectList, даже если вы не показываете
список, открыв треугольник раскрытия. Я упоминаю это, потому что значительная часть обработки в каждом
кадре может уходить на отображение переменных в Инспекторе. При всего лишь 44 строках это не страшно, но однажды я
сделал публичным список, содержавший 10 000 элементов, и это замедлило воспроизведение до менее чем 1
кадра в секунду! В таком случае вы можете сделать список приватным (или присвоить ему атрибут
[HideInInspector]), чтобы повысить частоту кадров более чем в 100 раз!
