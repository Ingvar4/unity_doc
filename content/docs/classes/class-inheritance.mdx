### Реализация класса Enemy на GameObject

Выполните следующие шаги:  

1. Создайте новую сцену (*File >New Scene* в панели меню Unity). Когда
появится запрос, выберите шаблон сцены Basic (Built-in), который
включает в себя камеру и направленный свет.
2. Сохраните эту новую сцену как Scene 1 (*File > Save As…* в панели меню
Unity).
3. Создайте новую сферу в сцене (*GameObject > 3D-объект > Сфера*).  

a. Переименуйте сферу в EnemyGO (GO означает GameObject). Эта
новая сфера никак не связана со сферой в
*_Scene_0*. (Например, к ней не прикреплены скрипт-компоненты
CountItHigher или MoveAlong.)  

b. Установите значение параметра `transform.position` объекта
EnemyGO равным [0, 4, 0 ] с
помощью компонента Transform в панели Inspector.  

c. Перетащите скрипт Enemy, который вы написали ранее в листинге
кода, из панели Project на объект EnemyGO в панели Hierarchy
сцены *_Scene_1*.  

d. Выберите EnemyGO в панели Hierarchy, и вы увидите, что Enemy
(Script) теперь отображается как компонент GameObject-а EnemyGO.
Этот компонент также показывает два общедоступных поля класса
Enemy — числа с плавающей запятой speed и fireRate, хотя,
как и в случае с именем компонента, в именах полей в инспекторе
добавляются заглавные буквы и пробелы.  

4. Перетащите EnemyGO из панели «Hierarchy» в панель «Project», чтобы
создать префаб с именем EnemyGO. Как описано в предыдущих
главах, вы поймете, что префаб был создан успешно, потому что в
панели «Project» появится элемент с именем EnemyGO и значком в
виде синего квадрата, а имя GameObject EnemyGO в панели
«Hierarchy» станет синим, что указывает на то, что это экземпляр
префаба EnemyGO.
5. Выберите Main Camera в панели Hierarchy и установите для
компонентов Transform и Camera настройки, выделенные светлыми
областями в левой части рисунка  

a. В компоненте Transform инспектора установите положение [ 0 ,
-15 , -10 ] .  

b. В компоненте «Камера» (Camera) инспектора:
- Установите для параметра Clear Flags камеры значение Solid Color.
- Измените «Проекцию» камеры с «Перспективной» на
«Ортографическую».
- Установите для камеры размер (Size) равным 20 (параметр Size
отображается только для ортогональных камер).  

Панель «Игра», показанная справа на рисунке, должна
приблизительно соответствовать тому, что вы сейчас видите через
камеру, при этом сфера EnemyGO должна находиться точно в центре
верхней части экрана.

панель «Игра», на которой EnemyGo отображается вверху  

6. Нажмите «Play». Вы должны увидеть, как EnemyGO движется вниз по
экрану с постоянной скоростью.
7. Сохраните сцену! Всегда сохраняйте сцену.

### Понимание суперклассов и подклассов

Суперкласс и подкласс описывают отношения между двумя классами, где
подкласс наследуется от суперкласса. Например, класс Enemy
наследуется от MonoBehaviour, что означает, что класс Enemy
состоит не только из полей и методов, определенных в скрипте Enemy на
C#, но и из всех не-частных полей и методов его суперкласса,
MonoBehaviour, а также всех классов, от которых наследуется
MonoBehaviour. Именно поэтому любой подкласс MonoBehaviour на
C#, который мы пишем в Unity, уже знает о таких полях, как gameObject
и transform, и таких методах, как `Update()` и `GetComponent<>()`.
Также можно создавать подклассы, наследующиеся от класса Enemy:
1. Создайте новый скрипт C# на панели «Проект» и назовите его EnemyZig.
2. Откройте скрипт EnemyZig в Visual Studio.  

a. Измените суперкласс с MonoBehaviour на Enemy.  

b. Удалите методы `Start()` и `Update()`.  

После выполнения этих шагов у вас должен получиться код, показанный в
листинге:  

**Листинг EnemyZig.cs**  

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

    public class EnemyZig : Enemy { // <== Change this from MonoBehaviour to Enemy!
    // Delete all the default code that Unity puts here in the EnemyZig class
    // void Start() {…}
    // void Update() {…}
}
```

3. Создайте новый куб в сцене, выбрав *GameObject > 3D
Object > Cube* в главном меню Unity.  

a. Переименуйте куб в EnemyZigGO.  

b. В инспекторе установите для EnemyZigGO значение
transform.position равным [ - 4, 4, 0 ].  

c. Перетащите скрипт EnemyZig из панели Project на
GameObject EnemyZigGO в панели Hierarchy.  

d. Создайте префаб EnemyZigGO, перетащив EnemyZigGO из панели
«Hierarchy» в панель «Project».  

4. Нажмите «Play». Видите, как прямоугольник EnemyZigGO
движется вниз точно с той же скоростью, что и сфера EnemyGO?
Это потому, что EnemyZig унаследовал все поведения объекта
Enemy!

### Предупреждение [!toc]
БУДЬТЕ ОСТОРОЖНЫ,   УДАЛЯЯ СТАНДАРТНЫЕ
МЕТОДЫ `Start()`
И `Update()`  

 Класс EnemyZig для своей работы
полагается на наследование метода `Update()` от
Enemy. Если вы оставили пустой метод `Update()` в скрипте EnemyZig, это переопределит метод
`Update()`, унаследованный от Enemy, и EnemyZigGO не
будет перемещаться вниз по экрану.
</Callout>

5. Теперь попробуйте добавить код из листинга ниже в EnemyZig,
чтобы изменить это движение (новые строки выделены жирным
шрифтом).

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class EnemyZig : Enemy {

    public override void Move () { // a
        Vector3 tempPos = pos; // The pos property is inherited from Enemy
        tempPos.x = Mathf.Sin( Time.time * Mathf.PI * 2 ) * 4; // b
        pos = tempPos; // c
        base.Move(); // Calls Move() on the Enemy superclass // d
    }
}
```

a. Здесь вы переопределили виртуальную функцию `Move()` из
суперкласса Enemy и заменили ее новым методом `Move()` в
подклассе EnemyZig. Метод `Enemy.Move()` должен быть
объявлен как виртуальный в суперклассе, чтобы C#
разрешил его переопределение в подклассе.  

b. Эта новая функция `Move()` заставляет прямоугольник двигаться
зигзагом вправо и влево, следуя синусоиде (синус и косинус часто
полезны для такого циклического поведения). В этом коде:
- `Time.time` (которое представляет собой количество секунд
с момента нажатия кнопки «Play») умножается на 2π.
- Если взять синус этого значения, то получится число, которое
циклически меняется от 0 до 1, затем от 0 до –1 и обратно к 0 за одну
секунду (следуя синусоиде).
- Затем это циклическое значение умножается на 4, чтобы положение
по оси x варьировалось от –4 до 4.  

c. Трансформация EnemyZigGO устанавливается на эту новую позицию с
помощью свойства
свойства pos в суперклассе Enemy.  

d. Вызов `base.Move()` указывает данному экземпляру EnemyZig
вызвать версию метода `Move()` из суперкласса (или «базового»
класса) Enemy. При вызове метод суперкласса `Enemy.Move()`
заставляет EnemyZigGO двигаться вниз с той же скоростью, что и
EnemyGO, в то время как переопределённый метод
`EnemyZig.Move()` добавляет движение влево и вправо. Если бы
`base.Move()` не вызывался в методе `EnemyZig.Move()`,
EnemyZigGO по-прежнему двигался бы вправо и влево, но не
опускался бы без вызова `Enemy.Move()`.  

6. Сохраните скрипт EnemyZig в Visual Studio, вернитесь в Unity и
нажмите «Play». Экземпляр EnemyZig будет как двигаться вниз по
экрану (благодаря `Enemy.Move()`), так и двигаться зигзагом влево и
вправо (благодаря синусоидальному движению в
`EnemyZig.Move()`).  

Возможно, вы задаетесь вопросом, что вообще вызывает метод `Move()` в
EnemyZig. Это довольно тонкая особенность наследования и
переопределенных методов, требующая пояснения. Поскольку в
EnemyZig нет метода `Update()`, метод `Update()` из суперкласса
Enemy наследуется и вызывается Unity в каждом кадре. Затем, когда
унаследованный метод `Enemy.Update()` вызывает `Move()`, он сначала проверяет фактический класс,
прикрепленный к GameObject (т. е. EnemyZig), чтобы увидеть, есть ли у
него метод `Move()`, прежде чем проверять какие-либо суперклассы на
наличие методов `Move()`. Именно поэтому метод `Update()`,
унаследованный от суперкласса Enemy, вызывает переопределенный
метод `Move()` в EnemyZig в каждом кадре.
GameObjects в этом примере называются Enemies, потому что вы будете
использовать аналогичную систему иерархии классов для различных
подклассов Enemy в главе - «Космический SHMUP — Часть 2».  

## Вывод 
Способность класса объединять данные с функциональностью позволяет
разработчикам использовать объектно-ориентированный подход, который
будет представлен в следующей главе.
Объектно-ориентированное программирование (ООП) позволяет
программистам рассматривать свои классы как объекты, которые могут
двигаться и думать самостоятельно, и этот подход очень хорошо сочетается
со структурой Unity, основанной на GameObject, и поможет вам создавать
игры проще и быстрее.
