title: Подклассы MonoBehaviour - компоненты GameObject
description: Как вы видели в предыдущих главах, когда вы перетаскиваете скрипт C# на GameObject, он становится компонентом этого GameObject. 
---

Точно так же как Transform, Rigidbody и другие элементы, которые вы видите в инспекторе Unity, являются компонентами GameObject. В качестве
примера выберите *Sphere* в иерархии, и вы увидите компонент *Count It
Higher (Script)* объекта *Sphere*, отображаемый в панели инспектора. 

>Если быть абсолютно точным, класс C#, расширяющий MonoBehaviour (и имеющий то же
имя, что и файл скрипта, в котором он находится), можно прикрепить к GameObject, чтобы он
стал компонентом этого GameObject.  

<Callout>
### Примечание [!toc]
В панели *Inspector* для GameObject *Sphere* имя компонента,
*Count It Higher (Script)*, и фактическое имя класса,
`CountItHigher`, различаются так же, как имена полей в
Inspector отличаются от фактического имени поля в вашем
скрипте (т. е. перед каждой заглавной буквой в стиле camelCase
добавляется пробел).
</Callout> 

Поскольку эти подклассы MonoBehaviour являются компонентами,
вы можете получить ссылку на любой класс, прикрепленный к
GameObject, с помощью `GetComponent<T>()`, где тип класса заменяет
`T` между угловыми скобками.  

1. Создайте новый скрипт на C# с именем *MoveAlong*.
2. Прикрепите скрипт *MoveAlong* к тому же GameObject *Sphere*, что
и CountItHigher.
3. Откройте скрипт *MoveAlong* в Visual Studio и введите код из листинга:

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class MoveAlong : MonoBehaviour {

    private CountItHigher cih; // a

    void Start() {
        cih = this.gameObject.GetComponent<CountItHigher>(); // b
        if ( cih == null ) { // c
            Debug.LogWarning("No CountItHigher component on GameObject "+name);
        }
    }

    void LateUpdate() { // d
        if ( cih == null ) return; // e

        float tX = cih.currentNum / 10f; // f
        Vector3 tempLoc = pos; // g
        tempLoc.x = tX;
        pos = tempLoc;
    }

    public Vector3 pos { // h
        get { return( transform.position ); }
        set { transform.position = value; }
    }
}
```

a. cih — это частное поле типа `CountItHigher`, что означает, что
оно может содержать ссылку на экземпляр класса `CountItHigher`.
Значение этого частного поля отличается для каждого экземпляра
класса `MoveAlong` и задается в строке 10.  

b. Этот вызов `GetComponent<CountItHigher>()` находит
компонент *CountItHigher (Script)*, прикрепленный к тому же
объекту Sphere GameObject, что и этот компонент *MoveAlong (Script)*. Вызов
`GetComponent()` довольно неэффективен, поэтому на протяжении
всех статей вы увидите, как я делаю это один раз, а затем кэширую
результат (например, вызываю `GetComponent<>()` здесь, один раз
в методе `Start()` этого класса, а затем кэширую значение в `cih`).  

c. При вызове `GetComponent<>()` возможно, что искомый
компонент не был прикреплен. Если нужный компонент не
существует, результат `GetComponent<>()` будет null. В этой
строке, если `cih` равен `null`, мы записываем предупреждение в
консоль, чтобы оповестить себя. В панели «Консоль» появится
сообщение `Debug.LogWarning()` с желтым треугольным значком
вместо стандартного белого значка «речевого пузыря».  

d. `LateUpdate()` — это встроенная функция, которую Unity
вызывает в каждом кадре. В каждом кадре Unity сначала вызывает
`Update()` для всех классов, присоединенных к GameObjects, но вы
никогда не знаете, в каком порядке будут вызваны `Update()` для
различных GameObjects.   

После завершения вызовов `Update()` Unity вызывает
`LateUpdate()` для всех объектов. Использование `LateUpdate()`
в данном случае гарантирует, что метод `Update()` в классе
CountItHigher будет вызван раньше, чем метод `LateUpdate()`
в классе MoveAlong. Это позволяет избежать так называемой
«условия гонки».  

>Список всех 65 встроенных вызовов в Unity см. в разделе «Сообщения» документации по
API Unity для MonoBehaviour:
https://docs.unity3d.com/2020.3/Documentation/ScriptReference/MonoBehaviour.html
— хотя, честно говоря, вы никогда не будете использовать подавляющее большинство из
них.  

e. Если вызов `GetComponent<>()` в строке 10 (// b) завершится неудачей, то
`cih` будет равен `null` при вызове `LateUpdate()`. В строке 19 (//
f) это вызовет исключение NullReferenceException, поскольку C# попытается
получить currentNum чего-то, что является `null` (т.е.,
`cih.currentNum`). Исключения NullReferenceException могут произойти только
во время работы игры и приведут к сбою функции, в которой они возникают. Это не приведет к сбою всего компьютера, но приведет к некорректной работе остальной части функции. Чтобы избежать этого,
мы проверяем в строке 17, и если `cih` равен `null`, то возвращаемся из метода,
чтобы избежать проблемы. 

f. Хотя `cih.currentNum` является `int`, когда он используется в
математической операции с `float` (например,
`cih.currentNum/10f`) или присваивается `float` (оба случая
встречаются в строке 19), он автоматически рассматривается как
`float` (т. е. 3 рассматривается как 3.0f).  

g. В строках 20 и 22 используется свойство `pos`, которое определено в
строках 25–28.  

h. По сути, это то же самое, что и свойство `pos` класса Enemy,
но здесь используется одна строка для определения каждого из
методов доступа `get{}` и `set{}`.  

<Callout>
### Совет [!toc]
Стоит отметить, что `this.gameObject` в строке 10 (т. е.
строке // b) не является обязательным, но я включил его в эту
строку, чтобы очень точно указать, где вызывается
`GetComponent<>()`. В C# this ссылается на этот экземпляр
этого класса, на котором в данный момент выполняется код (то
есть, этот экземпляр `MoveAlong`). `this.gameObject`
ссылается на GameObject, к которому прикреплен данный экземпляр
`MoveAlong`, поэтому мы вызываем `GetComponent<>()` на
GameObject Sphere. Однако `GetComponent<>()` можно
также вызвать напрямую на любом скрипте, прикрепленном к
GameObject, поэтому следующий вариант 10-й строки даст тот
же результат, что и 10-я строка в листинге кода  

```c#
cih = GetComponent<CountItHigher>();
```

Здесь `GetComponent<>()` вызывается не на GameObject
Sphere, а на этом экземпляре `MoveAlong` (поэтому эта строка 10
не только дает тот же результат, но и полностью идентична
вызову `this.GetComponent <CountItHigher>();`).
</Callout>

При каждом вызове `LateUpdate` класс MoveAlong будет извлекать
значение `currentNum`
из компонента *CountItHigher (Script)* этого GameObject. Затем скрипт делит
`currentNum` на 10 и устанавливает положение по оси `x` GameObject
равным полученному значению (используя свойство `pos`, которое
аналогично свойству `pos`, созданному нами в классе Enemy). Поскольку
поле `_num` экземпляра CountItHigher увеличивается в каждом кадре,
GameObject также будет перемещаться вдоль оси `X`.  

4. Обязательно сохраните как этот скрипт, так и CountItHigher. В строке
меню Visual Studio выберите *«Файл» > Save All. Если Save All*
неактивно, значит вы уже все сохранили.
5. Вернитесь в Unity и нажмите кнопку «Play», чтобы увидеть, как
работает этот код. Теперь, когда CountItHigher увеличивает
значение `_num`, MoveAlong также перемещает GameObject Sphere
вдоль оси `X`.
6. Обязательно сохраните сцену (в строке меню Unity выберите
*«Файл» > «Сохранить»*).

<Callout type='idea'>
### Warning [!toc]
БЕРЕГИТЕСЬ УСЛОВИЙ ГОНКИ! (RACE CONDITIONS)  

Гонка возникает всякий раз, когда две вещи зависят друг от друга,
но вы не уверены, какая из них произойдет первой. Именно поэтому в классе `MoveAlong` используется метод `LateUpdate()`.  

Если бы в `MoveAlong` использовался метод `Update()`, было бы неясно, какой из методов Unity вызовет первым:
`CountItHigher.Update()` или
`MoveAlong.Update()`. В этом случае GameObject мог быть перемещен либо
до, либо после увеличения `_num`, в зависимости от того,
какой из них был вызван первым. Использование `LateUpdate()` в
`MoveAlong` гарантирует, что
`CountItHigher.Update()` всегда будет вызываться перед
`MoveAlong.LateUpdate()`.
</Callout>
