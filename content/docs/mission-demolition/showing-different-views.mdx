title: Отображение различных видов уровня
description: Мы хотим, чтобы игрок мог нажимать кнопку в верхней части экрана для переключения между видом рогатки, видом только замка и видом, на котором видны и то, и другое.

Начнем с настройки самой кнопки и GameObject, который будет служить POI (то есть точкой интереса
скрипта FollowCam) при просмотре как замка, так и рогатки.  

1. Создайте новый пустой GameObject (*GameObject > Create Empty*) и назовите его
*ViewBoth*.
2. Установите трансформацию ViewBoth на P:[ 25, 25, 0 ] R:[ 0, 0, 0 ] S:[ 1, 1, 1 ].
3. Добавьте кнопку интерфейса в сцену (*GameObject > UI > Button*).
    - a. Назовите эту кнопку *UIButton_View*.
    - b. Задайте для кнопки настройки RectTransform, которые вы видите в левой половине рисунка. Настройку `On Click ()` вы добавите в компонент Button позже.

<img src="/unity_doc/images/ex80.jpeg" alt="1" style={{  height: 'auto' }} />
Настройки для UIButton_View и его дочернего элемента Text  

4. Раскройте треугольник раскрытия рядом с элементом *UIButton_View* в иерархии и задайте
для дочернего элемента Text элемента UIButton_View настройки, показанные в правой части
рисунка. Вне разделов «Текст» и «Символы» ничего менять не нужно. Далее мы внесем некоторые изменения в код FollowCam, чтобы он мог управлять тремя
различными представлениями.  

5. Откройте скрипт FollowCam в Visual Studio и внесите изменения  

Листинг FollowCam.cs  

```c#
public class FollowCam : MonoBehaviour {
    static private FollowCam S; // Another private Singleton // a
    static public GameObject POI; // The static point of interest

    public enum eView { none, slingshot, castle, both }; // b

    [Header("Inscribed")]
    public float easing = 0.05f;
    public Vector2 minXY = Vector2.zero; // Vector2.zero is [0,0]
    public GameObject viewBothGO; // c

    [Header("Dynamic")]
    public float camZ; // The desired Z pos of the camera
    public eView nextView = eView.slingshot; // d

    void Awake() {
        S = this; // e
        camZ = this.transform.position.z;
    }

    void FixedUpdate () { … }

    public void SwitchView( eView newView ) { // f
        if ( newView == eView.none ) {
            newView = nextView;
        }
        switch ( newView ) { // g
            case eView.slingshot:
            POI = null;
            nextView = eView.castle;
            break;
            case eView.castle:
            POI = MissionDemolition.GET_CASTLE(); // h
            nextView = eView.both;
            break;
            case eView.both:
            POI = viewBothGO;
            nextView = eView.slingshot;
            break;
        }
    }
    public void SwitchView() { // i
        SwitchView( eView.none );
    }

    static public void SWITCH_VIEW( eView newView ) { // j
        S.SwitchView( newView );
    }
}
```

    - a. Так же, как и в скрипте MissionDemolition, мы используем здесь частный синглтон,
чтобы обеспечить возможность вызова статического публичного метода (в данном
случае `SWITCH_VIEW()` в `// g`).
    - b. Мы создаем публичный тип перечисления eView, чтобы определить различные
возможные виды. В предыдущих изданиях книги я хранил имена видов в виде строк, и
это создавало несколько проблем для моих студентов, поскольку строки были очень
подвержены опечаткам. Использование перечисления гарантирует отсутствие опечаток (или, по крайней мере, гарантирует, что
если опечатка и будет, то она будет одинаковой во всем коде, что вполне приемлемо).
Поскольку этот публичный перечислитель определен внутри FollowCam, код внутри
FollowCam может ссылаться на значение eView как eView.slingshot, но код в других
классах должен будет полностью квалифицировать его, включая также имя класса, как
`FollowCam.eView.slingshot`.
    - c. Здесь будет храниться ссылка на GameObject ViewBoth, который вы только что создали.
    - d. Здесь сохраняется не текущий вид, а тот, к которому FollowCam перейдет, если игрок
нажмет кнопку. Это используется, когда вызывается `SwitchView()` с eView.none
в качестве параметра.
    - e. Убедитесь, что вы не пропустили эту строку. Без нее `SWITCH_VIEW()` не будет работать.
    - f. Основная версия `SwitchView()` принимает в качестве входных данных параметр
eView. Если newView равно eView.none, то вместо него используется значение
nextView. Это позволит переключаться между тремя видами одним и тем же
нажатием кнопки.
    - g. Здесь обрабатывается каждый возможный newView, при этом POI переключается между
ними, а nextView настраивается. Когда игрок фактически запускает снаряд из рогатки,
класс Slingshot устанавливает POI на новый снаряд. Это не один из наших трех видов, но
это сделано специально.
    - h. Чтобы получить доступ к замку, нам нужна ссылка на него. У нас её нет, но у
синглатона MissionDemolition она есть, поэтому мы вызовем статический
публичный метод `GET_CASTLE()`, который мы написали ранее в листинге кода в строке `// g`.
    - i. Эта перегрузка метода `SwitchView()` не принимает параметров, а затем сразу
вызывает основную версию `SwitchView()` с eView.none в качестве параметра. Эта
перегрузка нужна, потому что кнопки uGUI могут вызывать только методы с
определенными типами параметров, а тип eView, который мы только что написали, к ним
не относится. Совсем скоро вы подключите UIButton_View к этой перегрузке
`SwitchView()` с помощью UnityEvent.
    - j. Этот статический метод public void `SWITCH_VIEW()` не является перегрузкой
`SwitchView()`, поскольку он имеет другое имя, но здесь используется аналогичным
образом. С его помощью другие классы (включая Slingshot) могут вызывать
`FollowCam.SWITCH_VIEW()` для переключения вида по мере необходимости.  

7. Сохраните скрипт FollowCam и вернитесь в Unity. Вам нужно настроить еще пару
вещей.
8. Выберите *_MainCamera* в иерархии.
    - a. Присвойте GameObject *ViewBoth* в иерархии полю viewBothGO компонента
FollowCam в инспекторе *_MainCamera*.
9. Выберите *UIButton_View* (в разделе Canvas) в иерархии.  

>В нижней части компонента Button в инспекторе находится раздел с названием `On Click ()`.
Именно здесь вы можете использовать UnityEvents, чтобы при нажатии кнопки вызывался
определенный код. UnityEvents используются во всех элементах uGUI для создания таких
связей типа(наблюдатель-участник). UnityEvents основаны на событиях C#, которые представляют собой более защищенную форму делегатов C#.
Делегаты - это способ предоставления псевдонима или ярлыка для вызова функции, о чем вы узнаете больше в
проекте Space SHMUP. Если вы хотите узнать больше о UnityEvents, ознакомьтесь с документацией Unity по адресу
https://docs.unity3d.com/2020.3/Documentation/Manual/UnityEvents.html.  

    - a. Нажмите кнопку «+» внизу раздела «On Click ()» компонента «Button» в инспекторе
UIButton_View.
    - b. Под кнопкой Runtime Only находится поле, в котором в данный момент отображается None
(Object). Щелкните маленькую круглую мишень справа от этого поля None (Object) и
выберите
MainCamera в появившемся окне (перейдите на вкладку Scene, а затем дважды щелкните
MainCamera). Таким образом, _MainCamera выбирается в качестве GameObject, который
будет получать вызов от UIButton_View.
    - c. Нажмите кнопку всплывающего меню, в которой в данный момент отображается No Function,
и выберите
*FollowCam > SwitchView()*. Unity формирует этот список возможных функций для
вызова, ища все публичные методы в скриптах, прикрепленных к *_MainCamera*, которые
соответствуют типу UnityEvent, который может отправить кнопка.  

Теперь при каждом нажатии на UIButton_View будет вызываться перегрузка SwitchView()
без параметров на экземпляре FollowCam, прикрепленном к GameObject _MainCamera.
Нужно внести небольшие изменения только в два скрипта, и на этом мы закончим!  

10. Откройте скрипт MissionDemolition в Visual Studio и внесите два последних изменения,
указанных в листинге кода:  

Листинг кода MissionDemolition.cs  

```c#
public class MissionDemolition : MonoBehaviour {
    …
    void StartLevel() {
        …
        UpdateGUI();

        mode = GameMode.playing;

        // Zoom out to show both
        FollowCam.SWITCH_VIEW( FollowCam.eView.both ); // a
    }

    void UpdateGUI() { … }

    void Update() {
        …
        if ( (mode == GameMode.playing) && Goal.goalMet ) {
            // Change mode to stop checking for level end
            mode = GameMode.levelEnd;
            // Zoom out to show both
            FollowCam.SWITCH_VIEW( FollowCam.eView.both ); // b
            // Start the next level in 2 seconds
            Invoke("NextLevel", 2f);
        }
    }
    …
}
```

- a. Когда начинается новый уровень, вызывается `SWITCH_VIEW()`, чтобы показать и
замок, и рогатку. Обратите внимание на «полное» использование
`FollowCam.eView.both`, поскольку eView определено внутри класса FollowCam.
- b. `SWITCH_VIEW()` также вызывается в конце уровня, чтобы камера отдалилась, как только
игрок достигнет цели. Это гораздо лучшее указание на то, что игрок преуспел, чем просто
изменение прозрачности цели.  

11. Сохраните скрипт MissionDemolition и вернитесь в Unity.
Последняя проблема, которую мы решим, - это одна из тех мелких проблем, связанных с
удобством использования. Есть проблема, из-за которой игроку может показаться, что игра
слегка глючит.
12. Попробуйте следующее, чтобы понять, о чем я говорю:
    - a. Запустите игру в Unity. Камера поднимется и отдалится, чтобы показать и рогатку, и
замок.
    - b. Нажмите кнопку «Switch View» три раза, чтобы переключиться на вид «Slingshot», вид
«Castle», а затем обратно на вид «Both».
    - c. Оставаясь в режиме «Both», выпустите снаряд, но постарайтесь не попасть в цель.
Камера будет следовать за снарядом, а когда он остановится, камера вернется в режим
«Slingshot».
    - d. Нажмите кнопку «Switch View», чтобы перейти к виду «Castle».  

Вы это почувствовали? Когда вы впервые нажали кнопку «Switch View», она «не сработала».
Затем вам пришлось нажать ее второй раз, чтобы перейти к виду «Castle». На самом деле кнопка
сработала, но, как говорил мне отец, когда я только учился программировать: «Проблема с
компьютерами в том, что они всегда делают именно то, что вы им говорите». Когда вы впервые
нажали «Switch
View, поле nextView FollowCam все еще было установлено на eView.slingshot, потому
что вы стреляли из вида eView.both. Когда вы нажали кнопку в первый раз, вид
переключился на eView.slingshot (где он уже был), а затем при втором нажатии
переключился на eView.castle. Чтобы исправить это, мы позаботимся о том, чтобы
каждый раз, когда игрок стреляет, nextView FollowCam устанавливался на eView.castle.  

13. Откройте скрипт Slingshot и добавьте строки из листинга кода:  

Листинг кода Slingshot.cs  

```c#
public class Slingshot : MonoBehaviour {
    …

    void Update() {
        …

        if ( Input.GetMouseButtonUp(0) ) { // This 0 is a zero, not an o
            …
            projRB.collisionDetectionMode =
            CollisionDetectionMode.Continuous;
            projRB.velocity = -mouseDelta * velocityMult;

            // Switch to slingshot view immediately before setting POI
            FollowCam.SWITCH_VIEW( FollowCam.eView.slingshot ); // a

            FollowCam.POI = projectile;
            …
        }
    }
}
```

- a. Переключив вид на Slingshot непосредственно перед установкой FollowCam.POI в
следующей строке, мы гарантируем, что поле nextView в FollowCam будет
установлено в eView.castle.  

Теперь, если вы попробуете выполнить тот же процесс, описанный в шаге 12, кнопка должна
работать так, как вы ожидаете. Это может показаться мелочью, но удивительно, насколько такая
небольшая неполадка может испортить игроку удовольствие от игры.  

Я всегда внимательно слежу за тем, не возникает ли в моих играх ощущение, что контроллер,
клавиатура, мышь или графический интерфейс Unity не работают. Я не раз сталкивался с
ситуациями, когда разработчики думали, что у них неисправно оборудование, тогда как на
самом деле речь шла о такой же незначительной проблеме в коде.
