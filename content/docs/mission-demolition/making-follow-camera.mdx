---
title: Создание камеры слежения
description: Вам нужна _MainCamera, чтобы следовать за снарядом после его запуска, но поведение камеры немного сложнее, чем кажется. 
---

В конечном итоге полное поведение должно быть следующим:

- A. Камера находится в начальном положении и не движется во время режима
прицеливания (aimingMode) в Slingshot.
- B. После запуска снаряда камера следует за ним (с небольшим замедлением, чтобы
следование за снарядом происходило с небольшой плавной задержкой; мы рассмотрим
это вскоре).
- C. По мере того как камера поднимается в воздух, увеличивайте `Camera.orthographicSize`, чтобы
земля оставалась в поле зрения.
- D. Когда снаряд останавливается, камера перестает следовать за ним и возвращается в
исходное положение.  

Для начала давайте просто заставим камеру двигаться, а по ходу работы будем постепенно
добавлять новые функции. Следующий код позволит камере следовать за GameObject POI
(Point of Interest). Позже мы зададим этот POI в коде Slingshot.  

1. Выберите *_MainCamera* в иерархии.
2. Чтобы создать новый скрипт FollowCam и одновременно добавить его к *_MainCamera*:
    - a. Нажмите кнопку *Add Component* внизу инспектора *_MainCamera*.
    - b. Введите FollowCam в появившуюся строку поиска. Существующий скрипт FollowCam
не будет найден, поэтому вам будет предложено создать новый скрипт.
    - c. Нажмите «New script».
    - d. Еще раз проверьте название FollowCam, а затем нажмите «Создать и добавить».  

Процесс, описанный в шаге 2, создаст новый скрипт FollowCam в папке «Assets» панели
«Project», а также добавит этот скрипт FollowCam к *_MainCamera* в качестве компонента. Это
новый рабочий процесс в Unity, которым я лично часто пользуюсь. Единственным минусом
является то, что он помещает новый скрипт на верхний уровень папки «Assets» в панели
«Project», поэтому вам нужно будет вручную переместить скрипт в папку «Scripts»,
если она у вас есть.  

3. Дважды щелкните скрипт FollowCam, чтобы открыть его, и введите строки в листинге кода:  

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class FollowCam : MonoBehaviour {
    static public GameObject POI; // The static point of interest // a

    [Header("Dynamic")]
    public float camZ; // The desired Z pos of the camera

    void Awake() {
        camZ = this.transform.position.z;
    }

    void FixedUpdate () {
        // A single-line if statement doesn’t require braces
        if (POI == null) return; // if there is no POI, then return // b

        // Get the position of the poi
        Vector3 destination = POI.transform.position;
        // Force destination.z to be camZ to keep the camera far enough away
        destination.z = camZ;
        // Set the camera to the destination
        transform.position = destination;
    }

    // void Start() {…} // Please delete the unused Start() and Update() methods
    // void Update() {…}
}
```

- a. POI - это точка интереса, за которой должна следовать камера (например, снаряд).
Поскольку POI является статическим полем, одно и то же значение POI используется
всеми экземплярами класса FollowCam, а поскольку POI является одновременно
статическим и общедоступным, к нему можно получить доступ из любого класса в
любом месте кода как FollowCam.POI. Это позволяет коду Slingshot легко сообщать
*_MainCamera*, за каким снарядом следует следовать.
- b. Если POI установлено в null (по умолчанию), метод `FixedUpdate()` возвращается,
и остальная часть кода в этом методе не выполняется.  

Поле camZ содержит начальное положение камеры по оси z. В `FixedUpdate()` камера
перемещается в положение POI, за исключением координаты z, которая в каждом кадре
устанавливается равной camZ. (Это предотвращает ситуацию, когда камера находится так
близко к POI, что POI заполняет весь кадр или становится невидимым.) Мы выбрали здесь
`FixedUpdate()` вместо `Update()`, потому что отслеживаем снаряд, который
перемещается физическим движком PhysX, а этот движок обновляется синхронно с
`FixedUpdate()`.  

4. Откройте скрипт *Slingshot* на C# и добавьте одну строку ближе к
концу `Update()`:

```c#
public class Slingshot : MonoBehaviour {
    …

    void Update() {
        …
        if ( Input.GetMouseButtonUp(0) ) { // This 0 is a zero, not an o
            …
            projRB.velocity = -mouseDelta * velocityMult;
            FollowCam.POI = projectile; // Set the _MainCamera POI
            projectile = null;
        }
    }
}
```

Эта новая строка присваивает статическому общедоступному полю FollowCam.POI
значение в виде только что выпущенного снаряда. Нажмите «Play», чтобы посмотреть, как
это выглядит:  

>Если вы видите, что Slingshot движется вместе с Projectile вместо того, чтобы двигалась _MainCamera, это, вероятно,
потому, что вы прикрепили скрипт FollowCam к Slingshot вместо _MainCamera. Просто удалите компонент FollowCam
из Slingshot, выберите _MainCamera в иерархии, нажмите «Add Component» и введите FollowCam. На этот раз
FollowCam уже будет существовать, и вы можете щелкнуть по нему, чтобы добавить его к _MainCamera  

Вы должны заметить несколько проблем:  

- a. Если достаточно уменьшить масштаб окна «Сцена», можно увидеть, что снаряд на самом
деле пролетает мимо края земли.
- b. Если вы стреляете по земле, снаряд не отскакивает и не останавливается после удара о
землю. Если вы поставите на паузу сразу после выстрела, выберете снаряд в иерархии
(чтобы выделить его и центрировать инструменты панели «Сцена» вокруг него), а затем
снимите паузу, вы увидите, что он катится при ударе о землю и никогда не перестает
катиться.  

>В левом верхнем углу окна Unity находятся две кнопки: одна переключает между Pivot и Center, а другая - между
Local и Global. Кнопка Local/Global должна быть установлена в положение Local, чтобы вы могли видеть, как Gizmo
вращается вместе с снарядом.  

- c. Когда снаряд запускается впервые, камера сразу же перемещается к месту нахождения
снаряда, что выглядит некрасиво.
- d. После того как вы сделали один выстрел, *_MainCamera* больше не находится рядом с
рогаткой, поэтому вы не можете выстрелить снова.
- e. После того как снаряд достигает определенной высоты - или если он пролетел за пределы
земли - вы видите только небо, поэтому трудно определить, на какой высоте находится
снаряд.  

Используйте следующие шаги (которые, как правило, упорядочены от самого простого
исправления к самому сложному), чтобы исправить каждую из этих проблем по порядку.  

**Проблема A**: Земля слишком мала
Исправьте проблему A, изменив трансформацию Ground, чтобы увеличить
его размер:   

Ground (Cube): P:[ 100, -10, 0 ] R:[ 0, 0, 0 ] S:[ 400, 1, 4 ]  

Это заставит землю простираться гораздо дальше вправо.  

**Проблема B**: Снаряд не отскакивает реалистично
Чтобы решить проблему B, необходимо добавить к префабу «Снаряд» как ограничения Rigidbody,
так и физический материал:  

1. Выберите префаб «Projectile» на панели «Project».
2. В компоненте Projectile Rigidbody:
    - a. Откройте треугольник раскрытия рядом с Constraints.
    - b. Установите флажок рядом с параметром «Freeze Position Z» в положение «true».
    - c. Установите флажки рядом с параметрами Freeze Rotation X, Y и Z в положение true.  

Параметр «Freeze Position Z» не позволяет снаряду приближаться к камере или удаляться от нее
(по сути, удерживая его на той же глубине по оси Z, что и земля, и замок, который будет
добавлен позже). Параметры «Freeze Rotation X», «Y» и «Z» не позволяют ему
переворачиваться.  

3. Сохраните сцену, нажмите «Play» и попробуйте снова запустить снаряд.  

Эти настройки Rigidbody не дают снаряду катиться бесконечно, но все равно что-то не так. Вы
всю жизнь сталкивались с физикой, и это дает вам интуитивное представление о том, какие
виды поведения кажутся естественными и соответствуют реальной физике. Это верно и для
ваших игроков, а это значит, что, хотя физика - сложная система, требующая большого
количества математики для моделирования, если вы сделаете так, чтобы физика в игре
ощущалась как та, к которой привыкли игроки, вам не придется объяснять им эту математику.
Добавление Physic Material может сделать ваши физически смоделированные объекты гораздо
более реалистичными.  

4. В панели меню Unity выберите *Assets > Create > Physic Material*.
5. Назовите этот физический материал *PhysMat_Projectile*.
6. Щелкните *PhysMat_Projectile* и в инспекторе установите значение отскока равным 1.
7. Перетащите *PhysMat_Projectile* из панели Project на префаб Projectile (также в панели Project),
чтобы применить его к компоненту SphereCollider префаба Projectile.  

При выборе префаба Projectile вы увидите, что в инспекторе Projectile в поле Material коллайдера
Sphere Collider назначен материал PhysMat_Projectile. Теперь, когда вы запустите снаряд, он
будет отскакивать, пока не остановится, а не просто скользить по земле.  

8. Сохраните сцену, нажмите «Play» и попробуйте запустить снаряд еще раз.  

**Проблема C**: камере требуется плавная анимация
Вы решите проблему C двумя способами: смягчением движения с помощью интерполяции и
добавлением ограничений на положение камеры. Давайте это сделаем:  

Листинг кода FollowCam.cs

```c#
public class FollowCam : MonoBehaviour {
    static public GameObject POI; // The static point of interest

    [Header("Inscribed")]
    public float easing = 0.05f;

    [Header("Dynamic")]
    …

    void FixedUpdate () {
        // A single-line if statement doesn’t require braces
        if (POI == null) return; // if there is no POI, then return

        // Get the position of the poi
        Vector3 destination = POI.transform.position;
        // Interpolate from the current Camera position toward destination
        destination = Vector3.Lerp(transform.position, destination, easing);
        // Force destination.z to be camZ to keep the camera far enough away
        destination.z = camZ;
        // Set the camera to the destination
        transform.position = destination;
    }
}
```  

Метод `Vector3.Lerp()` использует линейную интерполяцию для нахождения точки между
двумя переданными объектами Vector3, возвращая средневзвешенное значение этих двух
значений. Если значение easing равно 0, `Lerp()` возвращает первую точку
(transform.position); если easing равно 1, `Lerp()` возвращает вторую точку
(destination). Если easing имеет любое значение от 0 до 1, `Lerp()` возвращает точку
между ними (при easing равном 0.5 возвращается средняя точка, расположенная на полпути
между ними). Установка easing = 0.05f указывает Unity перемещать камеру примерно на
5% от ее текущего положения к положению POI при каждом FixedUpdate (т. е. при каждом
обновлении физического движка, которое происходит 50 раз в секунду). Поскольку POI
постоянно движется, это обеспечивает плавное следование камеры. Попробуйте
поэкспериментировать со значением easing, чтобы увидеть, как оно влияет на движение
камеры. Такое использование `Lerp()` представляет собой очень упрощенную форму линейной
интерполяции. Для получения дополнительной информации о линейной интерполяции вы
можете прочитать раздел «Интерполяция» в Приложении B «Полезные концепции», где этот
конкретный метод описан под заголовком «Линейные интерполяции с использованием парадокса
Зенона».  

2. Добавьте строки из листинга кода в FollowCam, чтобы
установить минимальные ограничения по осям X и Y для положения FollowCam, не
позволяя ей смещаться слишком далеко влево или вниз:

```c#
public class FollowCam : MonoBehaviour {
    …
    [Header("Inscribed")]
    public float easing = 0.05f;
    public Vector2 minXY = Vector2.zero; // Vector2.zero is [0,0]

    [Header("Dynamic")]
    …

    void FixedUpdate () {
        …
        // Get the position of the poi
        Vector3 destination = POI.transform.position;
        // Limit the minimum values of destination.x & destination.y
        destination.x = Mathf.Max( minXY.x, destination.x );
        destination.y = Mathf.Max( minXY.y, destination.y );
        // Interpolate from the current Camera position toward destination
        destination = Vector3.Lerp(transform.position, destination, easing);
        …
    }
}
```

Значение Vector2 minXY по умолчанию равно [0, 0], что идеально подходит для ваших
целей. Функция `Mathf.Max()` выбирает максимальное значение из двух переданных ей чисел
с плавающей запятой. Когда снаряд только запускается, его координата по оси x отрицательна,
поэтому `Mathf.Max()` гарантирует, что камера никогда не сместится влево от плоскости X =
0 в отрицательную область. Аналогично, вторая строка с `Mathf.Max()` не позволяет камере
опускаться ниже плоскости Y = 0, когда координата снаряда по оси Y меньше 0.  

**Задача D**: Возвращение для повторного выстрела  

После того как снаряд остановился, камера должна вернуться, чтобы снова сфокусироваться на
рогатке. Для этого мы подождем, пока Rigidbody снаряда не перейдет в режим ожидания (то есть
пока он не перестанет считать, что движется), а затем вернем камеру в положение [ 0, 0, 0 ].  

1. Откройте скрипт FollowCam на C# в Visual Studio и измените строки `FixedUpdate()`
из листинга кода:

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class FollowCam : MonoBehaviour {
    …

    void FixedUpdate () {
        //-- // A single-line if statement doesn’t require braces // a
        //-- if (POI == null) return; // if there is no POI, then return
        //--
        //-- // Get the position of the poi
        //-- Vector3 destination = POI.transform.position;

        Vector3 destination = Vector3.zero; // b

        if ( POI != null ) { // c
            // If the POI has a Rigidbody, check to see if it is sleeping
            Rigidbody poiRigid = POI.GetComponent<Rigidbody>();
            if ( ( poiRigid != null ) && poiRigid.IsSleeping() ) { // d
                POI = null;
            }
        }

        if ( POI != null ) { // e
            destination = POI.transform.position;
        }

        // Limit the minimum values of destination.x & destination.y
        destination.x = Mathf.Max( minXY.x, destination.x );
        …
    }
}
```

- a. Все строки, предваряемые символами `//––`, следует закомментировать или удалить. Эти
строки будут заменены новым кодом, который вы добавите.
- b. Этот новый код изначально устанавливает для destination значение по
умолчанию [ 0, 0, 0 ]. Таким образом, если позже ничего не изменится, камера вернется
в начальную точку.
- c. Далее мы проверяем, не является ли POI нулевым и имеет ли он компонент Rigidbody.
Если на POI нет компонента Rigidbody, то вызов `GetComponent<Rigidbody>()`
вернет null.
- d. Если Rigidbody poiRigid не равен null, то мы проверяем, находится ли poiRigid в
состоянии «sleeping». Rigidbody находится в состоянии «sleeping», когда он перестал
двигаться, и системе PhysX больше не нужно заботиться о его симуляции. Если
`poiRigid.IsSleeping()` равно true, то мы сбрасываем POI в null, что на следующем
кадре вернет положение камеры обратно в [ 0, 0, 0 ].
Эта строка также является отличным примером поведения оператора && при сокращении.
Если poiRigid равен null, то && уже знает, что его результатом будет false после
вычисления (poiRigid != null), поэтому он «сократится» и не будет выполнять код,
расположенный справа от &&. Это хорошо, потому что если бы poiRigid был null и
был вызван `poiRigid.isSleeping()`, мы бы получили ошибку
NullReferenceException.
- e. Поскольку состояние null у POI могло измениться (и поскольку позже нам понадобятся
POI, не имеющие компонентов Rigidbody), мы снова проверяем, является ли POI null, и
если нет, то устанавливаем пункт назначения.  

Теперь, после того как снаряд остановился (что делает `poiRigid.IsSleeping()` true),
FollowCam обнулит свой POI, возвращая камеру в исходное положение. Однако снаряду,
безусловно, требуется много времени, чтобы остановиться. Давайте поможем физическому
движку «уснуть чуть легче», то есть заставим его прекратить симуляцию физики на объекте
раньше, чем это произошло бы в противном случае.  

2. Настройте параметр Sleep Threshold в настройках Unity Physics:  

    - a. Выберите *Edit > Project Settings* в главном меню Unity и выберите вкладку Physics
(не Physics 2D).
    - b. Измените значение Sleep Threshold с 0,005 на 0,01 и закройте окно Project Settings.  

Порог сна - это величина перемещения за один кадр физического движка, при которой
Rigidbody будет продолжать симулироваться в следующем кадре. Если объект перемещается на
расстояние меньше этой величины (которую мы сейчас установили на 1 см) за один кадр, PhysX
переведет этот объект Rigidbody в режим сна и прекратит его симуляцию (т. е. перестанет
перемещать GameObject). Rigidbody выйдет из режима сна только в том случае, если произойдет
что-то, что заставит его снова двигаться (например, он столкнется с другим объектом или пол,
на котором он лежит, будет удален).  

3. Сохраните сцену, а затем запустите игру, чтобы увидеть сброс камеры.  

**Проблема E**: Масштабирование размера камеры для сохранения земли в поле зрения
Чтобы исправить проблему E, необходимо динамически настраивать параметр
orthographicSize камеры.
1. Добавьте строки из листинга кода в скрипт FollowCam:  

```c#
public class FollowCam : MonoBehaviour {
    …
    void FixedUpdate () {
        …
        // Set the camera to the destination
        transform.position = destination;
        // Set the orthographicSize of the Camera to keep Ground in view
        Camera.main.orthographicSize = destination.y + 10;
    }
}
``` 
Это работает, потому что вы знаете, что благодаря только что добавленным строкам с
`Mathf.Max()` значение destination.y никогда не будет меньше 0. Таким образом,
минимальное значение orthographicSize равно 10, и orthographicSize камеры будет
увеличиваться по мере необходимости, чтобы земля всегда оставалась в поле зрения.  

2. Нажмите кнопку 2D в верхней части панели Scene, чтобы переключиться в 2D-режим
(это упростит просмотр).
3. Дважды щелкните Ground в иерархии, чтобы уменьшить масштаб и отобразить весь
GameObject Ground в панели Scene. (Если масштаб уменьшится слишком сильно, вы
можете увеличить его с помощью колесика прокрутки мыши.)
