Откройте скрипт ProjectileLine в Visual Studio и добавьте код:  

Листинг кода ProjectileLine.cs

```c#
public class ProjectileLine : MonoBehaviour {
    static List <ProjectileLine> PROJ_LINES = new List<ProjectileLine>(); // a
    private const float DIM_MULT = 0.75f;

    private LineRenderer _line;
    private bool _drawing = true;
    …

    void Start() {
        …
        _projectile = GetComponentInParent<Projectile>();

        ADD_LINE( this ); // b
    }

    void FixedUpdate() { … }

    private void OnDestroy() { // c
        // Remove this ProjectileLine from PROJ_LINES
        PROJ_LINES.Remove( this );
    }

    static void ADD_LINE( ProjectileLine newLine ) {
        Color col; // d
        // Iterate over all the old lines and dim them
        foreach ( ProjectileLine pl in PROJ_LINES ) {
            col = pl._line.startColor; // e
            col = col * DIM_MULT;
            pl._line.startColor = pl._line.endColor = col; // f
        }
        // Add newLine to the List
        PROJ_LINES.Add( newLine ); // g
    }
}
```  

    - a. Этот `static` список используется совместно всеми экземплярами класса
ProjectileLine. При создании первого экземпляра ProjectileLine выполняется эта строка и
инициализируется список PROJ_LINES. Мы используем этот список для хранения ссылки
на каждый скрипт ProjectileLine.
    - b. В конце метода `Start()` этот вызов `ADD_LINE()` добавит данный экземпляр
ProjectileLine в список PROJ_LINES.
    - c. Однако нам также необходимо удалить этот ProjectileLine из PROJ_LINES, когда его
GameObject будет уничтожен. Это понадобится, когда мы перезагрузим сцену, чтобы
загрузить новый уровень с замком. `OnDestroy()` вызывается автоматически для любого
скрипта при его уничтожении, поэтому мы можем использовать его, чтобы аккуратно
удалить этот ProjectileLine из PROJ_LINES.
Когда вы уничтожаете GameObject, он перестает существовать, но это не приводит к его
автоматическому удалению из переменных, которые на него ссылаются. В данном случае,
если бы каждый экземпляр ProjectileLine не был удален из PROJ_LINES, в PROJ_LINES
по-прежнему существовала бы ссылка, но она не указывала бы ни на что полезное и
вызывала бы ошибку при следующем обращении к ней.
    - d. Переменная Color col будет использоваться много раз в следующем цикле
foreach, поэтому мы объявляем ее здесь один раз, а не в каждой итерации цикла.
    - e. Прежде чем ADD_LINE() фактически добавит ProjectileLine newLine в PROJ_LINES, он
сначала изменяет цвет LineRenderer всех ProjectileLines, уже находящихся в списке.
Считывается startColor LineRenderer, а затем умножается на DIM_MULT (который
равен 0.75f). Когда вы умножаете цвет на число с плавающей запятой, каждый элемент
(RGBA) умножается на это число отдельно, поэтому исходный непрозрачный белый
RGBA:[ 1, 1, 1, 1 ] превращается в более серый, полупрозрачный RGBA:[ 0.75, 0.75, 0.75, 0.75 ]. И с каждым
дополнительным выстрелом цвет умножается снова, что приводит к его дальнейшему
затуханию. (См. обсуждение последствий возможности доступа к частному полю _line в
совете, следующем за // g.)
    - f. В этой строке сначала значение col присваивается переменной pl._line.endColor, а
затем это же значение присваивается переменной pl._line.startColor. Это вполне
допустимый способ выполнения нескольких присваиваний одного и того же значения, но,
возможно, вы раньше с таким не сталкивались. Объект LineRenderer имеет как
startColor, так и endColor, поскольку его цвет представляет собой градиент, а не
отдельный цвет.
    - g. Наконец, newLine добавляется в PROJ_LINES.

### Совет [!toc]
ЧАСТНЫЕ ПОЛЯ МОГУТ БЫТЬ ВИДИМЫ ЧЛЕНАМ СВОЕГО КЛАССА  

В части кода `// e` вы можете видеть, что `ADD_LINE()` обращается к частному полю
`pl._line` и устанавливает его значение. Это может показаться странным - и мне
тоже показалось странным, когда я впервые с этим столкнулся, - потому что мы
обычно думаем о частных полях как о заблокированных, к которым ничто другое не
может получить доступ, но гораздо точнее думать о частных полях и методах как о
доступных только для их собственного класса. Поскольку статический метод
`ADD_LINE()` является частью класса ProjectileLine, он может видеть и изменять
частные поля любого экземпляра ProjectileLine. Аналогично, экземпляры ProjectileLine
также могут видеть и изменять частные поля друг друга. Честно говоря, это стало для
меня неожиданностью, когда я впервые столкнулся с этим, поэтому я хотел убедиться,
что это не удивит вас в будущем.
