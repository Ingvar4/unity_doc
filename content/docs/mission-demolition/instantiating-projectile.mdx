### Предупреждение [!toc]
НЕ ИЗМЕНЯЙТЕ БЛОКИ `OnMouseEnter()` И `OnMouseExit()` В
ПРИВЕДЕННОМ НИЖЕ ФРАГМЕНТЕ КОДА!   

Об этом уже говорилось в
предыдущих главах, но я повторю это здесь на всякий случай.
В блоках `OnMouseEnter()` и `OnMouseExit()` листинга кода для Slingshot
вы увидите символ `{ … }` (фигурные скобки вокруг многоточия). По мере того как
мы будем писать все более сложные игры, скрипты будут становиться все длиннее и
длиннее. Всякий раз, когда вы видите имя уже существующей функции, за которым
следует `{ … }`, это означает, что весь код из предыдущего листинга должен остаться неизменным между этими фигурными скобками. В листинге кода функции `OnMouseEnter()` и `OnMouseExit()` должны остаться:

```c#
void OnMouseEnter() {
    //print("Slingshot:OnMouseEnter()");
    launchPoint.SetActive( true );
}
void OnMouseExit() {
    //print("Slingshot:OnMouseExit()");
    launchPoint.SetActive( false );
}
```
Обязательно обращайте на это внимание. Везде, где вы видите многоточия в коде, это
означает, что я использовал их, чтобы сократить приведенные в этой книге фрагменты
кода и исключить то, что вы уже набрали. `{ … }` — это не настоящий код C#.
</Callout>

**Листинг Slingshot**

```c#
public class Slingshot : MonoBehaviour {
    // fields set in the Unity Inspector pane
    [Header("Inscribed")] // a
    public GameObject projectilePrefab;

    // fields set dynamically
    [Header("Dynamic")] // a
    public GameObject launchPoint;
    public Vector3 launchPos; // b
    public GameObject projectile; // b
    public bool aimingMode; // b

    void Awake() {
        Transform launchPointTrans = transform.Find("LaunchPoint");
        launchPoint = launchPointTrans.gameObject;
        launchPoint.SetActive( false );
        launchPos = launchPointTrans.position; // c
    }

    void OnMouseEnter() { … } // Do not change OnMouseEnter()

    void OnMouseExit() { … } // Do not change OnMouseExit()

    void OnMouseDown() { // d
        // The player has pressed the mouse button while over Slingshot
        aimingMode = true;
        // Instantiate a Projectile
        projectile = Instantiate( projectilePrefab ) as GameObject;
        // Start it at the launchPoint
        projectile.transform.position = launchPos;
        // Set it to isKinematic for now
        projectile.GetComponent<Rigidbody>().isKinematic = true; // e
    }
}
```

    - a. Код, заключенный в такие скобки, называется атрибутом компилятора и содержит
конкретные инструкции для Unity или компилятора. В данном случае атрибут `Header`
указывает Unity создать заголовок в окне Inspector для этого скрипта. После сохранения этого
кода выберите Slingshot в панели Hierarchy и посмотрите на компонент Slingshot (Script). Вы
увидите заголовки, разделяющие общедоступные поля на два раздела:
        - Раздел «Inscribed» содержит поля, которые необходимо настроить в инспекторе.
        - Раздел «Dynamic» содержит поля, которые будут настраиваться динамически во время
работы игры.  

В этом примере вы установите `projectilePrefab` (ссылку на префаб GameObject для всех
снарядов) в инспекторе Unity перед запуском игры, тогда как все остальные поля будут
устанавливаться динамически с помощью кода во время работы игры. Заголовки позволяют
легко увидеть разницу между ними в инспекторе.

    - b. Теперь рассмотрим другие новые поля:
          - launchPos хранит 3D-координаты launchPoint в игровом мире.
          - projectile — это ссылка на новый экземпляр Projectile, который создается.
          - aimingMode обычно имеет значение false, но устанавливается в true, когда игрок нажимает
кнопку мыши 0 над Slingshot. Эта переменная состояния позволяет остальному коду понять,
как себя вести. В следующем разделе мы напишем код для Update() Slingshot, который
запускается только тогда, когда aimingMode == true.

    - c. В методе `Awake()` мы добавили одну строку для установки launchPos.
    - d. Метод `OnMouseDown()` содержит основную часть изменений в этом листинге.
    - e. Здесь стоит отметить, что если к префабу Projectile не прикреплен компонент Rigidbody, эта
строка вызовет в Unity красную ошибку NullReferenceException. Это произойдет потому, что
вызов `GetComponent<Rigidbody>()` вернет `null`, а затем остальная часть строки
попытается установить поле isKinematic равным null (что невозможно). Подобные
строки не являются самой безопасной практикой программирования — поэтому я бы не стал
использовать их в коде для игры, которую планирую продавать, — но для простого прототипа
это обычно допустимо.  

`OnMouseDown()` будет вызван только в том единственном кадре, когда игрок нажмет кнопку
мыши над компонентом Collider GameObject Slingshot, поэтому этот метод может быть вызван
только в том случае, если мышь находится в допустимом начальном положении в пределах
Collider GameObject Slingshot. Создается экземпляр projectilePrefab и присваивается
projectile. Затем projectile помещается в положение launchPos. Наконец, для
Rigidbody снаряда устанавливается значение true для isKinematic. Когда Rigidbody
находится в кинематическим, он не перемещается автоматически под действием физики, но по-прежнему
является частью симуляции (то есть кинематический Rigidbody не будет двигаться в результате
столкновения или под действием силы тяжести, но по-прежнему может вызывать движение
других некинематических Rigidbody).

2. Выберите Slingshot на панели Hierarchy и установите для projectilePrefab префаб Projectile
на панели Project (либо щелкнув по мишени справа от projectilePrefab в инспекторе и
выбрав Projectile на вкладке Assets, либо перетащив
префаб Projectile из панели Project в поле projectilePrefab в окне Inspector).
3. Нажмите «Play», наведите указатель мыши на активную область рогатки и щелкните.
Появится экземпляр Projectile.
4. Давайте добавим ему больше возможностей. Добавьте поле velocityMult и метод
`Update()` из листинга кода в код класса Slingshot:

**Листинг кода Slingshot.cs**

```c#
public class Slingshot : MonoBehaviour {
    // Inscribed fields are set in the Unity Inspector pane
    [Header("Inscribed")]
    public GameObject projectilePrefab;
    public float velocityMult = 10f; // a

    …

    void OnMouseDown() { … }

    void Update() {
        // If Slingshot is not in aimingMode, don’t run this code
        if (!aimingMode) return; // b

        // Get the current mouse position in 2D screen coordinates
        Vector3 mousePos2D = Input.mousePosition; // c
        mousePos2D.z = -Camera.main.transform.position.z;
        Vector3 mousePos3D = Camera.main.ScreenToWorldPoint( mousePos2D );

        // Find the delta from the launchPos to the mousePos3D
        Vector3 mouseDelta = mousePos3D -launchPos;
        // Limit mouseDelta to the radius of the Slingshot SphereCollider // d
        float maxMagnitude = this.GetComponent<SphereCollider>().radius;
        if (mouseDelta.magnitude > maxMagnitude) {
            mouseDelta.Normalize();
            mouseDelta *= maxMagnitude;
        }
        // Move the projectile to this new position
        Vector3 projPos = launchPos + mouseDelta;
        projectile.transform.position = projPos;

        if ( Input.GetMouseButtonUp(0) ) { // This 0 is a zero, not an o // e
            // The mouse has been released
            aimingMode = false;
            Rigidbody projRB = projectile.GetComponent<Rigidbody>();
            projRB.isKinematic = false; // f
            projRB.collisionDetectionMode = CollisionDetectionMode.Continuous;
            projRB.velocity = -mouseDelta * velocityMult;
            projectile = null; // g
        }
    }
}
```

    - a. Не забудьте добавить эту строку.
    - b. Если Slingshot не находится в режиме aimingMode, то вернитесь и не выполняйте остальную
часть этого кода.
    - c. Преобразуйте положение мыши из экранных координат в координаты мира.
    - d. Этот код ограничивает движение снаряда, чтобы его центр оставался в радиусе Sphere
Collider на Slingshot. Подробнее об этом — вскоре.
    - e. Здесь, вместо того чтобы запускать метод `OnMouseUp()`, мы считываем состояние
кнопки мыши 0 с помощью `Input.GetMouseButtonUp(0)`. Это вернет `true` только в
том Update (т. е. кадре), в котором игрок отпустил кнопку мыши.
    - f. Установка `isKinematic` обратно в `false` позволяет снаряду теперь лететь в воздухе на
основе физической симуляции. В следующей строке мы устанавливаем режим
обнаружения столкновений (Collision Detection Mode) в continuous. Пожалуйста, смотрите панель «Обнаружение столкновений: дискретное против непрерывного».
    - g. Установка поля projectile обратно в `null` разрывает связь между этим экземпляром
скрипта Slingshot и GameObject снаряда. Это хорошая задача по очистке. Если бы мы не
разорвали эту связь, а позже код уничтожил этот снаряд, то оставшаяся ссылка на него
помешала бы повторному использованию памяти компьютера, занимаемой снарядом, для
других целей.

<Callout>
### Обнаружение столкновений: дискретное против непрерывного [!toc]
Если вы посмотрите на компонент Rigidbody, то увидите, что там есть всплывающее
меню для выбора Collision Detection. Устанавливая collisionDetectionMode для
Rigidbody, мы настраиваем то же самое. Вот объяснение различных значений:  

- Discrete: Rigidbody проверяет столкновения только в каждом FixedUpdate. Это
наиболее эффективно, но также может означать, что если быстро движущийся снаряд
находится по одну сторону тонкой стены в одном FixedUpdate и по другую сторону в
следующем FixedUpdate (но не касается стены ни в одном кадре), дискретный режим
вообще не увидит столкновения.
- Continuous: этот режим более точен для быстро движущихся объектов, таких как
снаряд, поскольку он проверяет столкновения между циклами FixedUpdate. Однако
для этого требуется больше вычислительной мощности процессора.
- Continuous Dynamic: если бы вы создавали игру в бильярд с несколькими
быстро движущимися шарами, каждый шар нужно было бы настроить на
«Непрерывный динамический», чтобы точно сталкиваться с другими. Это связано с
тем, что предыдущий режим «Непрерывный» проверяет движущийся объект только
относительно статических (неподвижных) положений других объектов в кадре.
«Непрерывный динамический» нужен, когда вы хотите убедиться, сталкиваются ли друг с другом два быстро движущихся объекта. Это, конечно, требует значительно большей вычислительной мощности, чем любой другой режим.
- Continuous Speculative: этот режим нужен, если вы хотите обрабатывать
кинематический Rigidbody так, как будто у него включено непрерывное
обнаружение столкновений. Другие формы непрерывного обнаружения
столкновений полагаются на скорость Rigidbody для проверки столкновений между
кадрами, но кинематический Rigidbody не использует свою скорость, поэтому
«Continuous Speculative» использует другие вычисления, чтобы предположить (т. е.
угадать), с чем кинематический Rigidbody столкнулся между кадрами. На самом
деле это менее ресурсоемко для процессора, чем другие формы непрерывного
обнаружения, но и менее точно.

В предыдущих изданиях книги мы просто устанавливали для Projectile режим Collision
Detection на Continuous и оставляли так, но в более поздних версиях Unity, если вы
установите для Rigidbody с Continuous collision detection значение isKinematic, Unity
выдаст предупреждение в консоль, поэтому я хотел показать вам, как установить
collisionDetection-Mode в коде и избежать этого предупреждения.  

Для получения дополнительной информации о типах обнаружения столкновений
нажмите на значок справки в правом верхнем углу компонента Rigidbody.
</Callout>

Большая часть кода из листинга объясняется в строчных комментариях; однако связанные с
ним векторные вычисления требуют более тщательного изучения.  

Как видно на рисунке, векторы складываются и вычитаются по одной компоненте за раз
(то есть измерения x и y обрабатываются отдельно). Рисунок двумерный, но те же методы
работают и в 3D. Компоненты x векторов A и B вычитаются независимо от компонентов y,
образуя новый Vector2, равный Vector2( 2-5, 8-3 ), который становится Vector2( -3, 5 ). На
рисунке показано, что A-B дает нам векторное расстояние между A и B (при этом начало
вектора находится в точке [0,0], также известной как начало координат). Этот же векторный
результат является расстоянием и направлением, в котором нужно двигаться, чтобы добраться
из точки B в точку A. Мнемоническое правило, помогающее запомнить, в какую сторону будет
указывать вектор: «A минус B смотрит на A».

<img src="/unity_doc/images/ex71.jpeg" alt="1" style={{  height: 'auto' }} />

Двумерное вычитание векторов: A минус B смотрит на A  

Это важно в методе `Update()`, поскольку снаряд необходимо расположить вдоль вектора,
проходящего от launchPos до текущей позиции mousePos3D, который мы назвали
mouseDelta. Однако расстояние, на которое снаряд может переместиться вдоль
mouseDelta, ограничено значением maxMagnitude, которое соответствует радиусу
SphereCollider на Slingshot (в настоящее время в инспекторе компонента Collider оно
установлено на 3 м).  

Если mouseDelta длиннее, чем maxMagnitude, его величина ограничивается значением
maxMagnitude. Это достигается с помощью сначала вызова `mouseDelta.Normalize()`
(который устанавливает длину mouseDelta равной 1, но сохраняет направление), а затем
умножения mouseDelta на maxMagnitude.  

`projectile` перемещается в эту новую позицию, и если вы запустите игру, то увидите, что
снаряд движется вместе с мышью, но ограничен определенным радиусом.  

`Input.GetMouseButtonUp(0)` возвращает true только в первом кадре, в котором была
отпущена левая кнопка мыши (0-якнопка) (см. предупреждение «Не используйте
`GetMouseButtonUp()` в `FixedUpdate()`»). Это означает, что оператор `if` в конце
`Update()` выполняется в кадре, в котором отпускается кнопка мыши. В этом кадре:  

- aimingMode устанавливается в false.
- Rigidbody снаряда не установлен в non-kinematic, что позволяет ему снова реагировать на силу
тяжести.
- projectile присвоена скорость, пропорциональная расстоянию от
launchPos.
- В заключение переменная projectile сбрасывается в нуль. Это не удаляет
созданный экземпляр Projectile; просто поле projectile освобождается, чтобы при
следующем выстреле из рогатки в него мог быть занесен другой экземпляр.  

5. Нажмите «Play» и посмотрите, как работает рогатка. Экземпляр Projectile летит с
хорошей скоростью? Попробуйте настроить параметр velocityMult в инспекторе,
чтобы найти значение, которое вам подходит. Мне показалось, что значение 10 подходит
лучше всего.
6. Сохраните сцену.

### Предупреждение [!toc]
НЕ ИСПОЛЬЗУЙТЕ `GetMouseButtonUp()` В `FixedUpdate()` Об этом я
буду упоминать несколько раз на протяжении книги, так как это проблема, которую я
часто вижу в работах своих студентов.  

Методы Input: `Input.GetMouseButtonUp()`, `Input.GetKeyDown()`,
`Input.GetButtonUp()` и другие подобные методы Input, заканчивающиеся на …Up
или …Down, нельзя надежно использовать внутри `FixedUpdate()`. FixedUpdate
происходит ровно 50 раз в секунду, тогда как Update (или визуальный кадр) может
происходить до 1000 раз в секунду.  

Поэтому между двумя вызовами FixedUpdate обычно происходит несколько вызовов
Update, и если `Input.GetKeyDown()` возвращал true в любом из этих вызовов,
кроме самого последнего, то в рамках FixedUpdate он будет false! Когда это
происходит, создается впечатление, что клавиатура или кнопка мыши неисправны,
поскольку они не работают большую часть времени при нажатии.  

Если вы когда-нибудь создадите игру и вам покажется, что контроллер (клавиатура,
мышь, геймпад и т. д.) работает лишь время от времени, тщательно проверьте, не разместил один из этих методов Input внутри `FixedUpdate()`. Если вам нужно
исправить эту проблему, в листинге кода показан хороший способ сделать это:  

Листинг кода  (Это пример кода, не предназначенный для включения в Mission
Demolition)

```c#
public class MouseButtonUpInFixedUpdate : MonoBehaviour {
    // The 0 in this field name is a zero (not an o)
    private bool button0DownInUpdate = false;
    void Update() {
        // If the player presses the 0th mouse button down this frame
        if ( Input.GetMouseButtonDown( 0 ) ) {
            // …then set buttonDownInUpdate to true
            button0DownInUpdate = true;
            // …it will stay true until FixedUpdate() sets it to false
        }
    }
    
    private void FixedUpdate() {
        // buttonDownInUpdate replaces Input.GetMouseButtonDown( 0 )
        if ( button0DownInUpdate ) { // Input.GetMouseButtonDown( 0 )
            Debug.Log( "Mouse button 0 pressed!" );
            // Don’t forget to reset buttonDownInUpdate back to false
            button0DownInUpdate = false;
        }
    }
}
```
Другие методы Input, такие как `Input.GetAxis()`, `Input.GetKey()` и
`Input.GetButton()`, которые не заканчиваются на …Up() или …Down(), отлично
работают как в `FixedUpdate()`, так и в `Update()`, поскольку они возвращают
текущее состояние оси, клавиши или кнопки, что вполне допустимо проверять в
FixedUpdate.
