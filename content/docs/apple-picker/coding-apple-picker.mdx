На рисунке представлена блок-схема действий AppleTree.

<img src="/unity_doc/images/ex59.jpeg" alt="1" style={{  height: 'auto' }} />

Действия, которые необходимо запрограммировать для AppleTree, следующие:
- Двигаться с определенной скоростью в каждом кадре.
- Изменять направление при приближении к краю игровой области.
- Иногда также менять направление движения в зависимости от случайного выбора.
- Каждую секунду бросать яблоко.  

Вот и все! Приступим к программированию.  

1. Сначала создайте новый скрипт на C# с именем AppleTree и добавьте его к префабу AppleTree.
    - a. Выберите AppleTree на панели Project (не в Hierarchy).
    - b. Нажмите кнопку «Добавить компонент» внизу панели «Инспектор» для AppleTree
(префаб-ассет).
    - c. Введите AppleTree в появившееся поле поиска, а затем нажмите New Script. Вы перейдете
во всплывающее окно New Script, где в качестве имени нового скрипта будет
предварительно указано AppleTree.
    - d. Нажмите «Создать и добавить» внизу всплывающего окна «Новый скрипт». Это выполнит
две вещи:
        - Создается скрипт C# с именем AppleTree.cs в папке Assets панели Project (вы не
увидите «.cs» в Unity, но это расширение файла для C#).
        - И присоединяет этот скрипт AppleTree в качестве компонента префаба AppleTree.
Теперь вы увидите компонент AppleTree (Script) в инспекторе, когда выберете AppleTree на
панели «Проект» или «Иерархия» (изменения префаба на панели «Проект» автоматически
распространяются на экземпляр на панели «Иерархия» )  

>Иногда при использовании этого метода для автоматического добавления скрипта к GameObject новый компонент
AppleTree (Script) не появляется в инспекторе для этого GameObject, пока вы не выберете другой GameObject, а затем
снова не выберете AppleTree.  

Код, который вам предстоит ввести в файл AppleTree на языке C#, приведен в листинге. Первая часть скрипта в основном состоит из конфигурационных переменных, а позже
вы добавите в него дополнительные элементы. В коде вы увидите несколько
комментариев, объясняющих, что делают различные строки (вы можете скопировать их,
но это не обязательно). В конце некоторых строк вы увидите односимвольный
комментарий (например, // a). Это ссылки на комментарии, которые следуют за
листингом кода.  

В листингах кода других глав перед каждой строкой часто указывались номера строк. В
скриптах в этой части книги номера строк отсутствуют, поскольку скрипты достаточно
длинные и, вероятно, возникнут расхождения между вашими номерами строк и моими из-за
различий в переносах строки на протяжении многих строк кода.  

2. Откройте скрипт AppleTree в Visual Studio и введите код:

**Листинг кода AppleTree.cs**  

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class AppleTree : MonoBehaviour {
    [Header("Inscribed")] // a
    // Prefab for instantiating apples
    public GameObject applePrefab;

    // Speed at which the AppleTree moves
    public float speed = 1f;

    // Distance where AppleTree turns around
    public float leftAndRightEdge = 10f;

    // Chance that the AppleTree will change directions
    public float changeDirChance = 0.1f;

    // Seconds between Apples instantiations
    public float appleDropDelay = 1f;

    void Start () {
        // Start dropping apples // b
    }

    void Update () {
        // Basic Movement // b
        // Changing Direction // b
    }
}
```

- a. [Header("Inscribed")] - это атрибут компилятора, который указывает Unity
разместить заголовок «Inscribed» над следующим полем в инспекторе данного
скрипта. Атрибут «Inscribed» обозначает поля этого скрипта, которые не изменяются во
время его выполнения. В приведенных ниже фрагментах кода будет использоваться второй
заголовок «Dynamic» для обозначения полей, значения которых вычисляются во время
работы игры.
- b. В то время как другие комментарии в коде описывали, для чего будут использоваться
поля, расположенные ниже них, эти три строки описывают действия, которые нам еще
предстоит запрограммировать. Когда я впервые пишу скрипт, мне часто бывает полезно
наметить действия, которые я хочу, чтобы код выполнял, с помощью таких комментариев,
прежде чем приступить к написанию кода. Считайте это чем-то вроде наброска
письменной работы.  

3. Сохраните скрипт AppleTree в Visual Studio и вернитесь в Unity.
4. Выберите AppleTree на панели «Иерархия» (не на панели «Проект»).  

Когда AppleTree выбран, при просмотре компонента AppleTree (Script) в Inspector вы увидите все
общедоступные переменные, которые только что ввели. Вы также увидите выделенный
жирным шрифтом заголовок Inscribed из атрибута [Header("Inscribed")] над полями в
Inspector.  

5. Попробуйте переместить AppleTree по сцене, изменяя координаты X и Y в инспекторе
«Трансформация», чтобы найти подходящую высоту (position.y) для AppleTree и подходящие
границы для перемещения влево и вправо. На моем компьютере 11 кажется подходящим
значением для position.y, и, похоже, дерево может перемещаться от -24 до 24 по position.x и
при этом оставаться хорошо видимым в панели «Игра».
    - a. Установите положение AppleTree в P:[ 0, 11, 0 ].
    - b. Установите значение leftAndRightEdge в компоненте AppleTree (Script) Inspector
равным 24. Это переопределит значение по умолчанию 10, которое находится в скрипте.

<Callout>
### Warning [!toc]
Когда вы переопределяете значение поля в инспекторе, значение, заданное в C#-скрипте, игнорируется. Ввод числа 24 в поле `leftAndRightEdge` компонента `AppleTree (Script)` в инспекторе переопределил значение по умолчанию, равное 10. Если бы вы теперь изменили значение `10f`, присвоенное переменной `leftAndRightEdge` в C#-скрипте, значение для данного объекта `AppleTree` на сцене не изменилось бы. Значения, которые вы инициализируете в скрипте, лучше всего рассматривать как значения по умолчанию, которые могут быть переопределены в инспекторе.

</Callout>

### Применение переопределений экземпляра AppleTree к префабу AppleTree [!toc]

Если (как я и предлагал) при внесении этих изменений у вас был выбран экземпляр AppleTree в
иерархии, то теперь вы должны увидеть, что название поля leftAndRightEdge в инспекторе
AppleTree (Script) выделено жирным шрифтом, как и его новое значение - 24. Это связано с тем,
что данное значение теперь отличается от значения, сохраненного в префабе AppleTree (в
котором по-прежнему хранится исходное значение 10). Чтобы применить это изменение обратно
к префабу:
1. В верхней части инспектора вы увидите кнопку всплывающего меню с надписью Overrides.
    - a. Нажмите кнопку Overrides, как показано на рисунке. В появившемся всплывающем
окне отображается все, что будет применено обратно к версии префаба.

<img src="/unity_doc/images/ex60.jpeg" alt="1" style={{  height: 'auto' }} />
Применение всех переопределений экземпляра AppleTree в иерархии
обратно к префабу (я затемнил остальную часть окна инспектора, чтобы улучшить
наглядность)  

    - b. Нажмите «Apply All», чтобы скопировать все настройки AppleTree (Script) в префаб.  

Теперь вы увидите, что leftAndRightEdge больше не выделено жирным шрифтом на этом
экземпляре AppleTree, и если вы выберете префаб AppleTree на панели Project, то увидите, что у
него также значение leftAndRightEdge равно 24.

### Справочник по скриптам движка Unity [!toc]
Прежде чем углубиться в этот проект, крайне важно не забыть заглянуть в Справочник
по скриптам Unity, если у вас возникнут какие-либо вопросы по поводу представленного
здесь кода. Существует три способа открыть Справочник по скриптам:
1. Выберите *Help > Scripting Reference* в панели меню Unity. Это
откроет ваш веб-браузер и загрузит Справочник по скриптам, который сохранен
локально на вашем компьютере, что означает, что он будет работать даже без
подключения к Интернету. Вы можете ввести любое имя функции или класса в поле
поиска вверху, чтобы узнать о нем больше.
Введите MonoBehaviour в поле поиска на веб-странице справочника по скриптам и
нажмите Return. Щелкните по первому результату (просто MonoBehaviour) для
просмотра всех методов, встроенных в каждый скрипт MonoBehaviour (и,
соответственно, в каждый скрипт класса, который вы будете писать и присоединять к
GameObject в Unity).
2. При работе в Visual Studio выберите в коде любой термин, о котором хотите узнать
больше (например, MonoBehaviour), а затем выберите *Help > Unity API Reference* в панели меню Visual Studio. Откроется та же локальная версия справочника по
скриптам, что и в методе 1.
3. Откройте любой современный веб-браузер и введите «Unity Scripting Reference» в
строку поиска. Первым результатом поиска должна быть ссылка на онлайн-версию
справочника по скриптам Unity. Это не сработает без доступа к Интернету, но она содержит точно такую же информацию, как и локальное справочное руководство,
к которому вы можете получить доступ с помощью двух других методов. В то время как
методы 1 и 2 всегда предоставляют вам правильную версию справочника по скриптам
для используемой вами версии Unity (2020.3), в онлайн-документации может
отображаться другая версия. Если вы используете онлайн-документацию, проверьте
номер версии рядом со словом «Version» в левом верхнем углу страницы и убедитесь, что
он установлен на 20.3.
</Callout>
