1. Внесите в метод `Update()` скрипта *AppleTree* изменения. Вы разместите их сразу под комментарием `// Basic Movement` в уже имеющемся коде. Обратите внимание на многоточие (…) чуть выше `void Update()`
в листинге кода. Оно указывает на то, что я пропустил некоторые строки в этом листинге,
чтобы сэкономить место. Пожалуйста, не удаляйте эти строки!

```c#
public class AppleTree : MonoBehaviour {
    … // a
    void Update () {
        // Basic Movement
        Vector3 pos = transform.position; // b
        pos.x += speed * Time.deltaTime; // c
        transform.position = pos; // d

        // Changing Direction
        }
    }
```

- a. На протяжении всех учебных глав я использую многоточия (…) для обозначения
частей кода, которые я пропускаю в приведенных фрагментах. Без них фрагменты кода в
некоторых из последующих глав были бы нелепо длинными. Когда вы увидите такие
многоточия, пожалуйста, ничего не меняйте в коде в тех местах, где они стоят; просто
оставьте его как есть и сосредоточьтесь на новом коде (который выделен жирным шрифтом
для наглядности). В этом листинге кода не требуется вносить изменения в какие-либо
строки кода между объявлением класса `AppleTree` и началом метода `Update()`, поэтому я
использовал многоточия, чтобы пропустить эти неизменённые строки.
- b. Эта строка определяет `Vector3 pos` как положение `AppleTree` в данный момент.
- c. Компонента `x pos` увеличивается на скорость, умноженную на `Time.deltaTime`
(которая является мерой количества секунд, прошедших с момента последнего кадра).
Это делает движение `AppleTree` основанным на времени, что является очень важной
концепцией в программировании игр.
- d. Эта строка присваивает измененное значение `pos` обратно `transform.position` (что
перемещает `AppleTree` в новое положение). Если вы не установите
`transform.position` равным `pos`, `AppleTree` не будет двигаться.

### Создание игр, основанных на времени [!toc]
Практически во всех игровых движках частота кадров значительно колеблется в процессе
игры, поскольку движок стремится отображать новые кадры как можно быстрее, в то
время как ваш компьютер выполняет десятки других задач. Если движение в игре
основано на кадрах, эти колебания частоты кадров повлияют на вашу игру: движение
ускорится, когда частота кадров будет выше, и замедлится, когда она будет ниже. С
другой стороны, когда движение в игре основано на времени, объекты будут двигаться с
постоянной скоростью независимо от частоты кадров, с которой работает игра. Чтобы
этого добиться, мы можем использовать Time.deltaTime - встроенное поле Unity,
которое обновляется в каждом кадре и сообщает нам количество секунд, прошедших с
момента последнего кадра. Time.deltaTime обычно очень мало. Для игры,
работающей со скоростью 25 кадров в секунду (fps), Time.deltaTime равен 0,04f, что
означает, что на отображение каждого кадра уходит 4/100 секунды. Если бы строка кода
// c была запущена при частоте кадров 25 fps, код бы выполнялся следующим образом:

```c#
pos.x += speed * Time.deltaTime;
pos.x += 1.0f * 0.04f;
pos.x += 0.04f;
```

Таким образом, за 1/25 секунды значение `pos.x` увеличится на 0,04 м за каждый кадр.
За полную секунду значение `pos.x` увеличится на 0,04 м за каждый кадр * 25 кадров,
что в сумме даст 1 метр за 1 секунду.  

Если бы игра работала со скоростью 100 кадров в секунду, результат был бы следующим:

```c#
pos.x += speed * Time.deltaTime;
pos.x += 1.0f * 0.01f;
pos.x += 0.01f;
```

Таким образом, за 1/100 секунды `pos.x` увеличится на 0,01 м за каждый кадр. За
полную секунду `pos.x` увеличится на 0,01 м за каждый кадр * 100 кадров, что в сумме
даст 1 метр за 1 секунду.  

Движение на основе времени гарантирует, что независимо от частоты кадров элементы в
вашей игре будут двигаться с постоянной скоростью, а эта стабильность позволяет
создавать игры, которые будут интересны как игрокам, использующим новейшее
оборудование, так и тем, кто использует более старые устройства. Программирование на
основе времени также очень важно учитывать при разработке игр для мобильных
устройств, поскольку скорость и мощность мобильных устройств сильно различаются.
</Callout>

Возможно, вы задаетесь вопросом, почему строки от `// b` до `// d`, которые вы добавили в
метод `AppleTree.Update()`, занимают три строки, а не одну. Почему код не мог выглядеть
просто так?

```c#
transform.position.x += speed * Time.deltaTime;
```

Ответ заключается в том, что `transform.position` - это свойство, метод, маскирующийся
под поле (т. е. функция, маскирующаяся под переменную) с помощью аксессоров `get{}` и
`set{}` (см. Глава «Классы»). Хотя получение (т. е. чтение) значения подкомпонента
свойства возможно, установка значения подкомпонента свойства невозможна.  

Другими словами, `transform.position.x` можно прочитать, но нельзя установить напрямую.
Это требует создания временного `Vector3 pos`, который можно изменить, а затем присвоить
обратно `transform.position`.  

2. Сохраните скрипт, вернитесь в Unity и нажмите «Play».  

Когда вы нажмете кнопку Play, вы заметите, что AppleTree движется очень медленно.
Попробуйте несколько разных значений скорости в инспекторе AppleTree и посмотрите, что
вам больше нравится. Я установил скорость равной 10, что заставляет его двигаться со
скоростью 10 м/с (10 метров в секунду или 10 единиц Unity в секунду).

### Предупреждение [!toc]
ЗНАЧЕНИЯ ИНСПЕКТОРА, УСТАНОВЛЕННЫЕ В РЕЖИМЕ ВОСПРОИЗВЕДЕНИЯ,
СБРОСЯТСЯ ПРИ ЗАВЕРШЕНИИ ВОСПРОИЗВЕДЕНИЯ  

Я уже упоминал об этом несколько раз в книге, но стоит повторить. Если вы измените
значение скорости AppleTree в инспекторе во время работы Unity, скорость
вернется к прежнему значению при остановке воспроизведения. Unity делает это
специально, чтобы значения могли изменяться во время воспроизведения, не влияя на
сохраненную сцену; но в данном случае вы должны убедиться, что скорость
AppleTree установлена на нужное вам значение (например, 10), когда Unity не
находится в режиме воспроизведения.
</Callout>

### Изменение направления

Теперь, когда AppleTree движется с приличной скоростью, оно довольно быстро выбежит за
пределы экрана. Давайте заставим его менять направление, когда оно достигнет значения
`leftAndRightEdge`.

1. Измените скрипт AppleTree

```c#
public class AppleTree : MonoBehaviour {
    …
    void Update () {
        // Basic Movement
        …

        // Changing Direction
        if ( pos.x < -leftAndRightEdge ) { // a
            speed = Mathf.Abs( speed ); // Move right // b
        } else if ( pos.x > leftAndRightEdge ) { // c
            speed = -Mathf.Abs( speed ); // Move left // c
        }
    }
}
```

    - a. Эта строка проверяет, меньше ли новое значение `pos.x`, только что установленное в
предыдущих строках, отрицательного предела по горизонтали, заданного `leftAndRightEdge`.
    - b. Если `pos.x` слишком мало, `speed` устанавливается равным `Mathf.Abs(speed)`,
что берет абсолютное значение `speed`, гарантируя, что результирующее значение
будет положительным. Положительное значение скорости приводит к движению
вправо.
    - c. Если `pos.x` больше `leftAndRightEdge`, то `speed` устанавливается равным
отрицательному значению `Mathf.Abs(speed)`, что гарантирует, что `AppleTree` будет двигаться влево.
2. Сохраните скрипт, вернитесь в Unity и нажмите «Play», чтобы посмотреть, что произойдет.
Теперь `AppleTree` должно двигаться влево и вправо, меняя направление каждый раз, когда
значение `position.x` достигает `-24` или `24`.

### Случайная смена направления

Вместо того чтобы просто предсказуемо отскакивать туда-сюда, мы хотим, чтобы AppleTree
иногда меняло направление движения случайным образом. Чтобы внести случайные изменения
направления, выполните следующие шаги:

1. Добавьте код в AppleTree.cs

```c#
public class AppleTree : MonoBehaviour {
    …
    void Update () {
        // Basic Movement
        …
        // Changing Direction
        if ( pos.x < -leftAndRightEdge ) {
            speed = Mathf.Abs(speed); // Move right
        } else if ( pos.x > leftAndRightEdge ) {
            speed = -Mathf.Abs(speed); // Move left
        } else if ( Random.value < changeDirChance ) { // a
            speed *= -1; // Change direction // b
        }
    }
}
```

- a. `Random.value` - это свойство, которое возвращает случайное значение типа `float`
в диапазоне от 0 до 1 (включая 0 и 1). Если это случайное число меньше, чем `changeDirChance`, …
- b. …AppleTree изменит направление движения, установив скорость, равную
отрицательному значению самой скорости.  

2. Сохраните скрипт, вернитесь в Unity и нажмите «Play». Вы увидите, что значение
значение changeDirChance по умолчанию, равное 0,1, меняет направление движения
слишком часто.
3. Остановите воспроизведение.
4. В инспекторе для AppleTree измените значение changeDirChance на 0,02, и все
должно работать гораздо лучше.  

Чтобы продолжить обсуждение игр, основанных на времени, из боковой панели «Создание игр,
основанных на времени», стоит отметить, что эта вероятность изменения направления на самом
деле не зависит от времени. В каждом кадре существует 2% вероятности того, что AppleTree
изменит направление. На очень быстром компьютере это вероятность может реализоваться 400 раз в секунду (что дает в среднем восемь смен направления
в секунду), тогда как на медленном компьютере - всего 30 раз в секунду (в среднем 0,6 смены
направления в секунду).  

Чтобы исправить это, нам нужно перенести код изменения направления из Update(), который
вызывается так быстро, как компьютер может прорисовывать кадры, в FixedUpdate(),
который вызывается ровно 50 раз в секунду, независимо от того, на каком компьютере он
работает

5. Внесите изменения в код AppleTree.cs

```c#
public class AppleTree : MonoBehaviour {
    …
    void Update() {
        // Basic Movement
        …
        // Changing Direction
        if ( pos.x < -leftAndRightEdge ) {
            speed = Mathf.Abs( speed ); // Move right
        } else if ( pos.x > leftAndRightEdge ) {
            speed = -Mathf.Abs( speed ); // Move left
        // } else if ( Random.value < changeDirChance ) { // a
        // speed *= -1; // Change direction // a
        }
    }

    void FixedUpdate() { // b 
        // Random direction changes are now time-based due to FixedUpdate()
        if ( Random.value < changeDirChance ) { // b
            speed *= -1; // Change direction
        }
    }
}
```

- a. Закомментируйте две строки, отмеченные здесь символами `// a`, чтобы компьютер их
игнорировал. После этого код метода `Update()` вернется к тому виду, который был до
добавления этих строк в листинге.
- b. Создайте метод `FixedUpdate()`, как показано здесь, и поместите в него строки с
изменением направления случайным образом.  

Это приводит к тому, что AppleTree случайным образом меняет направление в среднем 1 раз в
секунду (50 FixedUpdate в секунду * вероятность 0,02 = в среднем 1 раз в секунду).
6. Обязательно сохраните сцену, прежде чем продолжить.
