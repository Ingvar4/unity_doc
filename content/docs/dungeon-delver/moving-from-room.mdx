description: Теперь, когда Dray может хорошо выравниваться по отношению к дверям, пришло время для него отправиться в остальную часть подземелья.
---

Поскольку Dray — единственный, кто будет
перемещаться из комнаты в комнату, мы можем прикрепить большую часть этого кода к классу
Dray; однако глобальная информация о комнатах, такая как расположение дверей и общий размер
карты, по-прежнему должна управляться InRoom.  

1. Откройте скрипт InRoom в Visual Studio и введите код.  
        Листинг кода InRoom.cs
```c#
public class InRoom : MonoBehaviour {
    static public float ROOM_W = 16;
    static public float ROOM_H = 11;
    static public float WALL = 2;
    static Vector2 GRID_OFFSET = new Vector2( 0.5f, 0.5f );
    static public int MAX_RM_X = 9; // a
    static public int MAX_RM_Y = 9;

    static public Vector2[] DOORS = new Vector2[] { // b
        new Vector2(14.5f, 5.5f ), // Right Door
        new Vector2( 8.0f, 9.5f ), // Up Door
        new Vector2( 1.5f, 5.5f ), // Left Door
        new Vector2( 8.0f, 1.5f ) // Down Door
    };

    [Header("Inscribed")]
    …
}
```

- a. Статические целые числа MAX_RM_X и MAX_RM_Y обозначают максимальные границы
карты. Значение 9 будет работать с текущим максимальным размером уровня Delver
, упомянутого в конце этой главы. Если вы хотите создать карту большего размера, вам нужно
будет изменить эти значения.
- b. Статический массив Vector2[] DOORS хранит координаты posInRoom каждой
возможной двери. Обычно я не сторонник жесткого кодирования таких чисел (то есть ввода их в
код вместо настройки в Инспекторе), но в этой игре расположение дверей не изменится.  

2. Сохраните скрипт InRoom.
3. Откройте класс Dray в Visual Studio и введите код из листинга.  
      Листинг Dray.cs
```c#
public class Dray : MonoBehaviour, IFacingMover {
    public enum eMode { idle, move, attack, roomTrans } // a

    [Header("Inscribed")]
    public float speed = 5;
    public float attackDuration = 0.25f;// Number of seconds to attack
    public float attackDelay = 0.5f; // Delay between attacks
    public float roomTransDelay = 0.5f; // Room transition delay // b
    …

    private float timeAtkDone = 0;
    private float timeAtkNext = 0;
    private float roomTransDone = 0; // b
    private Vector2 roomTransPos; // b

    private Rigidbody2D rigid;
    …

    void Update () {
        if ( mode == eMode.roomTrans ) { // c
            rigid.velocity = Vector3.zero;
            anim.speed = 0;
            posInRoom = roomTransPos; // Keeps Dray in place
            if (Time.time < roomTransDone) return;
            // The following line is only reached if Time.time >= transitionDone
            mode = eMode.idle;
        }

        // Finishing the attack when it’s over
            if (mode == eMode.attack && Time.time >= timeAtkDone) {
            mode = eMode.idle;
        }
    …
    }

    void LateUpdate() {
        // Get the nearest quarter-grid position to Dray
        Vector2 gridPosIR = GetGridPosInRoom( 0.25f ); // d

        // Check to see whether we’re in a Door tile
        int doorNum;
        for (doorNum=0; doorNum <4; doorNum++) { // e
            if (gridPosIR == InRoom.DOORS[doorNum]) {
                break;
            }
        }

        if (doorNum > 3 || doorNum != facing) return; // f

        // Move to the next room
        Vector2 rm = roomNum;
        switch (doorNum) { // g
        case 0:
            rm.x += 1;
            break;
        case 1:
            rm.y += 1;
            break;
        case 2:
            rm.x -= 1;
            break;
        case 3:
            rm.y -= 1;
            break;
        }

        // Make sure that the rm we want to jump to is valid
        if (0 <= rm.x && rm.x <= InRoom.MAX_RM_X) { // h
        if (0 <= rm.y && rm.y <= InRoom.MAX_RM_Y) {
        roomNum = rm;
        roomTransPos = InRoom.DOORS[ (doorNum+2) % 4 ]; // i
        posInRoom = roomTransPos;
        mode = eMode.roomTrans; // j
        roomTransDone = Time.time + roomTransDelay;
        }
        }
    }

    //———————————————————— Implementation of IFacingMover ————————————————————
    public int GetFacing() { return facing; }
    …
}
```

- a. Вам необходимо добавить состояние roomTrans в перечисление eMode.
- b. Убедитесь, что вы не пропустили эти три строки.
- c. Эти строки заставляют Дрея на короткое время замирать в дверном проеме новой комнаты при
каждом переходе из одной комнаты в другую. Это не дает игроку войти в опасную комнату,
пока камера не успеет перейти в новую комнату.
- d. Значению gridPosIR присваивается ближайшая к Дрею точка четверти сетки. Здесь
используется значение параметра mult
0,25 используется здесь по двум причинам:
    - InRoom.DOORS находятся на координатах половины сетки (некоторые из них заканчиваются
на 0,5).
    - Запрос положения в четверти сетки означает, что Дрей должен будет пройти дальше вглубь
комнаты, чтобы инициировать переход в другую комнату. Если бы значение mult было
0,5, переход в другую комнату произошел бы слишком быстро.  
- e. Этот цикл проходит по каждому из местоположений дверей InRoom.DOORS и прерывается,
если находит одно в gridPosIR Дрея (т. е. в сетке, где стоит игрок). Если игрок не стоит у
какого-либо местоположения двери, doorNum завершает цикл for со значением 4.
- f. Если Дрей не стоит в дверном проеме (т. е. doorNum > 3) или Дрей не смотрит в сторону
дверного проема (т. е. doorNum != facing), то метод завершается здесь (с помощью
return).
- g. Выполнение достигнет этой точки только в том случае, если Дрей должен пройти через дверь.
Это оператор switch изменяет Vector2 roomNum в зависимости от того, через какую
дверь проходит Дрей.
- h. Здесь мы убеждаемся, что Дрей не выходит за пределы допустимой карты. Например, это не
дает Дрею выйти из входа в подземелье (что установило бы его roomNum.y равным -1,
поскольку roomNum.y стартовой комнаты равен 0).
- i. Код (doorNum+2) % 4 выбирает противоположную дверь в комнате (например, если Дрей
выходит из
DOORS[3], он войдет в DOORS[1]). Затем roomTransPos устанавливается в это значение, и в следующей строке posInRoom Дрея также устанавливается в то же место, помещая его в
дверной проем следующей комнаты.
- j. Дрей переводится в режим roomTrans, который на мгновение останавливает его, давая
игроку время осмотреть новую комнату перед входом в нее. Поскольку для Скелетоса
установлен флаг InRoom.keepInRoom, он не может дотянуться до Дрея, когда тот находится
в дверном проеме (что было верно и для врагов в The Legend of Zelda).  

4. Сохраните все скрипты в Visual Studio, вернитесь в Unity и нажмите «Play».  

Теперь вы можете перемещать Дрея из комнаты в комнату. Однако камера пока не будет следовать за
Дреем в новую комнату, поэтому вам нужно наблюдать за его движением в панели «Сцена».
