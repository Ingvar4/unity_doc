Начнем с создания для Дрея нечто вроде синглатона, но вместо синглатона,
который позволил бы прямой публичный доступ к классу Dray, мы создадим статический
публичный интерфейс IFacingMover (IFM), который позволит любому другому классу
обращаться только к публичным аспектам Dray, связанным с IFacingMover, что нам понадобится для
скрипта CamFollowDray, который мы напишем далее.  

1. Откройте скрипт Dray в Visual Studio и добавьте две строки.  
        Листинг кода Dray.cs
```c#
public class Dray : MonoBehaviour, IFacingMover {
    static public IFacingMover IFM;
    public enum eMode { idle, move, attack, roomTrans }
    …

    void Awake () {
        IFM = this;
        rigid = GetComponent<Rigidbody2D>();
        …
    }
    …
}
```

Здесь видно, что реализация IFM очень похожа на то, как мы раньше реализовывали синглатоны,
но здесь - благодаря интерфейсу IFacingMover - мы разрешаем доступ только к нескольким
общедоступным методам и свойствам Dray, а не открываем все общедоступные поля Dray для
других классов.  

2. Создайте новый скрипт C# с именем CamFollowDray в папке « » в папке «Scripts».
3. Прикрепите CamFollowDray к Main Camera в иерархии.
4. Откройте CamFollowDray в Visual Studio и введите код.  
        Листинг кода CamFollowDray.cs
```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

[RequireComponent( typeof(InRoom) )] // a
public class CamFollowDray : MonoBehaviour {
    static public bool TRANSITIONING { get; private set; } // b

    [Header("Inscribed")]
    public float transTime = 0.5f;

    private InRoom inRm;
    private Vector3 p0, p1;
    private float transStart;

    void Awake() {
        inRm = GetComponent<InRoom>();
        TRANSITIONING = false;
    }

    void Update () {
        if (TRANSITIONING) { // c
            float u = (Time.time - transStart) / transTime;
            if (u >= 1) {
                u = 1;
                TRANSITIONING = false;
            }
                transform.position = (1 -u) *p0 + u *p1;
            } else { // d
                if (Dray.IFM.roomNum != inRm.roomNum) {
                TransitionTo( Dray.IFM.roomNum );
            }
        }
    }

    void TransitionTo( Vector2 rm ) { // e
        p0 = transform.position;
        inRm.roomNum = rm;
        p1 = transform.position + (Vector3.back * 10);
        transform.position = p0; // f

        transStart = Time.time;
        TRANSITIONING = true;
    }

    // void Start() {…} // Please delete the unused Start() method
}
```

- a. Для этого класса требуется, чтобы к главной камере был прикреплен компонент InRoom (Script).
- b. Это еще один случай, когда статическое автоматическое свойство с частным условием set
позволяет любому классу видеть поле, но устанавливать его может только один класс.
- c. Если CamFollowDray находится в переходе, переместите камеру из старой комнаты (p0) в
новую (p1) в течение transTime секунд (по умолчанию 0,5).
- d. Если CamFollowDray не находится в процессе перехода, он следит за тем, чтобы Dray.IFM
находился в комнате, отличной от комнаты этого GameObject (Main Camera).
- e. При вызове TransitionTo() CamFollowDray сохраняет своё текущее положение в p0,
затем временно перемещается в новую комнату и сохраняет это положение в p1. Код «+
(Vector3.back * 10)²» необходим, поскольку установка roomNum на объекте InRoom
приводит к тому, что Z-координата GameObject становится равной 0 (нулю).
- f. Затем CamFollowDray возвращается в исходное положение, инициализирует
линейную интерполяцию от p0 до p1 и устанавливает для параметра
TRANSITIONING значение true.  

5. Сохраните все скрипты в Visual Studio и вернитесь в Unity.
6. Сохраните сцену и нажмите «Play».  

Первое, что произойдет при нажатии Play, - это появление предупреждающего (желтого)
сообщения в консоли: «Creating missing InRoom component for CamFollowDray in Main Camera».
Благодаря атрибуту [RequireComponent( typeof(InRoom) )] Unity автоматически
добавила компонент InRoom (Script) к Main Camera, что хорошо. Плохо то, что теперь у нас есть
странная ошибка, из-за которой камера мигает черным, когда Дрей перемещается из комнаты в
комнату.  

Мне, собственно, потребовалось некоторое время, чтобы понять, что здесь происходит, поэтому я
хотел бы провести вас через этот процесс. Мое первоначальное предположение заключалось в том,
что каким-то образом Main Camera оказалась слишком близко к игровым элементам, чтобы их можно
было увидеть (ближняя плоскость отсечения на Main Camera по умолчанию равна 0,3, что означает:
если что-либо находится ближе, чем на 0,3 единицы от Main Camera, оно не будет
визуализироваться). Это оказалось верным. Каждый раз, когда главная камера перемещалась в
другую комнату, у нее по оси Z было значение 0 (ноль) вместо -10, как должно было быть. Я
заглянул в скрипт CamFollowDray, чтобы понять, где произошла ошибка, но проблема была не
там. Проблема заключалась в том, что поле keepInRoom в InRoom по умолчанию имеет
значение true, поэтому, когда скрипт InRoom был автоматически добавлен к Main Camera,
keepInRoom был отмечен. Из-за этого всякий раз, когда Main Camera перемещалась, она
ограничивалась InRoom в пределах комнаты, что устанавливало ее положение по оси Z равным 0. Я
рассказал вам об этом, чтобы напомнить: всегда проверяйте значения в любом компоненте скрипта,
который автоматически прикрепляется к GameObject.  

7. Выберите Main Camera в иерархии.
8. В скрипте InRoom компонента Main Camera установите для keepInRoom значение false (не
отмечено).
9. Сохраните сцену и нажмите «Play».  

Теперь вы должны иметь возможность перемещаться в любом месте в трех нижних комнатах
подземелья. Вы намеренно не можете пройти через нижнюю дверь в средней комнате, потому что это
(или в конечном итоге будет) вход в подземелье. Однако запертая верхняя дверь в средней комнате
представляет собой проблему, и решение этой проблемы в данном издании книги сильно отличается
от предыдущего. В следующей главе вы узнаете, как мы реализуем работу запертых дверей и многих
других элементов.

Теперь вы выполнили большую часть настроек, связанных с Tilemap уровня, и у вас есть персонаж,
который может ходить и атаковать во всех четырех направлениях, а также перемещаться из комнаты в
комнату. В следующей главе вы добавите несколько важных аспектов, таких как нанесение урона

использовать для создания головоломок для игрока.
