На своих занятиях я обнаружил, что воссоздание старых игр действительно помогает
дизайнерам их изучить, и The Legend of Zelda всегда была одной из лучших игр
для такого клонирования.  

Это последний прототип в книге и, следовательно, самый сложный.
Однако в этом прототипе также используется более сильный компонентный подход
к проектированию, чем во многих других, поэтому отдельные скрипты будут
короче. Когда вы закончите эту главу, у вас будет хороший каркас для
приключенческой игры, который вы сможете расширять самостоятельно.

### Чему вы научитесь [!toc]
В этой главе рассматриваются несколько новых концепций и повторяются многие другие. К ним
относятся:  

- Импорт и использование графических ресурсов, созданных для этой игры
- Работа с движком Unity Tilemap для создания 2D-игр
- Учет компонентного подхода при создании объектно-ориентированного кода
- Разбор шестнадцатеричных чисел в плитки карты подземелья
- Анимация 2D-персонажей и управление анимацией с помощью кода
- Разделение листов спрайтов как на плитки Tilemap, так и на кадры анимации
- Создание динамического 2D-столкновения для карты подземелий с помощью кода
- Удержание врагов в их комнатах при одновременном перемещении игрока и камеры в другие
комнаты

### The Dungeon Delver Game [!toc]
В этом проекте вы создадите приключенческую игру, в значительной степени основанную на The
Legend of Zelda для Nintendo Entertainment System. В игре вы будете следить за приключениями героя
по имени Дрей, который исследует подземелье, сражается со скелетами и ищет грапплер (grappling hook).

### Component-Based Design [!toc]

Для этого прототипа мы постараемся как можно больше использовать компонентный подход (см.
главу «Объектно-ориентированное мышление»). Чтобы сделать это правильно, вам нужно
заранее немного подумать о том, как вы хотите, чтобы работала игра. «Легенда о Зельде» и
большинство других игр того времени были построены на основе тайлов, то есть их карты состояли
из ограниченного числа тайлов, которые повторялись несколько раз на протяжении уровня. На
рисунке вы можете увидеть набор тайлов, которые вы будете использовать в игре и
часть карты, составленной из этих тайлов.

<img src="/unity_doc/images/ex129.jpeg" alt="1" style={{  height: 'auto' }} />
Атлас плиток слева и комната, построенная из них, справа. На левое изображение
нанесена сетка, чтобы вам было легче разглядеть края плиток.  

Несколько лет назад Unity представила свой собственный движок Tilemap, который теперь входит в
набор пакетов, автоматически включаемых в стандартный 2D-проект Unity. Как и многие новые аспекты Unity, первоначальная настройка Tilemap может занять некоторое время, но когда он
заработает, он сэкономит вам и время, и ресурсы (он гораздо эффективнее движка «UniTile»,
который я создал для второго издания этой книги). Движок Unity Tilemap обычно не извлекает
данные из текстовых файлов - как я делаю в этой главе - поэтому я использую его немного иначе,
чем предполагалось в Unity, но это хороший пример того, как можно модифицировать технологии
Unity под свои нужды.  

Использование Unity Tilemaps в этом издании книги потребовало некоторых изменений по
сравнению с версией во втором издании, но мы по-прежнему будем сосредоточены на максимальной
изоляции кодовых задач. Вот запланированное распределение задач:

1. MapInfo.cs: определяет уровень и информацию о фрагментах
    - Чтение данных карты: MapInfo считывает файл карты DelverLevel_Eagle.txt, чтобы
определить, какая плитка расположена в каждой точке на карте.
    - Чтение данных о столкновениях: MapInfo также считывает файлы DelverCollisions.txt (и
DelverGrapTiles.txt), чтобы сопоставить столкновения с визуальными элементами плиток на
карте.
2. TilemapManager.cs: использует информацию из MapInfo для заполнения тайл-карт Unity
    - Управление визуальной картой тайлов: извлекает визуальную информацию из MapInfo и
назначает тайлы на визуальной карте тайлов.
    - Управление картой коллизий: извлекает информацию о коллизиях из MapInfo и назначает
плитки, подверженные столкновениям, невидимой карте коллизий.
    - Управление картой тайлов для захвата: в следующей главе вы реализуете Grappler, который
может проходить через плитки с лавой, по которым игрок обычно не может ходить, поэтому
TilemapManager также поддерживает вторую карту тайлов «GrapTiles», подверженных
столкновениям.

### Панель «Игра» [!toc]

Перед настройкой камер необходимо подготовить панель «Игра».  

1. Откройте сцену *__Scene_Dungeon*, дважды щелкнув по ней в панели «Hierarchy».
2. В раскрывающемся меню «Соотношение сторон» панели «Игра» выберите «Full HD (1920 x 1080)»,
которое должно быть опцией по умолчанию (поэтому вам не нужно его добавлять). Однако,
если у вас нет этой опции в соотношениях сторон панели «Игра», сделайте следующее:
        - a. Щелкните всплывающее меню «Соотношение сторон» в верхней части панели «Игра»
(второе всплывающее меню слева) и нажмите на значок «+» в нижней части этого меню.
        - b. В появившемся диалоговом окне установите:
                - Label to Full HD
                - Type to Fixed Resolution
                - W to 1920
                - H to 1080
        - c. Нажмите «ОК», чтобы сохранить эти настройки в качестве пресета.
        - d. Выберите «Full HD (1920 x 1080)» во всплывающем меню «Соотношение сторон».

### Основная камера [!toc]
Выберите «Основная камера» в иерархии. В инспекторе установите следующие настройки:  

1. Transform - P:[ 24, 5.5, -10 ] R:[ 0, 0, 0 ] S:[ 1, 1, 1 ]
2. Camera
        - a. Clear Flags: Solid Color
        - b. Background: Установите очень темно-серый цвет ( RGBA:[ 15, 15, 15, 0 ] ) Значение альфа для цвета фона камеры игнорируется, поэтому мы оставим его равным 0.
        - c. Projection: Orthographic
        - d. Size: 5.5
        - e. Viewport Rect: X:0, Y:0, W:0.8, H:1

### Камера GUI [!toc]
Выполните следующие шаги, чтобы создать камеру с именем GUI Camera.  

1. Создайте новую камеру, выбрав *GameObject > Camera*.
2. Переименуйте камеру в «GUI Camera».
3. Выберите «GUI Camera» в иерархии и установите в инспекторе следующие настройки:
        - a. Tag: Untagged - это гарантирует, что Camera.main по-прежнему будет ссылаться на Main
Camera.
        - b. Transform - P:[ -100, 0, -10 ] R:[ 0, 0, 0 ] S:[ 1, 1, 1 ]
        - c. Camera
                - Clear Flags: Solid Color
                - Background: Пока установите средне-серый цвет (RGBA:[ 128, 128, 128, 0 ])
                - Projection: Orthographic
                - Size: 5.5
                - Viewport Rect: X:0.8, Y:0, W:0.2, H:1
        - d. Audio Listener - в сцене может быть только один Audio Listener, и для этой сцены им является
Main Camera, поэтому вам нужно удалить Audio Listener из GUI Camera.
                - Нажмите на три вертикальные точки (⋮) справа от компонента Audio Listener и выберите в
раскрывающемся меню пункт «Удалить компонент». 

Это разделит панель «Игра» на два меньших окна просмотра. Главная камера займет большую часть
экрана, а камера GUI - правые 20%.
