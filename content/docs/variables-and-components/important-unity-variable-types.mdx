---

Все эти типы переменных на самом деле
являются классами и следуют соглашению об именовании Unity, согласно
которому все типы классов начинаются с заглавной буквы. Для каждого из
типов переменных Unity вы увидите информацию о том, как создать новый
экземпляр этого класса (см. боковую панель «Экземпляры классов и
статические функции» далее), за которой следует список важных
переменных и функций для данного типа данных. Для большинства
классов Unity, перечисленных в этом разделе, переменные и функции
разделены на две группы:

- **Переменные и функции экземпляра**: эти переменные и функции
напрямую связаны с одним экземпляром типа переменной. Если вы
посмотрите на приведенную ниже информацию о *Vector3*, то увидите,
что `x`, `y`, `z` и `magnitude` — все это переменные экземпляра *Vector3*,
и доступ к каждой из них осуществляется с помощью имени
конкретной переменной Vector3, точки, а затем имени переменной
экземпляра (например, `position.x`). Каждый экземпляр Vector3
может иметь разные значения для этих переменных. Аналогично,
функция `Normalize()` действует на отдельный экземпляр Vector3 и
устанавливает величину (**magnitude**) этого экземпляра равной 1.
- **Статические переменные и функции класса**: Статические
переменные привязаны ко всему классу, а не к отдельному экземпляру.
Они часто используются для хранения информации, одинаковой для
всех экземпляров класса (например, `Color.red` — это статическая
переменная, определяющая красный цвет для всего класса Color; в
результате red имеет одинаковое значение и значение во всех экземплярах Color) или для воздействия на несколько
экземпляров класса, не затрагивая ни один из них (например,
`Vector3.Cross( v3a, v3b )` используется для вычисления
векторного произведения двух Vector3 и возвращает это значение в виде
нового Vector3, не изменяя ни `v3a`, ни `v3b`).

Для получения дополнительной информации о любом из этих типов переменных Unity
ознакомьтесь с документацией Unity.

### Экземпляры классов и статические функции [!toc]
Так же, как и префабы, которые вы видели в статье «Hello World:
ваша первая программа», классы также могут иметь экземпляры.
Экземпляр любого класса (также известный как член класса) — это
объект данных, тип которого определяется классом.  

Например, можно определить класс `Human`, и каждый из ваших
знакомых будет экземпляром этого класса. Для всех экземпляров
класса «Человек» определены несколько функций (например, `Eat()`,
`Sleep()`, `Breathe()`).  

Так же, как вы отличаетесь от всех других людей вокруг вас,
каждый экземпляр класса `Human` отличается от других
экземпляров. Даже если два экземпляра имеют абсолютно
одинаковые значения, они хранятся в разных местах в памяти
компьютера и рассматриваются как два отдельных объекта.
(Продолжая аналогию с людьми, можно представить их как
однояйцевых близнецов.) Равенство экземпляров классов
проверяется по ссылке, а не по значению. Это означает, что если вы
сравниваете два экземпляра класса, чтобы проверить, одинаковы ли
они, то сравнивается их местоположение в памяти, а не их
значения (так же, как у двух однояйцевых близнецов разные имена,
т. е. ссылки).  

Конечно, можно ссылаться на один и тот же экземпляр класса с
помощью более чем одной переменной. Так же, как человека,
которого я могу называть «сыном», мои родители будут называть
«внуком», экземпляр класса может быть присвоен любому
количеству переменных, но при этом оставаться одним и тем же
объектом данных, как показано в следующем коде:

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

// Defining the class Human
[System.Serializable] // Allows this class to be seen in the Inspector
public class Human {
    public string name;
    public Human partner;
}

public class Family : MonoBehaviour {
    // Declaration of public variables
    public Human husband;
    public Human wife;

    void Start() {
    // Initial state
    husband = new Human();
    husband.name = "Jeremy Gibson";

    wife = new Human();
    wife.name = "Melanie Schuessler";

    // My wife and I get married
    husband.partner = wife;
    wife.partner = husband;

    // We change our names
    husband.name = "Jeremy Gibson Bond";
    wife.name = "Melanie Schuessler Bond";

    // Because wife.partner refers to the same instance as
    // husband, the name of wife.partner has also
    changed
    print( wife.partner.name );
    // prints "Jeremy Gibson Bond"
    }
}
```

Также можно создавать статические функции в классе `Human`,
которые могут действовать на один или несколько экземпляров
класса. Следующая статическая функция `Marry()` позволяет
установить двух людей в качестве партнеров друг для друга с
помощью одной функции, как показано в следующем коде.

```c#
// } // Comment out the closing brace on line 37.
    static public void Marry( Human h0, Human h1 ) {
        h0.partner = h1;
        h1.partner = h0;
    }
}
```

Благодаря этой функции строки 25 и 26 из исходного листинга кода
теперь можно заменить одной строкой `Family.Marry(wife, husband );` . Поскольку перед методом `Marry()` стоит ключевое слово `static`, его можно использовать практически в
любом месте кода.  

>Функция и метод имеют одинаковое базовое значение. Единственное различие заключается в
том, что «функция» — это термин для обозначения автономной функции, тогда как «метод»
относится к функции, являющейся частью класса, так как метод `Marry()` является частью
класса `Family`.
