В 2018 году Unity начало включать в
состав Unity фантастический пакет TextMeshPro. TextMeshPro рендерит
текст быстрее, с более высоким качеством и с большим количеством опций,
чем традиционные текстовые поля в Unity, поэтому мы будем использовать
его для этой игры.

1. В панели меню Unity выберите *Game Object > UI > Text - TextMeshPro*. При первом выполнении этой операции в проекте
откроется окно TMP Importer.
2. В окне TMP Importer нажмите кнопку Import TMP Essentials.
TextMeshPro состоит из нескольких различных скриптов на C# и
файлов шрифтов, и эта операция установит самые важные из них.
3. После их установки в окне TMP Importer появится возможность «Import
TMP Examples & Extras». Не нажимайте эту кнопку сейчас (хотя
можете сделать это позже в другом проекте, чтобы увидеть, на что
способен TextMeshPro).
4. Вместо этого просто закройте окно TMP Importer.  

В результате в иерархии появилось несколько GameObjects:  

- Canvas: в системе uGUI (графический интерфейс пользователя
Unity) Canvas является родительским трансформом всех
GameObjects GUI, включая текстовое поле, которое вы только что
создали.
- Text (TMP): это GameObject TextMeshPro, который вы только что
создали.
- EventSystem: этот GameObject управляет взаимодействиями и
событиями, связанными с GUI-объектами на Canvas. Не удаляйте его!  

5. В иерархии дважды щелкните Canvas, чтобы уменьшить масштаб окна
Scene, чтобы увидеть весь Canvas. В Unity 3D 1 единица равна 1 метру,
но в Unity UI 1 единица равна 1 пикселю на экране, поэтому Canvas
выглядит огромным по сравнению со всем остальным, что мы делали в
этом проекте. Когда вы закончите с элементами UI Canvas, вы можете
дважды щелкнуть по MainCamera или ProspectorBackground, чтобы
вернуть вид сцены к масштабу игры Prospector.
6. Выберите Tex t (TMP) в иерархии (если вы его не видите, он находится в
подчинении у Canvas) и измените его имя на FloatingScore.
7. Измените настройки FloatingScore, чтобы они соответствовали тем,
что выделены на рисунке. На этом рисунке все многочисленные
настройки, которые вам нужно изменить, выделены белым
прямоугольником (всё остальное затенено).

Обратите внимание, что изменения, которые вы вносите в SDF-материал
LiberationSans, являются глобальными и затрагивают все экземпляры
TextMeshPro, использующие этот же шрифтовой материал. Для Prospector
это подходит, но если в какой-то момент вам понадобятся разные
настройки для разных экземпляров TextMeshPro с одним и тем же
шрифтом, вы можете использовать значок с двумя ползунками (между
значком справки и тремя точками в правом верхнем углу раздела
материалов в инспекторе), чтобы создать несколько пресетов материала.  

>Для получения дополнительной информации см. https://docs.unity3d.com/2020.3/Documentation/Manual/Presets.html  

Пока не делайте FloatingScore префабом. Сначала будет немного проще
работать с ним как с обычным GameObject.

### Настройка панели Game и CanvasScaler [!toc]

CanvasScaler - это один из компонентов, по умолчанию прикрепленных ко
всем новым Canvases. Задача CanvasScaler - обеспечить правильное
отображение элементов uGUI при показе на экранах с разрешением,
отличным от того, на котором вы создавали GUI. Однако для того, чтобы
GUI правильно отображалось на экранах с различными разрешениями, нам
сначала нужно настроить CanvasScaler, чтобы он знал, для экрана какого
размера мы разработали игру и как обрабатывать другие разрешения.  

1. Убедитесь, что на панели «Игра» установлено соотношение сторон
«WebGL x 2» (2048 x 1536), которое вы настроили в предыдущей главе. Если
соотношение не установлено, щелкните всплывающее меню
разрешения (расположенное в левом верхнем углу панели «Игра»,
между «Дисплеем 1» и ползунком «Масштаб») и выберите из списка
WebGL x 2 (2048 x 15 36). Если этого параметра нет в списке, найдите инструкции
по его добавлению рядом с рисунком предыдущей главы.
2. Выберите Canvas в иерархии.
3. В разделе «Canvas Scaler (Script)» инспектора Canvas установите
следующие настройки:
    - a. Установите для параметра UI Scale Mode значение Scale With Screen
Size.
    - b. Установите для параметра «Reference Resolution» значения X: 1024, Y: 768.
    - c. Перетащите ползунок «Match» до самого правого края, чтобы
установить значение «Match» равным 1. Ползунок «Match»
определяет, будет ли Unity пытаться привести ширину или высоту
экрана в соответствие, если текущее соотношение сторон экрана
отличается от соотношения сторон эталонного разрешения. Значение 1 означает, что приоритет отдается высоте экрана. Подробнее об этом можно прочитать в документации Unity по настройке экрана. (https://docs.unity3d.com/Packages/com.unity.ugui@1.0/manual/script-CanvasScaler.html.)
4. Сохраните сцену!  

Вы увидите, что при установке эталонного разрешения на 1024x768 текст
FloatingScore увеличился вдвое. Это произошло потому, что эталонное
разрешение указало Canvas рендерить все с размерами, как если бы экран
был 1024x768, даже если разрешение другое (например, наше разрешение
WebGL x2, которое вдвое больше). Это чрезвычайно полезно при работе с
экранами разных размеров. Здесь мы используем разрешение вдвое
большего размера, чтобы Unity отображало изображение в редакторе с
более высоким разрешением, но планируем, что окончательный размер
сборки WebGL будет 1024x768.

### Тестирование скрипта FloatingScore, использующего BezierMover [!toc]
Далее мы создадим базовый класс FloatingScore для тестирования
BezierMover.  

1. Создайте новый скрипт на C# в папке папке Scripts с именем
FloatingScore, откройте его в Visual Studio и введите код, выделенный
жирным шрифтом, показанный в листинге кода. Это всего лишь
тестовый код, который вскоре будет заменен настоящим кодом
FloatingScore.  

      Листинг FloatingScore.cs

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;
using UnityEngine.Events;
using TMPro;

[RequireComponent( typeof(BezierMover) )]
[RequireComponent( typeof(TMP_Text) )] // FloatingScore will require TextMeshPro
public class FloatingScore : MonoBehaviour {
    void Awake() { // This is a testing method that will be completely replaced.
        int numPoints = 4;
        BezierMover mover = GetComponent<BezierMover>();

        List<Vector2> points = new List<Vector2>();
        Vector2 v2Half = new Vector2( 0.5f, 0.5f );
        points.Add( v2Half );
        for ( int i = 0; i < numPoints; i++ ) {
            points.Add( Random.insideUnitCircle * 0.5f + v2Half );
        }

        mover.completionEvent.AddListener( MoverCompleteCallback );
        mover.Init( points, numPoints );
    }

    void MoverCompleteCallback() {
        print( "FloatingScore is done!" );
    }

    // void Start() {…} // Please delete Start() and Update()
    // void Update() {…}
}
```

2. Сохраните все скрипты в Visual Studio и вернитесь в Unity.
3. Выберите GameObject FloatingScore в иерархии и в панели меню Unity
выберите *Component > Scripts > FloatingScore*.  

Если прокрутить вниз ниже компонента TextMeshPro в инспекторе объекта
FloatingScore, можно увидеть, что атрибут [RequireComponent(
typeof( BezierMover ) )] заставил Unity добавить как компонент
FloatingScore (Script), так и компонент
BezierMover (Script) к объекту FloatingScore.  

4. Нажмите «Play» в Unity.  

Теперь текст «+104» в FloatingScore будет самостоятельно перемещаться в
течение четырёх секунд. По истечении этого времени в консоли
отобразится сообщение «FloatingScore is done!». Изучив код, мы видим, что
это сообщение является результатом вызова
`BezierMover.MoverCompleteCallback()` событием UnityEvent
completionEvent в классе BezierMover. Теперь, когда мы
успешно завершили тестирование, мы можем интегрировать класс
FloatingScore в нашу игру.
