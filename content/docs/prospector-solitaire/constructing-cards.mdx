Это уменьшит конечный размер сборки и даст вам возможность увидеть, как работает JSON.  

На изображении на рисунке показан пример того, как это будет сделано, с использованием
спрайтов масти, декоратора, номинала и лица. На протяжении всего этого проекта мы будем
использовать эти термины, говоря о спрайтах, из которых состоит каждая карта:

<img src="/unity_doc/images/ex112.jpeg" alt="1" style={{  height: 'auto' }} />
Дама и тройка червей, на которых показаны все спрайты, из которых они состоят  

- Декоративные элементы: обозначения, расположенные в углах всех карт (масть и номинал в противоположных углах карты).
- Знаки масти (пипсы): крупные символы масти, расположенные в центральной части карты (например, три больших значка червей в центре тройки червей).
- Номиналы: цифры или буквы, входящие в состав обозначений в углах карты (например, A, 2, 3, …, Q, K).
- Фигуры: красивые изображения королей, дам и валетов, которые уникальны для каждой
масти. На рисунке показаны две карты, построенные следующим образом:
    - Дама состоит из шести спрайтов: 1× Card_Front, 2× Suit_Heart в качестве декораторов, 2×
Rank_12 (Q ) в качестве декораторов и 1× FaceCard_12H (изображение дамы червей).
    - Трефа червей состоит из восьми спрайтов: 1× Card_Front, 2× Suit_Heart в качестве
декораторов, 2× Rank_3 в качестве декораторов и 3× Suit_Heart в качестве мастей.  

Положение и поворот различных элементов, составляющих карту, определяются с помощью
файла JSON (JavaScript Object Notation), который был импортирован вместе с изображениями в
начале этой главы. Важно отметить, что файл JSON не хранит отдельную информацию для всех
52 карт в колоде; вместо этого он хранит информацию о расположении 13 различных рангов
карт. Макет тройки червей идентичен макету тройки пик, отличается только изображение масти;
поэтому вся информация в JSON сосредоточена на макете этих рангов, а не на повторении
информации четыре раза (по одному разу для каждой масти).  

Прочитайте раздел «JSON» в Приложении B «Полезные концепции», чтобы узнать больше о
JSON.  

### Использование JSON в коде [!toc]

Unity включает невероятно полезный класс под названием JsonUtility, который использует процесс
десериализации для автоматического преобразования между текстом JSON и объектом данных
C#, но прежде чем он сможет это сделать, вам сначала нужно настроить типы данных C# для
хранения информации, содержащейся в JSON. Опять же, эти данные JSON и эти классы не
представляют отдельные карты; скорее, они хранят информацию о расположении, необходимую
нашему движку для построения всех карт в колоде из всего лишь нескольких изображений. Если
вы хотите посмотреть весь файл, вы найдете его под названием
JSON_ Deck в папке *Assets > Resources* на панели Project. Выбрав этот файл на панели Project, вы
отобразите его содержимое в Unity Inspector. Если вы хотите прочитать весь файл, вы можете
открыть файлы JSON с помощью Visual Studio.  

Вот немного информации о том, как это будет работать. Если посмотреть на тройку червей,
показанную на рисунке, все изображения червы или цифры 3 на этой карте представлены в
файле JSON как пип или декоратор. Все номиналы имеют общие декораторы в тех же позициях,
поэтому мы будем хранить четыре декоратора отдельно от отдельных номиналов карт.  

В JSON информация о двух декораторах и картах ранга 3 и 12 (дама) показана в следующем
отрывке из JSON_Deck (я переформатировал JSON, чтобы он поместился в меньшем количестве
строк, но информация осталась прежней):  

Фрагмент **JSON_Deck** демонстрирующий декораторы, а также карты номиналом «3» и «дама»

Следующим важным шагом является определение классов на C#, которые смогут содержать всю
информацию из JSON-документа. Каждый уровень фигурных скобок в JSON-файле потребует
отдельного класса на C# для его хранения, но поскольку ни один из этих классов не расширяет
MonoBehaviour, мы можем включить их все в один и тот же файл C# вместе с подклассом
MonoBehaviour, который будет управлять разбором: JsonParseDeck.  

1. Создайте новый скрипт C# с именем JsonParseDeck и поместите его в папку __Scripts.
2. Откройте скрипт JsonParseDeck и вставьте строки из
листинга кода в указанном месте (между строками, начинающимися с
UnityEngine; и public class JsonParseDeck : MonoBehaviour).  

    Листинг кода JsonParseDeck.cs

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

// This class stores information about each decorator or pip from JSON_Deck
[System.Serializable] // a
public class JsonPip { // b
    public string type = "pip"; // "pip", "letter", or "suit"
    public Vector3 loc; // Location of the Sprite on the Card
    public bool flip = false; // True to flip the Sprite vertically
    public float scale = 1; // The scale of the Sprite
}

// This class stores information for each rank of card
[System.Serializable]
public class JsonCard { // c
    public int rank; // The rank (1-13) of this card
    public string face; // Sprite to use for each face card
    public List<JsonPip> pips = new List<JsonPip>(); // The pips on this card
}

// This class contains information about the entire deck
[System.Serializable]
public class JsonDeck { // d
    public List<JsonPip> decorators = new List<JsonPip>();
    public List<JsonCard> cards = new List<JsonCard>();
}

public class JsonParseDeck : MonoBehaviour
{
// void Start() {…} // Remove the unused Start() & Update() methods // e
// void Update() {…}
}
```

- a. Атрибут `[System.Serializable]` сообщает Unity, что мы хотим, чтобы эти классы
могли быть сериализованы. Сериализация - это процесс, который Unity использует для
отображения общедоступных полей в инспекторе, а также для преобразования данных C# в
JSON, тогда как десериализация - это процесс, с помощью которого данные JSON могут
быть преобразованы в C#.
- b. Как видно из JSON, для значков и мастей требуется одинаковая информация (type, loc,
flip и scale), поэтому мы создали единый класс JsonPip для хранения данных обоих
элементов.
- c. Класс JsonCard будет использоваться для представления информации о макете для
каждого ранга карты. Сюда входит ранг карты, наличие изображения на лицевой стороне
(которое требуется для валетов, дам и королей) и список всех пипсов на карте (в виде
`List<JsonPip>`).
- d. Класс JsonDeck содержит как список декораторов, которые будут находиться в углах
каждой карты (в виде `List<JsonPip>`), так и список всех 13 типов карт в колоде (в виде
`List<JsonCard>`). Все карты имеют декораторы в одинаковых позициях, поэтому мы
храним эту информацию как часть класса JsonDeck, а не повторяем ее для каждого ранга в
JsonCard.
- e. Пожалуйста, удалите методы `Start()` и `Update()` из класса JsonParseDeck. Как
правило, рекомендуется удалять их, если мы не собираемся их использовать, поэтому,
пожалуйста, удалите их, если вы не видите их ни в одном из примеров кода.  

Обратите внимание, что все три этих публичных класса находятся вне класса JsonParseDeck
и ни один из них не расширяет MonoBehaviour. Они предназначены лишь для хранения
информации, извлеченной из файла JSON_Deck.json с помощью JsonUtility от Unity. Обязательно
добавьте атрибут [System.Serializable] над каждым из них. Это позволит JsonUtility
Unity сериализовать данные из каждого класса и десериализовать данные в каждый класс. Без
атрибута компилятора [System.Serializable] JsonUtility не сможет выполнять свою
работу, и вы получите нулевые данные там, где должна была быть информация из JSON.  

Теперь давайте заставим JsonUtility работать на нас.  

3. Добавьте выделенные жирным шрифтом строки из листинга кода в скрипт JsonParseDeck:

```c#
public class JsonParseDeck : MonoBehaviour {
    [Header("Inscribed")]
    public TextAsset jsonDeckFile; // Reference to the JSON_Deck text file

    [Header("Dynamic")]
    public JsonDeck deck;

    void Awake() {
        deck = JsonUtility.FromJson<JsonDeck>(jsonDeckFile.text); // a
    }
}
```

    - a. В этой небольшой строке происходит многое. Здесь вызывается метод `FromJson()` класса
JsonUtility, который преобразует текстовую строку в реальные классы (или структуры)
C#. Аргумент типа `<JsonDeck>` сообщает обобщенному методу `FromJson()`, что он
должен попытаться преобразовать этот текст в экземпляр класса JsonDeck (который
затем будет включать несколько экземпляров JsonPips и JsonCards). Без этого аргумента типа
`FromJson()` не смог бы понять, как интерпретировать JSON.  

Теперь нам нужно подключить все в Unity, чтобы увидеть, как работает магия!  

4. Сохраните скрипт JsonParseDeck в Visual Studio и вернитесь в Unity.
5. Прикрепите скрипт JsonParseDeck к объекту _MainCamera в сцене «_Prospector_Scene_0».
6. Выберите _MainCamera в иерархии и перетащите текстовый файл JSON_Deck из
папки Resources в панели Project в общедоступное поле jsonDeckFile компонента
компонента JsonParseDeck объекта _MainCamera. Это указывает JsonParseDeck, какой
текстовый файл нужно проанализировать.
7. Сохраните сцену и нажмите «Play»!  

Если вы раскроете треугольник раскрытия для deck под заголовком Dynamic, то увидите, что
информация обо всех 13 картах и 4 декораторах на всех картах заполнила deck с помощью
всего одной строки кода! Это можно увидеть на рисунке *a*, где показаны данные для карты
3 (элемент 2) и дамы (элемент 11), которые использовались в качестве примеров на протяжении
всей этой главы. Хотя существует множество способов чтения текстовых файлов, JsonUtility
становится стандартом в Unity благодаря простоте использования.
