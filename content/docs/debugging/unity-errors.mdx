Обычно они отображаются в виде красных ошибок в панели
«Консоль», но относятся к аспектам Unity, над которыми вы не имеете
контроля. Раньше это происходило гораздо чаще, и я всегда рекомендую
решать эту проблему одинаково:  

1. Если в панели «Консоль» появляется красная ошибка, которая, по-
видимому, не связана с вашим кодом, нажмите кнопку «Очистить» в
левом верхнем углу консоли. Если ошибка не повторяется (что бывает
очень часто), то все готово!
2. Если ошибка не исчезает, сообщите об ошибке, чтобы Unity смогло ее
исправить. В главной панели меню Unity выберите *«Справка» > «Сообщить об ошибке»*  

Это откроет приложение Unity Bug Reporter и даст вам возможность
объяснить, что, по вашему мнению, произошло. Будет очень полезно, если
вы сможете описать, что вы делали до появления ошибки. Когда я знаю,
какие шаги были предприняты, и их сложно описать текстом, я часто
использую OBS3 для записи видео с экрана, демонстрирующего действия,
приводящие к появлению ошибки. В любом случае, Unity не сможет
исправить проблему, если вы не сообщите им о ней, поэтому, пожалуйста,
сообщайте о любых обнаруженных ошибках, особенно если вы можете
выяснить, как заставить ошибку надежно повторяться.

## Пошаговое выполнение кода с помощью отладчика

В дополнение к инструментам автоматической проверки кода, которые вы
уже изучили в этой главе, Unity и Visual Studio также позволяют проходить
код построчно, что может быть очень полезно для понимания того, что
происходит в вашем коде.

1. Откройте скрипт CubeSpawner2 в Visual Studio.
2. Удалите метод Start.
3. Добавьте выделенные жирным шрифтом строки, показанные в
листинге кода. Окончательный код также показан на рисунке. (В этом листинге кода вы можете увидеть, как открывающая
фигурная скобка на отдельной строке может увеличить длину
скрипта.)  

Листинг кода *CubeSpawner2.cs*

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class CubeSpawner2 : MonoBehaviour
{
    public GameObject cubePrefabVar;

    // Update is called once per frame
    void Update()
    {
        SpellItOut(); // a
        // Instantiate( cubePrefabVar ); // Use // to comment out this line!
        GameObject cubeGO = Instantiate<GameObject>( cubePrefabVar );
        Material mat = cubeGO.GetComponent<Renderer>().material;
        mat.color = Random.ColorHSV( 0, 1, 0.5f, 1, 0.75f, 1 );
    }

    public void SpellItOut () // b
    {
        string sA = "Hello World!";
        string sB = "";

        for (int i=0; i<sA.Length; i++) // c
        {
            sB += sA[i]; // d
        }

        print(sB);
    }
}
```
a. Эта строка вызывает функцию `SpellItOut()` один раз при каждом
обновлении.  

b. В строках 19–30 объявляется и определяется функция
`SpellItOut()`. Эта функция копирует содержимое строки `sA` в
строку `sB` по одному символу за раз.  

c. Этот цикл `for` проходит по всей длине `sA`. Поскольку строка
«Hello World!» состоит из 12 символов, цикл пройдет 12
раз.  

d. Эта строка извлекает `i-й` символ из `sA` и добавляет его в конец `sB`. Это
ужасно неэффективный способ копирования строки, но он отлично
подойдет для демонстрации работы отладчика.  

4. После того как вы ввели весь код и дважды его проверили, щелкните в
промежутке (где курсор показан на рисунке) слева от строки 12
(или любой другой строки, вызывающей 4 в вашем коде).  

Это создает точку останова в строке 12, которая отображается в виде
красного кружка. Когда вы устанавливаете точку останова и
отладчик Visual Studio подключен к Unity, Unity будет приостанавливать
выполнение каждый раз, когда достигает любой точки останова. Давайте
проверим это.

### Включение отладки в Unity 2020

До версии Unity 2020 весь код в редакторе Unity всегда компилировался в
режиме отладки, что позволяло запускать отладчик в любое время. Однако
в связи с недавними шагами Unity по повышению эффективности и
стабильности в последних версиях весь код теперь по умолчанию
компилируется в режиме релиза.  

Код в режиме Release работает быстрее и эффективнее, но к нему нельзя
подключить отладчик. В Unity 2020.3 в правом нижнем углу окна Unity
появилась новая кнопка «Отладка», которая позволяет переключить
компиляцию в режим отладки (показано на рисунке).

<img src="/unity_doc/images/ex15.jpeg" alt="1" style={{  height: 'auto' }} />

Кнопка «Отладка» с тремя состояниями  

Чтобы подготовить Unity к отладке:  

1. Если ваш редактор Unity в данный момент находится в режиме
Release (кнопка Debugging серого цвета), нажмите кнопку Debugging, что откроет окно с
объяснением различных режимов компиляции кода.
2. Нажмите кнопку «Перейти в режим отладки». Теперь значок ошибки
должен показать, что он находится в режиме отладки, изменившись на
желтый значок с восклицательным знаком.  

Теперь, когда редактор Unity находится в режиме отладки, вы можете
подключить к нему отладчик Visual Studio.

### Подключение отладчика к Unity

Чтобы Visual Studio мог отлаживать то, что происходит в Unity во время
воспроизведения, вам нужно подключить его к процессу Unity, что соединит
отладчик с внутренними механизмами выполнения кода Unity. После
присоединения отладчика Visual Studio к Unity он сможет заглянуть в
глубину происходящего в вашем коде C# и приостанавливать выполнение
кода на точках останова  

Эта часть процесса наиболее отличается в macOS и Windows.  

Подключение отладчика в macOS  

В macOS процесс в Visual Studio проще, чем в Windows, но выбрать
правильный процесс Unity для присоединения сложнее.  

1. В верхней части окна Visual Studio нажмите кнопку воспроизведения
(показанную под курсором на рисунке).  

На момент написания этой статьи вы увидите окно, в котором
отображаются два запущенных процесса Unity. Один из
них - это Unity Editor, а другой - Unity Hub (и если у вас запущено несколько экземпляров Unity, вы также увидите процесс для
каждого из них). К сожалению, вам придется просто угадать, какой из них
нужный. Я обычно просто дважды щелкаю по верхнему и надеюсь на
лучшее. (Версия этого окна для Windows знает, какой процесс какой, так
что я надеюсь, что эта функция появится в macOS к тому времени, когда
вы будете читать эту главу.)

<img src="/unity_doc/images/ex16.jpeg" alt="1" style={{  height: 'auto' }} />

Присоединение отладчика к процессу Unity Editor в macOS  

2. Щелкните один из двух процессов Unity Editor (работающих в
фоновом режиме), а затем нажмите «Присоединить».
3. Есть два способа проверить, присоединились ли вы к правильному
процессу:  

a. В Unity Editor кнопка «Отладка» будет отображаться в виде синего
значка
«Отладчик подключен», если отладчик подключен правильно. (Если вы подключились к
неправильному процессу, значок кнопки останется желтым значком
режима отладки с восклицательным знаком.)  

b. В Visual Studio, если вы подключились к правильному процессу,
красный кружок точки останова на строке 12 по-прежнему будет
отображать мишень с несколькими кружками внутри. (Если вы
подключились к неправильному процессу, красный кружок точки
останова будет представлять собой просто одно пустое кольцо без
ничего внутри.)
4. Если вы подключились не к тому процессу, нажмите кнопку
«Остановить отладку» в Visual Studio (там, где была кнопка
воспроизведения), а затем повторите шаги 1–3, щелкнув по другому процессу.

«Подключить к Unity»), как показано на рисунке, то НЕ

### Использование отладчика для проверки кода

Теперь, когда отладчик готов и подключен, пришло время посмотреть, как
он работает. Вы заметите, что окно Visual Studio изменилось. В нижней части окна Visual Studio появилось несколько панелей и
ряд кнопок для управления отладчиком. Я расскажу о них в
ближайшее время.

1. Переключитесь в Unity и нажмите кнопку «Play», чтобы запустить
сцену. Практически сразу Unity зависнет, и должно появиться окно
Visual Studio. Иногда в Windows Visual Studio не открывается
автоматически, но Unity выглядит зависшим. Просто вручную
переключитесь на задачу Visual Studio, и вы должны увидеть то, что
показано на рисунке:

<img src="/unity_doc/images/ex17.jpeg" alt="1" style={{  height: 'auto' }} />

Выполнение метода Update() приостановилось на 12-й строке, где вы
установили точку останова. Стрелка в боковом поле и желтая линия рядом
с ней показывают текущую строку выполнения. Пока выполнение
остановлено в отладчике, процесс Unity полностью заморожен. Это
означает, что вы не сможете переключиться на него обычным способом,
пока он не запустится снова.  

В режиме отладки некоторые кнопки в верхней части панели
инструментов Visual Studio изменились:

<img src="/unity_doc/images/ex18.jpeg" alt="1" style={{  height: 'auto' }} />

Кнопки управления отладчиком для macOS и Windows  

Следующие шаги показывают, как работают различные кнопки управления
отладчиком.  

2. Нажмите кнопку «Продолжить» отладчика в Visual Studio. Это заставит Unity продолжить выполнение скрипта.
Когда Unity останавливается на точке останова, такой как в строке 12,
все в Unity замораживается, пока вы не дадите команду продолжить.  

Когда вы нажимаете кнопку «Продолжить» в Visual Studio, Unity снова
запускается и работает до тех пор, пока не достигнет другой точки
останова. Когда вы нажали «Запустить», Unity прошел игровой цикл,
запустил новый кадр, а затем снова остановился на 12-й строке (когда в
следующем кадре был вызван `Update()`), поэтому вы могли даже не
заметить, что это произошло, кроме мигания или мерцания окна Visual
Studio.

3. Когда стрелка выполнения снова остановится на точке останова в
строке 12, нажмите кнопку «Step Over» (Пройти). Жёлтая стрелка
переместится на строку 14, не заходя в функцию `SpellItOut()` (и
не останавливаясь на строке 13, которая является просто
комментарием). Функция `SpellItOut()` по-прежнему вызывается
и выполняется, но отладчик пропускает ее. Команда «Step Over»
полезна, если вы не хотите видеть внутреннее поведение вызываемой
функции.
4. Снова нажмите «Continue». Unity переходит к следующему кадру,
и желтая стрелка выполнения снова останавливается на точке
останова в строке 12.
5. В третий раз нажмите «Step Into». Жёлтая стрелка перескакивает со
строки 14 к началу метода `SpellItOut()` (в зависимости от
отладчика это может быть строка 20 (Windows) или 21 (macOS)).
Каждый раз, когда вы нажимаете «Step Into», отладчик входит в
вызываемые функции.
6. Убедитесь, что видна панель «Локальные переменные», на которой
отображаются все переменные, доступные текущей функции (в
данном случае это `SpellItOut()`). Чтобы открыть эту панель из
панели меню Visual Studio, выберите *«Вид» > «Окна отладки» > «Локальные» (macOS) или «Отладка» > «Окна» >
«Локальные»* (Windows).
7. Теперь, когда вы находитесь внутри функции `SpellItOut()`,
нажмите Step Over несколько раз, чтобы пройти по шагам
выполнение функции `SpellItOut()`.
8. Продолжая нажимать «Step Over», вы можете наблюдать за изменением
значений sA и sB в ходе выполнения этой функции.  

При каждом проходе цикла for в строках 24–27 в строку `sB` добавляется
один символ из `sA`. Изменение значений переменных можно наблюдать на
панели отладчика «Локальные переменные».

### Просмотр переменных в отладчике [!toc]
Одним из главных преимуществ любого отладчика является
возможность просматривать значение отдельной переменной
практически в любой момент времени. Отладчик Visual Studio
предлагает три различных способа сделать это. Прежде чем
попробовать любой из них, убедитесь, что вы выполнили
инструкции, приведенные в этой главе, и запустили процесс
отладки.  

Наведите указатель мыши на переменную: Первый и самый
простой способ - просто навести указатель мыши на любую
переменную в панели кода Visual Studio. Если вы наведете
указатель мыши на имя переменной и удержите его в таком
положении примерно одну секунду, появится всплывающая
подсказка с указанием значения этой переменной.
Однако очень важно отметить, что отображаемое значение - это
текущее значение переменной, основанное на положении желтой
стрелки, а не на положении этой переменной в коде. Например, переменная `sB` функции `SpellItOut()` повторяется несколько
раз в коде, и при наведении курсора на любую из них будет
отображаться одно и то же значение.  

Панель «Локальные переменные»: Второй способ - найти
переменную в
панели «Локальные» отладчика. Чтобы открыть эту панель, в строке
меню Visual Studio выберите *«Вид» > «Окна
отладки» > «Локальные» (macOS) или «Отладка» >
Окна > «Локальные»* (Windows). При
этом на передний план выйдет панель наблюдения за переменными
«Локальные». Здесь вы увидите список всех локальных
переменных, доступных отладчику в данный момент. Если вы
выполните пошаговую отладку функции `SpellItOut()`, как
указано в этой главе, и окажетесь на 19-й строке, то увидите в
списке как минимум три локальные переменные: this, sA и sB
(там могут быть и другие переменные). Переменные sA и sB
изначально имеют значение null, но их значения появляются в
панели «Локальные» после того, как они были определены в
строках 19 и 20 соответственно. После нескольких нажатий на
«Пройти» и достижения строки 22 в отладчике вы увидите, что в
этой строке объявлено и определено целое число i. Переменная
this ссылается на текущий экземпляр скрипта CubeSpawner2.
Щелкните треугольник раскрытия рядом с this, чтобы
отобразить общедоступное поле cubePrefabVar внутри this, а
также переменную с именем base. Раскрытие треугольника рядом
с base показывает все переменные, связанные с базовым классом
CubeSpawner2, которым является MonoBehaviour. Базовые
классы, такие как MonoBehaviour (также известные как
суперклассы или родительские классы), рассматриваются в главе
«Классы».  

Панель «Наблюдение»: Третий способ просмотра значения
переменной - ввести его вручную в панель «Наблюдение». Чтобы
открыть эту панель, в строке меню Visual Studio выберите *«Вид» >
«Окна отладки» >«Наблюдение»* (macOS)
или *«Отладка» > Окна отладки > Watch > Watch

10. Находясь все еще внутри функции `SpellItOut()`, нажмите «Step
Out». Это приведет к тому, что отладчик выйдет из функции
`SpellItOut()`. В macOS это перенесет выполнение на строку 14
(следующую строку кода после вызова `SpellItOut()`), а в Windows
стрелка выполнения все еще будет находиться на строке 12, но после

функции `SpellItOut()` все равно была выполнена; просто вы не
видели этого в отладчике. Это полезно, когда вы хотите выйти из
текущей функции, но не хотите полностью возвращаться к
выполнению на полной скорости, нажав «Continue».
11. Нажмите кнопку «Stop Debugging», чтобы отсоединить отладчик
Visual Studio от процесса Unity и вернуть Unity к нормальному
выполнению. Это не остановит воспроизведение в Unity, поэтому,
если вы теперь вернетесь в Unity, скрипт CubeSpawner2 по-прежнему
будет генерировать кубы.
12. Если вы не занимаетесь активной отладкой, вы можете вернуть

Честно говоря, я использую отладчик так часто, что обычно оставляю
Unity в режиме отладки.

использовали отладчик для поиска неизвестной ошибки, вы можете
