1. Превратите щит героя в триггер:
    - a. Раскройте список дочерних объектов для _Hero в окне Hierarchy (нажмите на треугольник рядом с именем объекта).
    - b. Выберите дочерний объект Shield (щит) внутри _Hero.
    - c. В окне Inspector установите для компонента Sphere Collider щита режим триггера (установите флажок Is Trigger). Вам не нужно, чтобы объекты отскакивали от щита; достаточно лишь фиксировать момент столкновения.
2. Откройте скрипт *Hero* в Visual Studio и добавьте в его конец метод:  
    Листинг Hero.cs

```c#
public class Hero : MonoBehaviour {
    …

    void Update () { … }

    void OnTriggerEnter(Collider other) {
        Transform rootT = other.gameObject.transform.root; // a
        GameObject go = rootT.gameObject;
        Debug.Log("Shield trigger hit by: " + go.gameObject.name);
    }
}
```

Теперь, если запустить сцену и направить корабль на врагов, вы увидите, что метод `OnTriggerEnter()` сообщает о столкновении с Enemy_0(Clone) - экземпляром объекта Enemy_0.  

>Если вы не получаете эти сообщения, убедитесь, что для компонента Sphere Collider щита установлен режим триггера (шаг 1.c). Еще одна распространенная проблема, с которой я сталкиваюсь, заключается в том, что враги или объект _Hero находятся не на позиции Z=0.

### Совет [!toc]
**Итеративная разработка кода.** При самостоятельной разработке прототипа вам часто придется выполнять подобные проверки с выводом сообщений в консоль, чтобы убедиться в корректной работе написанного кода. На мой взгляд, проведение таких небольших промежуточных тестов гораздо эффективнее, чем многочасовая работа над кодом, которая в итоге может привести к обнаружению ошибки, возникшей где-то в процессе. Поэтапное тестирование значительно упрощает отладку: поскольку с момента последней успешной проверки вы внесли лишь незначительные изменения, найти место, где появилась ошибка, становится гораздо проще.  

Еще одним важным элементом этого подхода является использование отладчика. В процессе написания этой книги, всякий раз сталкиваясь с ситуацией, когда код работал не так, как я ожидал, я обращался к отладчику, чтобы разобраться в происходящем. Эффективное использование отладчика часто становится решающим фактором: оно позволяет устранить проблемы в коде, тогда как в противном случае можно часами бездумно смотреть на страницы с программным текстом. Попробуйте установить точку останова (breakpoint) в только что добавленном методе `OnTriggerEnter()` и понаблюдать за тем, как выполняется код и как изменяются значения переменных.  

Итеративная разработка кода обладает теми же преимуществами, что и итеративный процесс проектирования; она лежит в основе методологии гибкой разработки (Agile).
</Callout>

Далее мы изменим метод `OnTriggerEnter()` класса `Hero` так, чтобы при столкновении с врагом прочность щита игрока уменьшалась на 1, а сам враг уничтожался. Мы также предусмотрим защиту от повторного срабатывания триггера одним и тем же родительским игровым объектом (что может произойти с очень быстро движущимися объектами, когда два дочерних коллайдера одного объекта касаются триггера щита в пределах одного кадра).  

3. Откройте скрипт Hero в Visual Studio и внесите изменения:  
    Листинг кода Hero.cs

```c#
public class Hero : MonoBehaviour {
    …
    [Header("Dynamic")]
    public float shieldLevel = 1;
    [Tooltip( "This field holds a reference to the last triggering GameObject" )]
    private GameObject lastTriggerGo = null; // a
    …

    void OnTriggerEnter(Collider other) {
        Transform rootT = other.gameObject.transform.root;
        GameObject go = rootT.gameObject;
        // Debug.Log("Shield trigger hit by: " +go.gameObject.name); // b

        // Make sure it’s not the same triggering go as last time
        if ( go == lastTriggerGo ) return; // c
        lastTriggerGo = go; // d

        Enemy enemy = go.GetComponent<Enemy>(); // e
        if (enemy != null) { // If the shield was triggered by an enemy
            shieldLevel--; // Decrease the level of the shield by 1
            Destroy(go); // … and Destroy the enemy // f
        } else {
            Debug.LogWarning("Shield trigger hit by non-Enemy: "+ go.name); // g
        }
    }
}
```

    - a. В этом закрытом поле `lastTriggerGo` будет храниться ссылка на последний объект `GameObject`, который активировал коллайдер `_Hero`. Изначально оно имеет значение `null`.
    - b. Закомментируйте эту строку.
    - c. Если `lastTriggerGo` совпадает с `go` (текущим объектом `GameObject`, вызвавшим срабатывание триггера), то это событие игнорируется как дубликат, и выполнение функции прекращается (происходит выход из нее). Такая ситуация может возникнуть, если два дочерних объекта `GameObject` одного и того же врага (Enemy) одновременно (то есть в течение одного кадра) активируют коллайдер героя.
    - d. Присвойте переменной `lastTriggerGo` значение `go`, чтобы подготовить ее к последующим вызовам `OnTriggerEnter()`.
    - e. В предыдущих главах мы проверяли тег объекта `GameObject`, чтобы определить его тип, однако в своей практике я почти никогда так не делаю. Я считаю, что проверка наличия определенного скрипта на объекте `GameObject` - гораздо более надежный способ определить, что это за объект (поскольку это позволяет избежать ошибок, вызванных возможными опечатками в названии тега).
    - f. Объект `go` (вражеский `GameObject`) уничтожается при столкновении со щитом. Поскольку проверяемый объект `go` - это вражеский `GameObject`, найденный с помощью `transform.root`, удален будет весь враг целиком (а следовательно, и все его дочерние объекты), а не только один из дочерних элементов врага.
    - g. Если `_Hero` столкнется с объектом, не имеющим тега `Enemy`, в консоль будет выведено сообщение с информацией об этом объекте. Подобная ситуация не должна возникать, но эта проверка добавлена ​​на всякий случай. Здесь используется `Debug.LogWarning()` вместо `Debug.Log()`, чтобы сообщение было более заметным в окне консоли: обычные сообщения `Log` имеют серый значок, тогда как сообщения `LogWarning` отображаются в консоли со значком желтого треугольника.  

4. Запустите сцену и попробуйте столкнуться с несколькими кораблями. После нескольких столкновений вы можете заметить странное поведение щита: после полной потери заряда его уровень снова восстанавливается до максимума. Как вы думаете, чем это вызвано? Попробуйте выбрать объект _Hero в окне Hierarchy во время воспроизведения сцены, чтобы понаблюдать за изменениями поля shieldLevel.  

Поскольку у переменной shieldLevel нет нижнего предела, ее значение может опускаться ниже нуля.
Скрипт Shield на языке C# преобразует это в отрицательные значения смещения по оси X для материала Mat_Shield, и
поскольку для текстуры материала включен режим циклического повторения (loop), создается визуальный эффект восстановления щита до полной мощности.
Также стоит отметить, что ползунок shieldLevel в окне Inspector, созданный с помощью атрибута [Range(0,4)] (строка `// b` в листинге), ограничивает лишь те значения,
которые можно задать непосредственно в интерфейсе Unity Inspector. Ваш код на C# может присваивать переменной shieldLevel любое значение.  

Чтобы устранить проблему с отрицательным значением, нужно преобразовать `shieldLevel` в свойство, которое управляет доступом к новому приватному полю с именем `_shieldLevel` и ограничивает его. Свойство `shieldLevel` отслеживает значение поля `_shieldLevel` и гарантирует, что оно не превысит 4, а также обеспечивает уничтожение корабля, если значение упадет ниже 0. Поле вроде `_shieldLevel` следует сделать приватным (`private`), так как другим классам не нужен прямой доступ к нему; однако в Unity приватные поля обычно не отображаются в Инспекторе. Решение заключается в том, чтобы добавить строку `[SerializeField]` перед объявлением `_shieldLevel` - это укажет Unity отображать поле в Инспекторе, несмотря на его приватный статус. Свойства же никогда не отображаются в Инспекторе, даже если они являются публичными (`public`).  

5. В классе Hero замените поле `public float shieldLevel` на `private float _shieldLevel` (разместив его в верхней части класса) и добавьте атрибут `[SerializeField]` к уже имеющимся там атрибутам. Затем добавьте свойство `public shieldLevel` в конце класса.  
    Листинг кода Hero.cs

```c#
public class Hero : MonoBehaviour {
    …
    [Header("Dynamic")] [Range(0,4)] [SerializeField]
    private float _shieldLevel = 1; // Remember the underscore
    // public float shieldLevel = 1; // and remove this old line
    [Tooltip( "This field holds a reference to the last triggering GameObject" )]
    private GameObject lastTriggerGo = null;
    …

    void OnTriggerEnter(Collider other) {
        …
        Enemy enemy = go.GetComponent<Enemy>();
        if (enemy != null) { // If the shield was triggered by an enemy…
        shieldLevel--; // Decrease the level of the shield by 1 // a
        Destroy(go); // … and Destroy the enemy
        } else {
            Debug.Log("Shield trigger hit by non-Enemy: "+go.name);
        }
    }

    public float shieldLevel {
        get { return ( _shieldLevel ); } // b
        private set { // c
            _shieldLevel = Mathf.Min( value, 4 ); // d
            // If the shield is going to be set to less than zero…
            if (value < 0) { // e
                Destroy(this.gameObject); // Destroy the Hero
            }
        }
    }
}
```

    - a. Строка `shieldLevel--;` в методе `OnTriggerEnter()` задействует как блок `get`, так и блок `set` свойства `shieldLevel`. Сначала используется блок `get` для получения текущего значения `shieldLevel`, затем из этого значения вычитается единица, и вызывается блок `set` для присвоения полученного результата обратно.
    - b. Блок `get` просто возвращает значение переменной `_shieldLevel`. Вполне допустимо записывать этот блок в одну строку.
    - c. Ключевое слово `private` гарантирует, что, хотя получить значение `shieldLevel` может любой класс, изменить его способен только класс `Hero`.
    - d. Метод `Mathf.Min()` гарантирует, что значение `_shieldLevel` никогда не превысит 4.
    - e. Если значение, переданное в блок `set`, меньше 0, объект `_Hero` уничтожается.  

Теперь, если вы будете играть, уровень щита будет снижаться, а затем корабль героя будет уничтожен.
