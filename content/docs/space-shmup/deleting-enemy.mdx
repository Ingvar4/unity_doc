1. Выберите префаб Enemy_0 в папке _Prefabs на панели Project.
2. Установите параметр keepOnScreen в значение false (снимите галочку) в компоненте BoundsCheck (Script) на панели Inspector.  

После выполнения этих действий компонент BoundsCheck (Script) как у префаба Enemy_0 на панели Project, так и у экземпляра Enemy_0 на панели Hierarchy должен выглядеть так, как показано на рисунке.

<img src="/unity_doc/images/ex86.jpeg" alt="1" style={{  height: 'auto' }} />
Настройки компонента BoundsCheck (Script) как для префаба, так и для экземпляра Enemy_0.  

При таких настройках скрипт BoundsCheck не будет принудительно удерживать Enemy_0 в пределах экрана, однако он будет отслеживать нахождение объекта в кадре (или за его пределами); значение переменной isOnScreen станет равным false, когда Enemy_0 полностью покинет экран, что позволит нам уничтожить игровой объект так, чтобы игрок не увидел, как тот внезапно исчезает.  

3. Добавьте в скрипт Enemy выделенный жирным шрифтом код из листинга, чтобы управлять этим процессом уничтожения:  
    **Enemy.cs**

```c#
[RequireComponent( typeof(BoundsCheck) )] // a
public class Enemy : MonoBehaviour {
    …
    public float health = 10; // Damage needed to destroy this enemy
    public int score = 100; // Points earned for destroying this

    private BoundsCheck bndCheck; // b

    void Awake() { // c
        bndCheck = GetComponent<BoundsCheck>();
    }

    // This is a Property: A method that acts like a field
    public Vector3 pos { … }

    void Update() {
        Move();

        // Check whether this Enemy has gone off the bottom of the screen
        if ( !bndCheck.isOnScreen ) { // d
            if ( pos.y < bndCheck.camHeight - bndCheck.radius ) {
                // We’re off the bottom, so destroy this GameObject
                Destroy( gameObject );
            }
        }
    }

    public virtual void Move() { … }
}
```

    - a. Атрибут компилятора `[RequireComponent( typeof(BoundsCheck) )]` сообщает Unity, что любой игровой объект (GameObject), к которому прикреплен этот класс `Enemy`, должен также иметь компонент `BoundsCheck`. Большим преимуществом здесь является то, что этот атрибут наследуется подклассами `Enemy`; следовательно, все подклассы `Enemy`, которые вы напишете в следующей главе, также будут требовать наличия компонента `BoundsCheck`, и при их добавлении к префабам игровых объектов врагов Unity будет автоматически присоединять к ним этот компонент.
    - b. Эта закрытая (private) переменная позволяет скрипту `Enemy` хранить ссылку на компонент `BoundsCheck`, расположенный на том же игровом объекте.
    - c. Метод `Awake()` выполняет поиск компонента скрипта `BoundsCheck`, прикрепленного к этому же игровому объекту. Если такой компонент отсутствует, переменной `bndCheck` будет присвоено значение `null`, однако на практике этого никогда не произойдет благодаря атрибуту компилятора `[RequireComponent]`. Я часто размещаю код, выполняющий поиск компонентов и кэширование ссылок, именно в методе `Awake()`, чтобы ссылки были готовы к использованию сразу же после создания экземпляра игрового объекта.
    - d. Если переменная `isOnScreen` имеет значение `false`, данная конструкция `if` проверяет, не вышел ли объект за пределы экрана из-за того, что его координата `pos.y` стала слишком низкой (то есть объект ушел за нижнюю границу экрана). В этом случае игровой объект уничтожается.  

Это решение работает и выполняет поставленную задачу, однако выполнять одно и то же сравнение `pos.y` с `camHeight` и `radius` и здесь, и в классе `BoundsCheck` кажется не слишком аккуратным подходом. Хорошим стилем программирования - и основой паттерна проектирования «Компонент» (Component Design Pattern) - считается принцип, согласно которому каждый класс C# отвечает за свою непосредственную задачу, избегая подобного смешения обязанностей.  

В связи с этим давайте изменим метод BoundsCheck так, чтобы он мог сообщать, в каком именно направлении игровой объект (GameObject) вышел за пределы экрана. Нам нужно знать, находится ли он в пределах экрана (onScreen) или вышел за его границы справа (offRight), слева (offLeft), сверху (offUp) либо снизу (offDown); поэтому для хранения этой информации лучше всего подойдет перечисление (enum). Однако игровой объект может одновременно выйти за границы и справа, и сверху. Чтобы можно было хранить оба этих значения одновременно, мы создадим тип перечисления eScreenLocs с использованием атрибута компилятора [System.Flags]. Подробнее о том, как это работает, см. во врезке «Использование побитовых операций с перечислениями System.Flags».  

Для этого мы создадим перечисление (enum) с атрибутом компилятора `[System.Flags]`. При использовании атрибута `Flags`, если значения элементов перечисления заданы как степени двойки (например, 0, 1, 2, 4, 8), такое перечисление сможет хранить несколько значений одновременно. Unity постоянно использует этот подход при работе со слоями (Layers), в частности со слоями физики (Physics Layers). Дополнительную информацию о перечислениях можно найти во врезке «Использование побитовых операторов с перечислениями System.Flags» (см. далее), а также в разделе «Перечисления» (Enums) в Приложении B. Еще один пример использования перечисления с атрибутом `[System.Flags]` приведен в подразделе «Паттерн "Наблюдатель"» (Observer Pattern) раздела «Объектно-ориентированные паттерны проектирования».  

<Callout>
### Использование побитовых операторов с перечислениями System.Flags [!toc]
Если перечисление (enum) имеет атрибут компилятора `[System.Flags]`, оно может хранить несколько значений одновременно. Перечисления с атрибутом `[System.Flags]` также называют битовыми масками, поскольку каждый двоичный разряд (бит) в таком перечислении можно рассматривать как индикатор того, истинно или ложно соответствующее ему отдельное значение. Например, тип `LayerMask` в Unity - это перечисление с атрибутом `[System.Flags]`, где каждый из 32 битов определяет, включен или выключен один из 32 возможных слоев (Layers). В этом можно убедиться, выбрав объект `MainCamera` в окне Hierarchy (иерархия сцены) и посмотрев на выпадающее меню Culling Mask в компоненте Camera в окне Inspector. По умолчанию для Culling Mask установлено значение Everything (включены все слои, то есть камера отрисовывает игровые объекты на всех слоях), однако слои можно включать и выключать по отдельности, так как `LayerMask` является перечислением типа Flags.  

Перечисление `eScreenLocs` с атрибутом `[System.Flags]` работает аналогичным образом. Значение каждой из определенных позиций за пределами экрана представляет собой отдельную степень двойки, как показано на рисунке 31.7b. Поскольку эти значения являются степенями двойки (0, 1, 2, 4 и 8), каждое из них может быть представлено одним битом в перечислении.  

Как показано на рисунке, если игровой объект находится за пределами экрана справа, его значение `eScreenLocs` равно `offRight`, что хранится как бит `0001` (десятичное значение 1). Значение `offUp` хранится как бит `0100` (десятичное значение 4). Если игровой объект находится одновременно справа (`offRight`) и сверху (`offUp`) от экрана, то значение `eScreenLocs` будет равно `0101` (десятичное значение 5), объединяя оба состояния (`offRight` и `offUp`) в одном значении перечисления.

<img src="/unity_doc/images/ex87.jpeg" alt="1" style={{  height: 'auto' }} />

Примеры применения побитовых операторов `&` и `|` к перечислениям eScreenLocs.  

На рисунке *b* показаны все объявленные значения eScreenLocs вместе с их двоичным и десятичным представлениями.

На рисунке *c* показано, что происходит при использовании `|` (побитовое ИЛИ) или `&` (побитовое И) для объединения значений eScreenLocs. Хотя можно использовать + для объединения двух значений перечисления [System.Flags] (например, offRight + offUp равно 0101), гораздо чаще используется |. Каждый бит в результате | будет равен 1, если этот бит в любом из операндов равен 1, поэтому результат offLeft | offUp (0010 | 0100) равно 0110.  

С другой стороны, каждый бит в результате `&` будет равен 1 только в том случае, если этот бит равен 1 в обоих
операндах, поэтому результат `offLeft & offUp (0010 & 0100)` равен 0000.  

Рисунок *d* показывает, как эта особенность `&` может быть использована для определения того, содержатся ли какие-либо из
определенных значений eScreenLocs в составном значении. Первая строка рисунка *d* показывает, что переменной testLocs присваивается значение `offLeft | offUp (0110)`. Вторая строка показывает, что результат `testLocs & offLeft (0110
& 0010)` равен `offLeft (0010)`. В третьей строке мы видим, что результат `testLocs &
offDown (0110 & 1000)` равен нулю (0000). Поскольку testLocs не содержит
offDown, ни один из битов в обоих числах не равен 1, поэтому результат оператора `&` равен нулю.
Поскольку мы выбрали 0 для значения onScreen, любое значение offScreen &
onScreen будет равно 0000 (т.е. onScreen).  

Следующий код демонстрирует те же принципы. (Примечание: приведенный ниже код не является листингом и не должен добавляться в ваши скрипты):

```c#
// This is just an example; PLEASE DO NOT ADD IT TO ANY SCRIPTS!
[System.Flags]
public enum eScreenLocs {
    onScreen = 0, // 0000 in binary (zero)
    offRight = 1, // 0001 in binary
    offLeft = 2, // 0010 in binary
    offUp = 4, // 0100 in binary
    offDown = 8 // 1000 in binary
}
void TestScreenLocs() {
    eScreenLocs testLocs;
    // Set testLocs to offLeft, which is 2 (or 0010 in binary)

    testLocs = eScreenLocs.offLeft; // 2 or 0010 in binary
    // Use |, the bitwise OR, to add offUp: (0010 | 0100) is 0110
    testLocs = testLocs | eScreenLocs.offUp; // 5 or 0101
    eScreenLocs result;
    // Use & to see if offLeft is part of testLocs: (0110 & 0010) is 0010
    result = testLocs & eScreenLocs.offLeft; // result of the & is offLeft
    // Use & to see if offDown is part of testLocs: (0110 & 1000) is 0000
    result = testLocs & eScreenLocs.offUp; // result of the & is zero
    // == is often used with & to check whether a value is contained
    eScreenLocs checkLoc = eScreenLocs.offLeft;
    if ( (testLocs & checkLoc ) == checkLoc ) { // (0110 & 0010) == 0010
        print( "This will print because testLocs contains offLeft.");
    }
    checkLoc = eScreenLocs.offDown;
    if ( ( testLocs & checkLoc ) == checkLoc ) { // (0110 & 1000) == 1000
        print( "This will NOT print; testLocs doesn’t contain offDown." );
    }
}
```

Операторы `&` и `==` также используются совместно в методе `LocIs()` из листинга 31.10.
В этом листинге метод `LocIs()` применяет `&` в сочетании с `==` для быстрой проверки того,
содержит ли переменная `screenLocs` заданное значение `checkLoc` (типа `eScreenLocs`). Если
выражение `(screenLocs & checkLoc) == checkLoc` истинно, это означает, что `checkLoc`
содержится в `screenLocs`, и метод возвращает `true`. Если же результат
`screenLoc & checkLoc` не равен `checkLoc`, метод возвращает `false`.
</Callout>

Для проверки границ (BoundsCheck) мы создадим перечисление `eScreenLocs`, отслеживающее, находится ли игрок в пределах экрана или за его пределами. Начнем с определения этого перечисления и создания публичного поля `screenLocs`.

    - a. Для перечислений с атрибутом [System.Flags] следует явно задавать значение каждого элемента. В данном случае: onScreen=0 (ноль), offRight=1, offLeft=2, offUp=4, offDown=8. Двоичное представление каждого из этих чисел приведено в комментарии рядом с соответствующим элементом. 5. Сохраните скрипт BoundsCheck и вернитесь в Unity.  

Если выбрать экземпляр Enemy_0 в окне Hierarchy, то в окне Inspector можно увидеть, что для параметра screenLocs предусмотрено выпадающее меню, аналогичное меню Culling Mask у объекта _MainCamera. Однако, в отличие от опции «Nothing» в Culling Mask, в меню screenLocs отображается вариант «On Screen». Это объясняется тем, что значение eScreenLocs.onScreen равно 0 (нулю); оно является взаимоисключающим по отношению к остальным значениям, что означает отсутствие выбора каких-либо других опций. Например, игровой объект может одновременно находиться в состояниях offLeft и offUp, но не может одновременно находиться в состояниях onScreen и offRight.  

Теперь мы наконец задействуем этот перечислимый тип (enum). Попутно мы выполним рефакторинг: превратим поле `isOnScreen` в свойство, которое будет обращаться к `screenLocs`. Рефакторинг - это распространенная практика в разработке программного обеспечения, подразумевающая переработку и улучшение уже написанного кода. Уверяю вас: я неоднократно перерабатывал код для этой книги, чтобы сделать его максимально читабельным и понятным, - ведь в черновом варианте он выглядит далеко не так изящно.  

6. Измените скрипт BoundsCheck, добавив код. Обязательно закомментируйте или удалите все семь строк, отмеченных комментарием `// a`.  

    Листинг BoundsCheck.cs

```c#
public class BoundsCheck : MonoBehaviour {
    …
    [Header("Dynamic")]
    public eScreenLocs screenLocs = eScreenLocs.onScreen;
    // public bool isOnScreen = true;
    // a
    public float camWidth;
    …

    void Awake() { … }

    void LateUpdate () {
        …
        Vector3 pos = transform.position;
        screenLocs = eScreenLocs.onScreen;
        // b
        // isOnScreen = true;
        // a

        if ( pos.x > camWidth + checkRadius ) {
            pos.x = camWidth + checkRadius;
            screenLocs |= eScreenLocs.offRight; // c
            // isOnScreen = false; // a
        }
        if ( pos.x < -camWidth - checkRadius ) {
            pos.x = -camWidth - checkRadius;
            screenLocs |= eScreenLocs.offLeft; // c
            // isOnScreen = false; // a
        }

        if ( pos.y > camHeight + checkRadius ) {
            pos.y = camHeight + checkRadius;
            screenLocs |= eScreenLocs.offUp; // c
            // isOnScreen = false; // a
        }
            if ( pos.y < -camHeight - checkRadius ) {
            pos.y = -camHeight - checkRadius;
            screenLocs |= eScreenLocs.offDown; // c
            // isOnScreen = false; // a
        }

        if ( keepOnScreen && !isOnScreen ) { // d
            transform.position = pos;
            screenLocs = eScreenLocs.onScreen;
            // isOnScreen = true; // a
        }
    }

    public bool isOnScreen { // e
        get { return ( screenLocs == eScreenLocs.onScreen ); }
    }
}
```

    - a. Обязательно закомментируйте все семь старых строк, содержащих `isOnScreen`.
    - b. В начале каждого метода `LateUpdate()` мы устанавливаем `screenLocs` в значение `eScreenLocs.onScreen`. Это заменяет старую строку, которая присваивала `isOnScreen` значение `true`.
    - c. Теперь мы заменили каждое вхождение `isOnScreen = false;` строкой вида `screenLocs |= eScreenLocs.offRight;`. Подробнее о том, как оператор `|=` взаимодействует с перечислениями-флагами (flags enums), можно узнать во врезке «Использование побитовых операторов с перечислениями `System.Flags`».
    - d. Благодаря новому свойству `isOnScreen`, добавленному в конце этого листинга (в строке с комментарием `// e`), данную строку кода менять не нужно.
    - e. Новое свойство `isOnScreen` не только позволяет оставить строку `// d` без изменений, но и обеспечивает обратную совместимость с полем `isOnScreen`, которое мы удалили. При создании подобных классов, предназначенных для повторного использования, важно учитывать обратную совместимость, чтобы не нарушить работу других классов, зависящих от того класса, который вы рефакторите. Если бы этого свойства не было, не только возникла бы ошибка в строке `// d`, но и файл `Enemy.cs` перестал бы компилироваться, так как в строке `// d` листинга 31.7 используется `bndCheck.isOnScreen`.

8. Добавьте метод `LocIs()`, как показано в листинге кода, в конец класса BoundsCheck.  
    Листинг кода BoundsCheck.cs

```c#
public class BoundsCheck : MonoBehaviour {
    …

    public bool isOnScreen { … }

    public bool LocIs( eScreenLocs checkLoc ) {
        if ( checkLoc == eScreenLocs.onScreen ) return isOnScreen; // a
        return ( (screenLocs & checkLoc) == checkLoc ); // b
    }
}
```

    - a. Результатом побитового ИЛИ (`|`) любого значения с нулем всегда будет ноль (так же, как произведение любого числа на ноль равно нулю). Поскольку значение `eScreenLocs.onScreen` равно нулю, требуется особый подход для обработки случая, когда `checkLoc` совпадает с `eScreenLocs.onScreen`. К счастью, мы уже реализовали свойство `isOnScreen`, которое выполняет именно эту задачу.
    - b. Если результат побитового И (`&`) для `screenLocs` и `checkLoc` совпадает со значением `checkLoc`, это означает, что `checkLoc` входит в состав `screenLocs`, и функция возвращает `true`. Если `checkLoc` не содержится в `screenLocs`, возвращается `false`. Этот механизм работает и для составных значений `checkLoc` (например, если `checkLoc` равно `0110` (комбинация `offLeft | offUp`), то `LocIs()` вернет `true` только в том случае, если `screenLocs` также равно `0110`).
