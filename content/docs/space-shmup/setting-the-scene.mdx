1. Откройте сцену *__Scene_0*.
2. Удалите оставшуюся папку *Scenes* и находящуюся в ней по умолчанию сцену *SampleScene*.
3. Выберите *Directional Light* в иерархии и убедитесь, что его трансформация
выглядит так:  
P:[ 20, 20, 0 ] R:[ 50, -30, 0 ] S:[ 1, 1, 1 ]  

4. Еще раз проверьте трансформацию *_MainCamera*:  
P:[ 0, 0, -10 ] R:[ 0, 0, 0 ] S:[ 1, 1, 1 ]
5. В компоненте «Камера» класса *_MainCamera* установите следующие параметры, выделенные на
рисунке:
    - *Clear Flags* - Solid Color
    - *Background* - черный с альфа-каналом 255 (альфа — это параметр A для цвета, определяющий
прозрачность; альфа-канал 225 — полностью непрозрачный и устанавливает полосу под
образцом цвета в белый цвет)
    - *Projection* - Orthographic
    - *Size* - 40 (после установки *Projection*)
    - *Far Clipping Plane* - 100  

6. Сохраните сцену.
7. Поскольку эта игра будет вертикальным шутером с видом сверху, вам нужно установить
соотношение сторон для панели «Игра» в портретной ориентации (т. е. высота больше ширины).
    - a. На панели Game щелкните всплывающее меню со списком соотношений сторон, в котором,
вероятно, в данный момент отображается либо Full HD (1920 x 1080), либо Free Aspect (см. рис.).

<img src="/unity_doc/images/ex83.jpeg" alt="1" style={{  height: 'auto' }} />
Добавление новой предустановки соотношения сторон в панель Game  

    - b. Внизу списка находится символ «+». Щелкните его, чтобы добавить новую предустановку
соотношения сторон.
    - c. Установите значения, показанные на рисунке, а затем нажмите «Добавить».
    - d. Установите для панели Game это новое соотношение сторон 3 : 4 Portrait (768 x 1024).  

Макеты, которые можно выбрать в правом верхнем углу окна Unity (например, макет IGDPD,
который мы используем в этой книге), включают настройку разрешения панели «Игра», поэтому
каждый раз, когда вы меняете макет в этом проекте, вам также нужно будет вернуть соотношение
сторон панели «Игра» к значению 3 : 4 (вертикальная ориентация) (768 x 1024).  

Если вы хотите создать сборку WebGL для этого проекта, вам также нужно будет установить
разрешение сборки WebGL.

### Setting Up a WebGL Build [!toc]
По умолчанию проекты Unity настроены на создание исполняемого файла для той же платформы, на которой запущена сама среда Unity (например, в Windows Unity по умолчанию создает приложение для Windows). Однако, если вы хотите поделиться своим проектом с другими людьми, лучше всего выполнить сборку в формате WebGL.  

Чтобы переключить Unity на сборку для WebGL и добавить сцену `__Scene_0` в список сборки, выполните следующие действия (как показано на рисунке):  

>Сборки WebGL не только кроссплатформенны, но и имеют значительно меньший размер по сравнению с другими типами сборок, поэтому именно их я всегда прошу сдавать своих студентов. Преподавателям, читающим этот текст: я обычно требую от студентов сдавать проект в виде сборки WebGL, в которую я могу поиграть. Кроме того, я прошу их добавить меня в качестве менеджера в их организацию Plastic SCM, чтобы я мог видеть все их коммиты в проектах.  

1. В главном меню Unity выберите **File > Build Settings…** (Файл > Настройки сборки…). Откроется окно **Build Settings**, в котором будет видно, что в список сборки не добавлено ни одной сцены. (Если в списке уже есть сцены, которые вам не нужны, щелкните правой кнопкой мыши по каждой из них и выберите **Remove Selection** (Удалить выбранное).)
2. Нажмите кнопку **Add Open Scenes** (Добавить открытые сцены), чтобы добавить сцену `__Scene_0`, которая открыта в данный момент. Она появится в списке с установленным флажком и номером 0 рядом с ней (указывающим, что это начальная сцена, которая будет загружаться первой), как показано на рисунке.

<img src="/unity_doc/images/ex84.jpg" alt="1" style={{  height: 'auto' }} />

3. В списке платформ выберите WebGL.
4. Нажмите кнопку Switch Platform.  

Смена платформы займет некоторое время, но лучше сделать это сейчас, чем потом. Со временем этот процесс ускорился, однако при работе над крупным проектом для iOS и Android в 2014 году переключение между платформами каждый раз занимало больше часа!  

>Значительные затраты времени при переключении между платформами обусловлены тем, что для каждой из них Unity требует особой подготовки ассетов. Одно из ключевых преимуществ Unity Cloud Build заключается в том, что сервис кэширует ассеты для всех выбранных целевых платформ, позволяя избежать задержек, характерных для локальной сборки при смене платформы.  

5. Нажмите кнопку «Настройки проигрывателя…», чтобы открыть раздел «Настройки проигрывателя» в окне «Настройки проекта».

6. В панели «Настройки проигрывателя» окна «Настройки проекта» установите для параметра «Название компании» любое желаемое значение. Обратите внимание, что для параметра «Название продукта» автоматически устанавливается имя папки проекта, которое вы указали ранее в этом приложении (шаг 4b раздела «Настройка нового проекта»). Здесь же можно установить номер версии, который становится особенно важным, если вы хотите отправить приложение в магазин, например, Apple App Store (но в контексте этой книги это не имеет значения).

7. Откройте треугольник раскрытия рядом с пунктами «Разрешение» и «Представление» и установите следующие параметры:  

>Обратите внимание, что для проекта Space SHMUP значения ширины и высоты будут другими, однако эти настройки подходят для любого проекта, в котором для панели Game установлено разрешение Full HD (1920x1080).  

    - a. Ширина холста по умолчанию: 1280
    - b. Высота холста по умолчанию: 720
    - c. Запуск в фоновом режиме: false (не отмечено)

Для области игры установлено разрешение Full HD (1920x1080), однако для многих мониторов такой размер слишком велик для размещения на веб-странице. Разрешение 1280x720 имеет то же соотношение сторон, что и 1920x1080, но при этом достаточно компактно, чтобы поместиться на веб-странице на большинстве мониторов; именно такое разрешение используется в телевизорах стандарта 720p.  

Мы отключаем параметр «Run in Background» (работа в фоновом режиме), чтобы сборка игры на базе WebGL не продолжала выполняться, когда веб-страница с ней не является активным окном на компьютере игрока. Если бы этот параметр был включен, игра продолжала бы работать, даже если бы окно веб-браузера было скрыто из виду!  

В окне настроек Unity Player (Player Settings) рядом с этими тремя параметрами стоит звездочка (*). Она указывает на то, что данный параметр является общим для нескольких платформ. Однако параметр «Run in Background» не только является общим для разных платформ сборки: он также определяет, будет ли Unity Editor приостанавливать режим воспроизведения (Play Mode), когда само приложение Unity переходит в фоновый режим. Я всегда рекомендую отключать «Run in Background». В противном случае можно случайно оставить игру запущенной в Unity, переключившись на другое окно, и она будет без необходимости потреблять значительные ресурсы компьютера.  

8. Откройте треугольник раскрытия рядом с пунктом «Настройки публикации» и установите параметр «Формат сжатия» в значение «Отключено». (Это выделено жирным шрифтом, потому что многие мои студенты этого не замечают.)  

По умолчанию используется формат сжатия Gzip, однако для его работы веб-серверы должны быть соответствующим образом настроены, а многие из них такой настройки не имеют. Кроме того, если вы пытаетесь запустить сборку WebGL локально на своем компьютере (а не онлайн через веб-сервер), сжатие Gzip в локальных сборках работать не будет.  

9. Закройте окна Project Settings и Build Settings.  

Если вы используете систему контроля версий Plastic SCM (о которой я расскажу чуть позже в этом приложении), учтите, что ни одна из этих настроек сборки не сохраняется в системе контроля версий Unity. Поэтому, если ситуация не изменится в будущем, вам придется вручную задавать параметры Build Settings и Player Settings на компьютере каждого члена вашей команды.
