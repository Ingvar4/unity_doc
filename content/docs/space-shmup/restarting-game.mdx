title: Перезапуск игры
description: По результатам тестирования видно, что игра становится невероятно скучной после того, как герой уничтожен.
---

Теперь вы измените классы Hero и Main так, чтобы при уничтожении объекта Hero вызывался метод, который ждет 2 секунды, а затем перезапускает игру.  

1. Добавьте в скрипт Main поля и методы:  
    Листинг кода Main.cs

```c#
public class Main : MonoBehaviour {
    …
    [Header("Inscribed")]
    public GameObject[] prefabEnemies; // Array of Enemy prefabs
    public float enemySpawnPerSecond = 0.5f; // # Enemies spawned/second
    public float enemyInsetDefault = 1.5f; // Inset from the sides
    public float gameRestartDelay = 2; // a
    …

    public void SpawnEnemy() { … }

    void DelayedRestart() { // c
        // Invoke the Restart() method in gameRestartDelay seconds
        Invoke( nameof(Restart), gameRestartDelay );
    }

    void Restart() {
        // Reload __Scene_0 to restart the game
        // "__Scene_0" below starts with 2 underscores and ends with a zero.
        SceneManager.LoadScene( "__Scene_0" ); // d
    }

    static public void HERO_DIED() {
        S.DelayedRestart(); // b
    }
}
```

    - a. Обязательно добавьте поле `gameRestartDelay` в начало класса.
    - b. Любой другой класс может вызвать этот статический публичный метод `HERO_DIED()` через `Main.HERO_DIED()`. В свою очередь, `HERO_DIED()` вызовет `DelayedRestart()` у приватного синглтона `S` класса `Main`.
    - c. Метод `DelayedRestart()` вызывает `Restart()` через две секунды.
    - d. Метод `Restart()` перезагружает сцену `__Scene_0`. К сожалению, не существует гораздо более удачного способа сослаться на сцену, чем по ее имени, поэтому необходимо убедиться, что строка `__Scene_0` написана правильно - как здесь, так и в фактическом названии сцены.

Хотя именно гибель героя инициирует перезагрузку сцены, я решил разместить весь код, отвечающий за управление сценой и её загрузку, в классе `Main`, а не в `Hero`, чтобы сосредоточить всё в одном месте. Как мы уже обсуждали, это соответствует духу паттерна проектирования «Компонент» (Component Pattern), согласно которому каждый скрипт должен отвечать лишь за одну задачу: `Hero.cs` управляет всем, что связано с героем, а `Main.cs` - сценой и появлением врагов.  

2. Теперь добавьте вызов `Main.HERO_DIED()` в скрипт `Hero`.  
    Листинг кода Hero.cs

```c#
public class Hero : MonoBehaviour {
    …

    public float shieldLevel {
        get { return ( _shieldLevel ); }
        private set {
            _shieldLevel = Mathf.Min( value, 4 );
            // If the shield is going to be set to less than zero…
            if (value < 0) {
                Destroy(this.gameObject); // Destroy the Hero
                Main.HERO_DIED();
            }
        }
    }
}
```

Попробуйте запустить игру и получить столько урона, чтобы персонаж погиб. Через две секунды сцена должна перезагрузиться… или же может возникнуть следующая ошибка (хотя в Unity 2020.3 это обычно не происходит):

>Scene ’__Scene_0’ couldn’t be loaded because it has not
been added to the build settings or the AssetBundle has
not been loaded.  

Если вы столкнулись с этой ситуацией, это означает, что сцена `__Scene_0` не была добавлена ​​в настройки сборки (Build Settings).
Даже если вы не выполняете сборку проекта, Unity определяет, какие сцены могут быть загружены,
исходя из списка сцен, добавленных в окне Build Settings.  

3. Добавьте __Scene_0 в настройки сборки (Build Settings):
    - a. В меню Unity выберите *File > Build Settings…*
    - b. Если в окне Build Settings вы не видите __Scene_0 в верхней части списка, нажмите кнопку
Add Open Scenes.
    - c. Закройте окно Build Settings.
4. Сохраните сцену!  

Теперь, после того как корабль игрока уничтожен, игра выжидает пару секунд, а затем перезапускается, перезагружая сцену.

<Callout>
### Совет [!toc]
Если после перезагрузки сцены освещение выглядит странно (например, ваш корабль и корабли противника кажутся немного темнее), возможно, вы столкнулись с известной проблемой системы освещения Unity (о которой я также упоминал в главе 28). Чтобы исправить это, нужно выполнить запекание освещения (build lighting), а затем отключить функцию автоматического построения света. Выполните следующие действия для решения этой проблемы в данном проекте:
1. В строке меню выберите *Window > Rendering > Lighting*.
2. Нажмите кнопку Scene в верхней части окна Lighting.
3. Если установлен флажок Auto Generate в нижней части окна Lighting (рядом с кнопкой Generate Lighting), снимите его. Это предотвратит постоянный пересчет настроек глобального освещения со стороны Unity.
4. Чтобы убедиться, что освещение построено корректно, нажмите кнопку Generate Lighting в нижней части окна Lighting для ручного расчета глобального освещения.
5. После завершения процесса Generate Lighting нажмите кнопку Play для проверки; освещение должно оставаться неизменным даже после перезагрузки сцены.
Разумеется, если вы внесете какие-либо изменения в настройки освещения, его придется перестраивать вручную. Эта ошибка проявляется только в редакторе и не влияет на итоговую сборку проекта.
</Callout>
