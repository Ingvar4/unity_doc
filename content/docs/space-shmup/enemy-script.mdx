---
title: The Enemy C# Script
description: Чтобы создать скрипт Enemy, выполните следующие действия
---

1. Создайте новый скрипт C# с именем *Enemy* и поместите его в папку *__Scripts*.
2. Прикрепите скрипт *Enemy* к префабу *Enemy_0*:
    - a. Выберите *Enemy_0* на панели Project (а не в Hierarchy).
    - b. В окне Inspector для объекта *Enemy_0* нажмите кнопку Add Component и выберите *Scripts >
Enemy* во всплывающем меню. После этого, если вы выберете *Enemy_0* на панели Project или Hierarchy,
вы увидите, что к объекту прикреплен компонент Enemy (Script).  

>Иногда в Unity 2020 прикрепить новый скрипт описанным способом не удается. Понять, что это произойдет, можно по появлению индикатора выполнения сразу после создания скрипта: в результате для переименования файла приходится выбирать его заново. Если в такой ситуации открыть скрипт, окажется, что имя класса в нем - `public class NewBehaviourScript`, а не то новое имя, которое вы задали. Чтобы решить эту проблему, просто исправьте имя класса в самом скрипте (например, замените `NewBehaviourScript` на `Enemy`, как показано в пятой строке листинга кода 31.4), после чего вы сможете прикрепить скрипт (как описано в шаге 2b этого раздела).  

3. Откройте скрипт *Enemy* в Visual Studio и введите код:  

```c#
using System.Collections; // Required for some Arrays manipulation
using System.Collections.Generic; // Required for Lists and Dictionaries
using UnityEngine; // Required for Unity

public class Enemy : MonoBehaviour {
    [Header("Inscribed")]
    public float speed = 10f; // The movement speed is 10m/s
    public float fireRate = 0.3f; // Seconds/shot (Unused)
    public float health = 10; // Damage needed to destroy this enemy
    public int score = 100; // Points earned for destroying this

    // This is a Property: A method that acts like a field
    public Vector3 pos { // a
        get {
            return this.transform.position;
        }
        set {
            this.transform.position = value;
        }
    }

    void Update() {
        Move(); // b
    }

    public virtual void Move() { // c
        Vector3 tempPos = pos;
        tempPos.y -= speed * Time.deltaTime;
        pos = tempPos;
    }

    // void Start() {…} // Please delete the unused Start() method
}
```

    - a. Как уже говорилось в главе «Классы», свойство - это функция, маскирующаяся под поле. Это означает, что вы можете получать и устанавливать значение `pos` так, словно это переменная класса `Enemy`.
    - b. Не забудьте добавить в метод `Update()` строку, вызывающую `Move()`.
    - c. Метод `Move()` получает текущую позицию данного `GameObject`, перемещает его вниз по оси Y и присваивает новое значение свойству `pos` (тем самым устанавливая позицию `GameObject`).  

4. Сохраните скрипт, вернитесь в Unity и нажмите Play.  

Экземпляр Enemy_0 в сцене должен перемещаться к нижней части экрана.
Однако с текущим кодом этот экземпляр будет продолжать существовать за пределами экрана, пока вы не остановите игру. Вам нужно, чтобы враг уничтожил себя после того, как полностью переместится за пределы экрана.
Это отличное место для повторного использования компонента BoundsCheck. (Он также будет проходить через Hero, но мы исправим это позже.)  

5. Чтобы прикрепить скрипт BoundsCheck к префабу Enemy_0:
    - a. Выберите префаб Enemy_0 в окне Hierarchy (в этот раз не в окне Project).
    - b. В окне Inspector нажмите кнопку Add Component и выберите *Add Component > Scripts > BoundsCheck*.  

Это действие прикрепляет скрипт к экземпляру Enemy_0 в окне Hierarchy, но пока не прикрепляет его к префабу Enemy_0 в окне Project.  

6. Чтобы применить изменения, внесенные в экземпляр Enemy_0, к соответствующему префабу:
    - a. Нажмите кнопку Overrides (Переопределения) в верхней части окна Inspector для экземпляра Enemy_0, выбранного в окне Hierarchy. Появится всплывающее окно, показывающее, что скрипт BoundsCheck является переопределением - то есть элементом, который в данном экземпляре отличается от префаба. Знак «плюс» на значке скрипта указывает на то, что этот скрипт был добавлен именно в данный экземпляр.
    - b. Нажмите кнопку Apply All (Применить все), чтобы применить это (и все остальные) переопределение к префабу.
    - c. Выберите префаб Enemy_0 в папке _Prefabs окна Project, чтобы убедиться, что скрипт BoundsCheck теперь также прикреплен к префабу.  
7. Выберите экземпляр Enemy_0 в окне Hierarchy (опять же, не в окне Project):
    - a. Установите для параметра boundsType в компоненте BoundsCheck (в окне Inspector) значение outset.
    - b. Установите значение radius в компоненте BoundsCheck (в окне Inspector) равным 2.
Обратите внимание: эти два значения в окне Inspector для данного экземпляра Enemy_0 выделены жирным шрифтом,
поскольку они отличаются от значений, заданных в префабе.
    - c. Снова нажмите кнопку Overrides в верхней части окна Inspector; вы увидите уведомление о том,
что настройки скрипта BoundsCheck отличаются от настроек префаба (хотя
на значке скрипта в этот раз нет знака «плюс», что указывает на то, что BoundsCheck является
компонентом как префаба, так и экземпляра, но одно из значений BoundsCheck
в окне Inspector для экземпляра в иерархии отличается от исходного).
    - d. Нажмите на BoundsCheck (Script) в появившемся меню, чтобы просмотреть подробности. Здесь четко видно,
что различие заключается именно в значении radius.
    - e. В этом окне с подробной информацией нажмите кнопку Apply, а затем выберите в меню пункт Apply to Prefab ’Enemy_0’.

Теперь во всплывающем меню Overrides отображается статус «No Overrides», а значения `boundsType` и `radius` в компоненте BoundsCheck экземпляра `Enemy_0` (в иерархии сцены) больше не выделяются жирным шрифтом - это указывает на то, что они совпадают со значениями в исходном префабе.  

8. Нажмите кнопку Play, и вы увидите, что экземпляр Enemy_0 останавливается сразу после того, как покидает пределы экрана. Однако вместо того чтобы принудительно удерживать Enemy_0 рядом с границей экрана, лучше проверять, вышел ли он за его пределы, и уничтожать его в этом случае.  

Чтобы наглядно видеть, когда игровые объекты (GameObjects) выходят за пределы экрана, можно нажать кнопку **2D** в верхней части окна **Scene** и немного уменьшить масштаб. Границы ортографической камеры отображаются в окне **Scene** в виде светло-серого прямоугольника.  

9. Чтобы получить возможность либо разрешить объекту Enemy_0 выходить за пределы экрана, либо ограничить его перемещение границами экрана, откройте скрипт BoundsCheck в Visual Studio и внесите изменения.  

    **BoundsCheck.cs**

```c#
/// <summary>
/// Checks whether a GameObject is on screen and can force it to stay on screen.
/// Note that this ONLY works for an orthographic Main Camera.
/// </summary>
public class BoundsCheck : MonoBehaviour {
    …
    [Header("Inscribed")]
    public eType boundsType = eType.center;
    public float radius = 1f;
    public bool keepOnScreen = true; // a

    [Header("Dynamic")]
    public bool isOnScreen = true; // b
    public float camWidth;
    public float camHeight;

    void Awake() { … } // Remember, { … } means to NOT alter this method. // c

    void LateUpdate () {
        …
        Vector3 pos = transform.position;
        isOnScreen = true; // d

        if ( pos.x > camWidth + checkRadius ) {
            pos.x = camWidth + checkRadius;
            isOnScreen = false; // e
        }
        if ( pos.x < -camWidth - checkRadius ) {
            pos.x = -camWidth - checkRadius;
            isOnScreen = false; // e
        }

        if ( pos.y > camHeight + checkRadius ) {
            pos.y = camHeight + checkRadius;
            isOnScreen = false; // e
        }
        if ( pos.y < -camHeight - checkRadius ) {
            pos.y = -camHeight - checkRadius;
            isOnScreen = false; // e
        }

        if ( keepOnScreen && !isOnScreen ) { // f
            transform.position = pos; // g
            isOnScreen = true;
        }
    }
}
``` 

    - a. Если параметр `keepOnScreen` имеет значение `true`, компонент `BoundsCheck` принудительно удерживает игровой объект в пределах экрана. Если `keepOnScreen` равен `false`, `BoundsCheck` позволяет игровому объекту выходить за границы экрана.
    - b. Переменная `isOnScreen` принимает значение `false`, если игровой объект покидает пределы экрана. Точнее говоря, при типе границ `outset` значение `isOnScreen` становится `false`, если игровой объект выходит за край экрана на расстояние, превышающее радиус.
    - c. Многоточие (…) в примерах кода означает, что метод `Awake()` изменять не следует.
    - d. Переменной `isOnScreen` изначально присваивается значение `true`, пока не будет доказано обратное. Это позволяет `isOnScreen` снова стать `true`, если в предыдущем кадре объект находился за пределами экрана, а в текущем - вернулся в его границы.
    - e. Если условие в любой из этих четырех инструкций `if` выполняется, значит, игровой объект вышел за пределы допустимой зоны. В результате `isOnScreen` устанавливается в `false`, а переменная `pos` корректируется так, чтобы вернуть объект в границы экрана.
    - f. Если `keepOnScreen` равен `true`, это означает, что вы пытаетесь удержать игровой объект в пределах экрана. Если `keepOnScreen` равен `true`, а `isOnScreen` - `false`, значит, объект вышел за границы и его необходимо вернуть обратно. В этом случае `transform.position` присваивается обновленное значение `pos` (находящееся в пределах экрана), а `isOnScreen` устанавливается в `true`, так как в результате присвоения новой позиции объект вернулся на экран.  

Если параметр keepOnScreen имеет значение false, то pos не присваивается обратно свойству transform.position, объекту GameObject разрешается выйти за пределы экрана, а переменная isOnScreen может оставаться равной false. Возможен и другой вариант: объект GameObject всё время находился в пределах экрана; в этом случае isOnScreen сохраняет значение true, установленное ранее в строке `// d`.
    - g. Обратите внимание, что эта строка теперь имеет отступ и находится внутри оператора `if` из строки `// f`.  

К счастью, все эти изменения в коде никак не сказываются на его использовании для _Hero, и там всё по-прежнему работает исправно. Вы создали компонент, пригодный для повторного использования: его можно применять как к _Hero, так и к игровым объектам Enemy без каких-либо изменений.
