title: Создание главного корабля
description: Чтобы подготовить космический корабль игрока к этой игре, выполните следующие шаги
---

1. В панели Project (Проект) раскройте папку *Assets > Assets by Peter Burroughs > Models* и выберите модель *heroShip*.  

После выбора в инспекторе откроется диалоговое окно «Настройки импорта корабля героя» —
довольно сложное окно с несколькими вкладками, предназначенное для импорта модели fbx из файла.  

>Для получения информации об этом инспекторе импорта, пожалуйста, обратитесь к документации Unity по адресу https://docs.unity3d.com/2020.3/Documentation/Manual/class-FBXImporter.html  

2. Перетащите *heroShip* из панели Project в Hierarchy.  

Это создаст экземпляр heroShip в сцене, но он не будет обращен вверх в панели Game, как нам
нужно. Художники обычно предоставляют вам такие ресурсы, которые направлены в сторону
положительной оси Z, и это хорошо, поскольку соответствует именованию осей в Unity, где
положительная ось Z означает «вперед». Однако для этой игры нам нужно переориентировать корабль, и для этого я обычно
считаю лучшим вариантом поместить модель внутрь другого GameObject. Я покажу вам, что я имею в
виду.  

3. Создайте пустой объект GameObject и назовите его *_Hero* (*GameObject >Create Empty*). Если
это еще не сделано, сбросьте его трансформацию на P:[ 0, 0, 0 ] R:[ 0, 0, 0 ] S:[ 1, 1, 1 ].
4. Сделайте *heroShip* дочерним объектом *_Hero*, перетащив *heroShip* на *_Hero* в панели Hierarchy.
5. Выберите дочерний объект *heroShip* объекта *_Hero* и установите его трансформацию на   
P:[ 0, 0, 0 ] R:[ - 90, 0, 0 ] S:[ 0.01, 0.01, 0.01 ].  

Это поворачивает модель *heroShip* так, чтобы она была правильно ориентирована для нашей игры.
Вы, вероятно, заметили масштаб 0,01 в трансформации *heroShip*. Это связано с тем, что основной
единицей измерения во многих программах моделирования являются сантиметры, тогда как в Unity
— метры. Поэтому нам нужно уменьшить размер модели *heroShip* в 100 раз (т. е. масштаб 0,01),
чтобы она стала нужного нам размера. Теперь модель ориентирована правильно, и пришло время
добавить дополнительные компоненты в окружающий GameObject *_Hero*.  

6. Выберите _Hero в иерархии.
    - a. Нажмите кнопку «Add Component» в панели «Inspector».
    - b. Выберите New Script в всплывающем меню (оно находится внизу).
    - c. Назовите скрипт *Hero* и нажмите *Create and Add*. (Это один из многих способов создать
новый скрипт и прикрепить его к GameObject.)
    - d. В панели Project переместите скрипт *Hero* в папку *__Scripts* (если ее нет, создайте папку
*__Scripts*; в начале имени должно быть два подчеркивания).  

7. Добавьте компонент Rigidbody к _Hero, выбрав _Hero в иерархии, а затем выбрав *Add Component > Physics > Rigidbody* с помощью кнопки «Добавить компонент»
в инспекторе. Вы также можете ввести «rig» в строку поиска в верхней части всплывающего
меню «Добавить компонент», чтобы найти компонент Rigidbody (убедитесь, что вы не выбрали
Rigidbody 2D).  

8. Установите следующие настройки для компонента Rigidbody объекта _Hero:
    - a. *Use Gravity* — false (не отмечено)
    - b. *isKinematic* — true (отмечено)
    - c. *Constraints: Freeze Position* по оси Z и *Freeze Rotation* по осям X, Y и Z (установив флажки). (Чтобы увидеть эти настройки, вам нужно раскрыть треугольник рядом c «Constraints»).  

9. Сохраните сцену! Помните, что вы должны сохранять сцену каждый раз, когда вносите в нее
изменения. Позже я проведу тест.  

На следующих страницах вы добавите в _Hero еще кое-что, но пока этого будет достаточно.

### The Hero Update() Method [!toc]

В листинге кода метод `Update()` сначала считывает горизонтальную и вертикальную оси из
Input Manager (см. панель «Оси ввода и Input Manager»), помещая значения от –1 до 1 в
переменные типа float hAxis и vAxis. Второй фрагмент кода `Update()` перемещает корабль с
учетом времени, принимая во внимание настройку скорости.  

Последняя строка (отмеченная `// c`) поворачивает корабль на основе ввода. Хотя ранее вы
зафиксировали вращение в компоненте Rigidbody объекта *_Hero*, вы все равно можете вручную
задать вращение на Rigidbody, установив *isKinematic* в `true`. (Как обсуждалось в одной из
предыдущих глав, если isKinematic равно true, Rigidbody будет отслеживаться системой физики, но
не будет двигаться автоматически за счет Rigidbody.velocity.) Это вращение делает движение корабля более динамичным и выразительным, или «сочным».  

1. Откройте скрипт Hero C# в Visual Studio и введите код из листинга:  

**Листинг кода Hero.cs**  

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class Hero : MonoBehaviour {
    static public Hero S { get; private set; } // Singleton property // a

    [Header("Inscribed")]
    // These fields control the movement of the ship
    public float speed = 30;
    public float rollMult = -45;
    public float pitchMult = 30;

    [Header("Dynamic")] [Range(0,4)] // b
    public float shieldLevel = 1;

    void Awake() {
        if (S == null) {
            S = this; // Set the Singleton only if it’s null // c
        } else {
            Debug.LogError("Hero.Awake() - Attempted to assign second Hero.S!");
        }
    }

    void Update () {
        // Pull in information from the Input class
        float hAxis = Input.GetAxis("Horizontal"); // d
        float vAxis = Input.GetAxis("Vertical"); // d

        // Change transform.position based on the axes
        Vector3 pos = transform.position;
        pos.x += hAxis * speed * Time.deltaTime;
        pos.y += vAxis * speed * Time.deltaTime;
        transform.position = pos;

        // Rotate the ship to make it feel more dynamic // e
        transform.rotation = Quaternion.Euler(vAxis*pitchMult,hAxis*rollMult,0);
    }

    // void Start() {…} // Please delete the unused Start() method
}
```

- a. Это реализация паттерна «Одиночка» (Singleton) для класса Hero.
Конструкция `{ get; private set; }` превращает это свойство в автоматическое (то есть такое, для которого C# сам создает поле-хранитель, избавляя нас от необходимости писать его код вручную). Поскольку для метода доступа `set` установлен модификатор `private`, мы обеспечиваем определенную защиту этого открытого свойства, разрешая изменять его значение только из кода самого класса Hero.
- b. Атрибут `[Range(0,4)]` здесь добавляет ползунок в Инспектор и не позволяет нам
использовать Инспектор для установки shieldLevel в значение меньше 0 или больше 4.
- c. Этот код в `Awake()` выдает ошибку в панели Console, если вы попытаетесь установить `Hero.S`
после того, как он уже был установлен. Это еще одна мера защиты от ошибок (например, если в
одной сцене было два GameObject, к которым были прикреплены скрипты Hero, или два
компонента Hero, прикрепленных к одному GameObject).
- d. Эти две строки используют класс Input Unity для извлечения информации из Unity
Input Manager.
- e. Строка `transform.rotation…` ниже этого комментария используется для придания
кораблю небольшого вращения в зависимости от скорости его движения, что может сделать
корабль более отзывчивым и динамичным. pitchMult и rollMult умножаются на vAxis и
hAxis (каждый из которых находится в диапазоне от [-1..1]), чтобы наклонять корабль вперед и
назад (от –30 до 30 градусов) и кренить его влево и вправо (от 45 до –45 градусов).

### Input Axes and the Input Manager [!toc]
Большая часть кода в листинге метода `Hero.Update()` должна быть вам знакома,
хотя с методом `Input.GetAxis()` вы сталкиваетесь в этой книге впервые.
Система Input Manager в Unity позволяет настраивать различные оси ввода,
значения которых можно считывать с помощью `Input.GetAxis()`. Чтобы просмотреть
оси ввода, заданные по умолчанию, выберите в строке меню пункт
*Edit > Project Settings…*, а затем — Input Manager на левой панели.
Вероятно, вам потребуется нажать на треугольник рядом с заголовком Axes,
чтобы развернуть список всех осей, как показано на рисунке.

<img src="/unity_doc/images/ex84.jpeg" alt="1" style={{  height: 'auto' }} />

Следует обратить внимание на то, что в настройках, представленных на рисунке, названия
некоторых осей указаны дважды (например, «Horizontal», «Vertical» и «Jump»). Как видно на
увеличенном изображении двух осей Horizontal на рисунке, это позволяет управлять осью
Horizontal либо с помощью нажатий на клавиатуре (принимая стрелки влево и вправо, а также A
и D, как показано на левом изображении на рисунке), либо с помощью оси джойстика
(показано на правом изображении).  

Это одно из главных преимуществ осей ввода: одной осью может управлять несколько
различных типов ввода. В результате вашим играм потребуется всего одна строка для
считывания значения оси, а не по одной строке для обработки ввода с джойстика, по одной
строке для каждой клавиши со стрелкой и по одной строке для клавиш A и D.
Каждый вызов Input.GetAxis() возвращает значение типа float в диапазоне от –1 до 1
(по умолчанию — 0). Каждая ось в диспетчере ввода также включает значения Sensitivity и
Gravity, хотя они используются только для ввода с клавиш или кнопок мыши (см. левое
изображение на рис.). Sensitivity и Gravity обеспечивают плавную интерполяцию
значения оси
при нажатии или отпускании клавиши. (То есть вместо того, чтобы сразу перейти к
конечному значению, значение оси будет плавно переходить от исходного значения к
конечному с течением времени.) На показанной горизонтальной оси чувствительность 3
означает, что при нажатии клавиши со стрелкой вправо требуется 1/3 секунды, чтобы
значение интерполировалось от 0 до 1. Сила притяжения 3 означает, что при отпускании
клавиши со стрелкой вправо требуется 1/3 секунды, чтобы значение оси интерполировалось
обратно к 0. Чем выше чувствительность или сила притяжения, тем быстрее происходит
интерполяция.  

Эффект настройки «Привязка» незаметен, но важен. Когда «Привязка» установлена в «false»
(не отмечена), если горизонтальная ось в данный момент находится в положении –1 (т. е.
полностью влево), и вы нажмете и удерживаете клавишу со стрелкой вправо, значение
плавно интерполируется обратно до 0, а затем до 1. С другой стороны, когда параметр
«Привязка» установлен в «true» (по умолчанию), если горизонтальная ось в данный момент
находится в положении –1, и вы нажмете и удерживаете клавишу со стрелкой вправо,
значение сразу перескочит к 0, а затем плавно интерполируется до 1. Это значение
установлено по умолчанию, поскольку оно делает корабль более «отзывчивым» и
реагирующим, но это может не соответствовать вашим требованиям для всех игр.  

Как и во многих других случаях в Unity, вы можете узнать гораздо больше об Input Manager,
нажав кнопку «Справка» (она выглядит как серый кружок с вопросительным знаком и
находится справа от названия Input Manager в верхней части окна «Настройки проекта»).
Начиная с 2020 года, Unity выпустила новую систему ввода в виде пакета в диспетчере
пакетов, но я решил не использовать её в этой книге. Хотя новая система ввода отлично
справляется с обработкой ввода с нескольких геймпадов на одном компьютере и
обеспечивает согласованность ввода между геймпадами разных брендов (например,
Microsoft, Sony, Nintendo), её настройка требует гораздо больше усилий и не нужна для ввода
с клавиатуры и мыши, который используется на протяжении всей этой книги.
</Callout>

Сохраните скрипт, вернитесь в Unity и попробуйте поиграть в игру, чтобы понять, как вам
управляется корабль. Вы можете перемещаться с помощью клавиш со стрелками или WASD (A:
влево, D: вправо, W: вверх, D: вниз). Настройки speed, rollMult и pitchMult подходят мне, но
это ваша игра, и вы должны выбрать настройки, которые вам удобны. Внесите необходимые
изменения в инспекторе Unity для объекта _Hero.

### Совет [!toc]
ЕСЛИ КОРАБЛЬ ГЕРОЯ НЕ ДВИГАЕТСЯ ПРИ НАЖАТИИ КНОПКИ «PLAY»  
часто требует, чтобы вы щелкнули в панели Game, прежде чем ввод с клавиатуры
начнет работать. Если вы нажмете Play, а клавиатура, похоже, не работает, просто
щелкните в панели Game, и все должно заработать.
</Callout>

Отчасти это ощущение создается за счет видимой инерции корабля. Когда вы отпускаете клавишу
движения, кораблю требуется некоторое время, чтобы замедлиться. Аналогично, при нажатии
клавиши движения кораблю требуется некоторое время, чтобы разгоняться. Эта видимая инерция
движения обусловлена настройками «Чувствительность», «Сила тяжести» и «Ось привязки»,
описанными в боковой панели.
Изменение этих настроек в «Менеджере ввода» влияет на движение и маневренность
_Hero.
