ИИшки быстро развиваються и буквально за полгода может навыходить кучу всего нового от софта до моделей, и вот в 2026 году уже можно поднять локально нейронку на бомж видюхе которая даже будет нормально кодить, собсна этим я и решил заняться...  

Немного духоты  

Зачем поднимать это локально когда есть бесплатный Дикпсих? Для тех кто не кодит нейронка в основном это чат и не более, но допустим вы захотели, чтобы Диписик написал код, вы его копируете, код выдает ошибку, вы копируете ошибку в чат, он исправляет и т.д., это превращается в бесконечный копипаст. А что если есть уже готовый проект в котором надо еще разобрать и понять как оно работает, или еще какая-то специфическая рутинная задача на комлюхтере которую вы нихотите делоть, вот для этого есть...  

Агенты это оболочки для нейросети (мозгов) которые интегрированы прямо в рабочий процесс, если чат-бомж может только гуглить и писать ответы, то у агента есть полный доступ к системе, он может писать код прямо в IDE (VS Code), отлаживать ошибки, работать с файлами прямо на компьютере, запускать команды в терминале, админить базы данных, чатитсья за вас в чатах или писать письма, попросите его прочитать все книги на компе или спарсить какой-то сайт и занести все данные в ексель табличку, написать статью на ДиТиэФ с рекламой телеги - он сможет, это вообще другой уровень работы с системой и софтом. И вишенка на торте это написание плана работы, где агент будет выполнять одну задачу за другой, в идеале без вашего участия. Пишите ему чёткий план с архитектурой проекта и он будет куралесит часами пока не сделает (или не обосреться в галлюцинациях), кароче ИМБА

https://opencode.ai/docs/ru  

**OpenCode** это открытый и бесплатный агент-оболочка для нейросетей, аналог того же Claude Code, туда можно поключать по API платные модели от разных провайдеров, есть пару БЕСПЛАТНЫХ, еще можно подключить свои локальные модели, работает на CLI (интефейс в терминале командной строки)  

Устанавливаете, заходите в VS code, окрываете терминал, пишите  

```
opencode
```

И всё, можно вайб-кодить  

Есть два режима работы 'Plan' и 'Build'  

**Plan** — режим для написания плана работ. В нем строим план работ, обсуждаем его, анализируем что имееться. В этом режиме ИИ не может редактировать файлы только читать.  

**Build** — режим выполнения плана и сборки проекта. Это режим "полного доступа". В нем ИИ может изменять файлы, запускать терминальные команды, сам код, создавать и удалять директории.  

Есть полезная команда `/init` просканирует проект и создаст файл *AGENTS.md*, зафиксировав свое понимание структуры. Там будут храниться инструкции, описание архитектуры, правила кодинга, как запускать тесты, куда смотреть в первую очередь. Символом `'@'` в промте можно ссылаться на файлы, например файл в котором нужно делать исправления, чтобы ИИ не тратил время на поиски или не трогал что не нужно.  

еще есть **'Скилы'** посути уже готовый промт (инструкция) как делать что-то  

https://www.skills.sh/  

LLM на локалке и никаких платно  

Зачем это нужно? Можно впринципе не делать этого, вкинуть котлету Антропик или Дипсику либо пользоваться простыми бесплатными моделям в том же OpenCode, но иметь в запасе локальную нейронку тоже хочеться, она бесплатна и безлимитна, не требует интернета (что актуально в российских реалиях) и никому ничего не передает, на нее можно скинуть простые задачи, чтобы например сэкономить лимитированные или дорогие токены  

### LLM модель [!toc]  

Главный показатель ума, помимо алгоритма работы, это количество параметров, обычно это пишут после названия, например Qwen3.6 35B, что значит 35 милиардов параметров.  

Серьёзные большие модели весят по сотне гигов, но сейчас стали появляться открытые маленькие модели на 4-9B, еще есть Квантизация (Cжатие) модели, то бишь уменьшение веса за счет снижения точности (ума), это позволяет запускать модели на !8Гб VRAM, и они вполне себе позволяют выполнять простые задачи и что-то кодить. Квантиазацию обозначают например как Q4, чем меньше цифра тем ИИ тупее, считаеться, что Q4 золотая середина, в Q8 мало выйгрыша в весе, а Q2 заметно тупее. Есть еще динамический квант UD-Q4 от unsloth, он вроде как умнее чем стандартный Q4  

Найти сжатые и открытые модели можно на huggingface.co  

https://huggingface.co/unsloth/Qwen3.5-4B-GGUF 

Я на своей бомж видеокарте 8 гб запускаю  

Он конечно тупой в кодинге, но для чат ботов или простых операций можно использовать, можно полностью выгрузить VRAM и получить хорошую скорость  

Второй вариант потяжелее и помедленнее, но уже может нормально кодить  

https://huggingface.co/unsloth/Qwen3.5-9B-GGUF  

Нейросеть оперирует Токенами, это слова которые ИИ обрабатывает, а количество токенов которые ИИ помнить казываеться Контекстом, от длины контекста зависит длина диалога который она помнит, код который она прочитала или написала, т.е. если к концу прочитанной книги контекст переполнится и начнет затираться новыми словами, ИИ забудет название и начало книги которую она читает и по сути весь смысл потеряет. Токены под контекст также выгружаються в память, поэтому важен его размер и скорость памяти. При выборе модели надо помнить что будеть еще контекст и закладывать 1-2 Гб свободных на VRAM. Я ставлю контекст 32К-64К токенов.

### llama.cpp [!toc]  

Чтобы запустить модель нужен движок, llama.cpp загружает модель из файла .gguf на GPU, и работает как локальный сервер, можно будет зайти через web-морду, либо подключать её куда либо например к OpenCode  

Качаем с git нужный дистрибутив под наше оборудования, например у меня это карта NVIDIA к ней еще отдельно DLL для CUDA, распаковывать все в одну папку  

https://github.com/ggml-org/llama.cpp/releases  

На винде нужно еще добавить путь к llama в переменные среды (PATH), чтобы работал запуск из терминала


```
setx PATH "%PATH%;C:\путь_к_папке" /M
```

Запускаем сервер  

```
llama-server -m C:\models\Qwen3.5-9B-UDQ4_K_XL.gguf -c 32000 -ctk q4_0 -ctv q4_0 --host 127.0.0.1 --port 8080
```  

- `-m` путь до файла с моделью  
- `-c` контекст в токенах
- `--host 127.0.0.1 --port 8080` адрес сервера  

можно зайти в браузере по этому адресу и уже что-то спрасить  

- `-ctk q4_0 -ctv q4_0` квантование контеста, по аналогии с сжатием модели
- `Ctrl + C` в терминале остановить работу  

Есть и другие движки LM Studio, Ollama например, где есть красивый интерфейс и удобная настройка всякой фигни, но я считаю это все не особо нужно главное максимальная производительность  

### Подключение локальной модели в OpenCode [!toc]

Самый простой вариант, установить плагин, который сам найдет ваши запущенные модели после запуска OpenCode

```
opencode plugin --global opencode-local-provider
```

#### MCP [!toc]
Важно об этом рассказать, если LLM это мозги, то MCP это руки, сама по себе нейронка может только в чат срать, но если нужен доступ к каким то инструментам например работе с файлами то нужно их подключать к ней, это и делает MCP или Model Context Protocol это универсальный протокол связи ИИ с внешними системами.  

В оболочках типо OpenCode уже есть встроенные инструменты для работы, но что если мы хотим подключить оболочку куда-то еще или работать вообще без оболочки напрямую с llama.cpp, тогда придеться использовать инструменты MCP.

Для удобства подключения инструментов используеться фреймворк Node.js (нужно установить отдельно), а конкретно Менеджер пакетов npx, т.е. мы просто добавляем строчку в json файле с настройками и нужный пакет сам скачиваеться и подключаеться из репозитория  

#### Пример подключения в llama.cpp [!toc]
Создаем файл **mcp.json**, прописываем туда инструмент для работы с файлами, доступ к папке, а также через какой браузер можно ходить в интернет

```
{ "mcpServers": { "filesystem": { "command": "C:\\Program Files\\nodejs\\npx.cmd", "args": [ "-y", "@modelcontextprotocol/server-filesystem", "C:\\LLM\\workspace" ] }, "playwright": { "command": "C:\\Program Files\\nodejs\\npx.cmd", "args": [ "@playwright/mcp@latest", "--browser", "msedge" ] } } }
```

Запускаем сервер с аргументом `--jinja --mcp-servers-config` и путем к файлу *mcp.json*

```
llama-server -m C:\models\Qwen3.5-4B-Q5_K_M.gguf -c 64000 --jinja --mcp-servers-config C:\mcp.json --host 127.0.0.1 --port 8080
```

и теперь ИИ может работать с файлами и лазить по сайтам. В целом это уже рабочий агент, можно заставить нейронку делать что нибуть, даже без дополнительных оболочек.  

Также ничто не мешает подключит MCP в **OpenCode**, прописать серверы в файле opencode.json
