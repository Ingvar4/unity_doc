Другим функциям
можно передавать информацию в скобках (например, `Say("Hello")`). Когда функция предназначена для получения внешней информации через скобки таким образом, тип информации указывается
одним или несколькими параметрами, которые создают локальную
переменную функции (с определенным типом) для хранения информации.
В строке 10 листинга кода `void Say( string sayThis )`
объявляется параметр с именем `sayThis`, который имеет тип
`string`. Затем `sayThis` можно использовать как локальную
переменную внутри функции `Say()`.  

Когда информация передается в функцию через ее параметры, это
называется передачей информации в функцию. Каждая переменная,
передаваемая в параметр, называется аргументом. В строке 7 листинга кода
 функция `Say()` вызывается с аргументом "Hello". Другими
словами, "Hello" передается в функцию `Say()`. Тип аргументов,
передаваемых в функцию, должен совпадать с типами параметров функции,
иначе возникнет ошибка.  

```c#
public class FunctionsEx : MonoBehaviour {
    void Start() { // Add a Start() method back into the FunctionsEx class
        Say("Hello");// a
    }

    void Say( string sayThis ) {// b
        print(sayThis); // Output: "Hello"
    }
}
```

**a.** Когда в строке 7 вызывается функция `Say()`, строковый литерал
"Hello" передается в функцию `Say()` в качестве аргумента, а затем
в строке 10 значение `sayThis` равным "Hello".  
**b.** Строка `sayThis` объявлена в качестве параметра функции
`Say()`. Таким образом, `sayThis` является локальной
переменной, область действия которой ограничена функцией
`Say()`; иными словами, переменная `sayThis` не существует за
пределами функции `Say()`.  

В функции `Say()` из листинга кода мы добавили один строковый
параметр с именем sayThis. Как и при объявлении любой другой
переменной, первое слово, `string`, обозначает тип переменной, а второе
слово, `sayThis`, - имя переменной.  

Как и другие локальные переменные функции, переменные-параметры
функции являются локальными для этой функции и исчезают из памяти, как
только функция завершается; если бы параметр `sayThis` использовался
где-либо в функции `Start()`, это вызвало бы ошибку компилятора,
поскольку область действия `sayThis` ограничена исключительно
функцией `Say()`.  

В строке 7 листинга кода аргументом, передаваемым в функцию,
является строковый литерал "Hello", но в качестве типа параметра для
функции можно указать любой тип переменной или литерала, и любая
переменная или литерал, соответствующие указанному типу, могут быть
переданы в эту функцию в качестве аргумента (например, в строке 7
листинга кода `this.gameObject` передается в качестве аргумента
функции `PrintGameObjectName()`). Если функция имеет несколько
параметров, передаваемые ей аргументы должны быть разделены запятыми.

```c#
public class FunctionsEx : MonoBehaviour {
    void Start() {
        PrintGameObjectName( this.gameObject ); // Output: "Cube"
        SetColor( this.gameObject, Color.red ); // Colors the Cube red
    }

    void PrintGameObjectName( GameObject go ) {
        print( go.name );
    }

    void SetColor( GameObject go, Color col ) {
      Renderer r = go.GetComponent<Renderer>();
      r.material.color = col;
    }
}
```

### Совет [!toc]
ФУНКЦИИ C# МОЖНО ОПРЕДЕЛЯТЬ В ЛЮБОМ ПОРЯДКЕ  

Вы, вероятно, заметили в листинге кода, что функции
`PrintGameObject()` и `SetColor()` вызываются функцией
`Start()` в строках 7 и 8, но определяются только в строках 11–
18. В C# это совершенно нормально. Перед выполнением
скрипта C# просматривает весь скрипт в поисках имен функций,
поэтому не имеет значения, где в скрипте определены функции.
