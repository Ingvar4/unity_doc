Вы напишете собственные
пользовательские функции, которые могут принимать
различные типы переменных в качестве входных аргументов
и возвращать одну переменную в качестве результата.  

Также я рассмотрю некоторые особые случаи параметров
входных данных для функций, такие как перегрузка функций,
необязательные параметры и модификатор ключевого слова
`params` - все это поможет вам писать более эффективный,
модульный, многократно используемый и гибкий код.

## Определение функции [!toc]

На самом деле вы писали функции с момента создания своей первой
программы «Hello World», но до сих пор вы добавляли код во встроенные
функции Unity MonoBehaviour, такие как `Start()` и `Update()`. С этого
момента вы также будете писать функции с собственными именами.  

Лучше всего представлять себе функцию как фрагмент кода, который что-то
делает. В качестве примера выполните следующие шаги, чтобы создать
скрипт, который будет подсчитывать количество вызовов `Update()`:  

1. Добавьте в сцену новый куб: в панели меню Unity выберите *GameObject > 3D Object > Cube*.
2. Создайте новый скрипт на C# с именем `FunctionsEx` и прикрепите его к кубу.
3. Откройте `FunctionsEx` и добавьте код:

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class FunctionsEx : MonoBehaviour {
    public int numTimesCalled = 0;// a

    // void Start() { } // You can comment out the Start method

    void Update() {
        numTimesCalled++; // b
        PrintUpdates(); // c
    }

    void PrintUpdates() { // d
        string outputMessage = "Updates: " + numTimesCalled; // e
        print( outputMessage ); // Output example: "Updates: 1" // f
    }
}
```

**a.** Объявляет публичную переменную `numTimesCalled` и
присваивает ей начальное значение `0`. Поскольку `numTimesCalled`
объявлена как поле внутри класса `FunctionsEx`, но вне каких-либо
функций, к ней могут обращаться любые функции в пределах класса
`FunctionsEx`. Ключевое слово `public` позволяет другим
классам, а также инспектору Unity видеть и изменять
`numTimesCalled`. Переменные, объявленные таким образом
внутри класса и вне функции, обычно называют полями.  

**b.** Значение `numTimesCalled` увеличивается (на 1).  

**c.** В строке 12 вызывается функция `PrintUpdates()`. Когда ваш код
вызывает функцию, это приводит к её выполнению. Я опишу это
более подробно чуть позже.  

**d.** В строке 15 объявляется функция `PrintUpdates()`. Объявление
функции похоже на объявление переменной. `void` - это тип
возвращаемого значения функции, что означает, что функция не
должна возвращать значение (я расскажу об этом подробнее чуть
позже). Строки 15–18 в совокупности
определяют функцию. Все строки кода между открывающей
фигурной скобкой `{` в строке 15 и закрывающей фигурной скобкой `}`
в строке 18 являются частью определения `PrintUpdates()`.  

Обратите внимание, что порядок объявления функций в классе не
имеет значения. Неважно, какая функция объявлена первой -
`PrintUpdates()` или `Update()` - главное, чтобы обе
находились в фигурных скобках класса `FunctionsEx`. Перед
выполнением кода C# просматривает все объявления в классе.
Совершенно нормально, что `PrintUpdates()` вызывается в строке
12 и объявлена в строке 15, поскольку и `PrintUpdates()`, и
`Update()` являются функциями, объявленными в классе
`FunctionsEx`.  

**e.** В строке 16 определяется локальная строковая переменная с именем
`outputMessage`. Поскольку `outputMessage` определена
внутри функции `PrintUpdates()`, ее область действия ограничена функцией
`PrintUpdates()`, что означает, что имя переменной
`outputMessage` перестает существовать за пределами функции
`PrintUpdates()`.  

В строке 16 также определяется, что `outputMessage` представляет
собой конкатенацию
`«Updates: »` и общедоступное целое число `numTimesCalled`.  

**f.** Функция Unity `print()` вызывается с единственным аргументом
`outputMessage`. Это выводит значение `outputMessage` в
консоль Unity. Аргументы функций я рассмотрю позже в этой главе.  

4. Сохраните скрипт `FunctionsEx` в Visual Studio, вернитесь в Unity и нажмите «Play».  

Вы увидите, что в каждом кадре значение `numTimesCalled`
увеличивается на единицу, а затем вызывается `PrintUpdates()`, что
приводит к выводу значения `numTimesCalled` в панель консоли много
раз в секунду.  

В реальной игре функция `PrintUpdates()` не была бы особо полезной,
но она демонстрирует два важных понятия, рассматриваемых в этой главе:  

- Функции инкапсулируют действия: можно представить себе
функцию как именованную коллекцию нескольких строк кода. Каждый
раз, когда функция вызывается, эти строки кода выполняются. Это
демонстрируется примером `PrintUpdates()`.
- Функции имеют собственную область действия, область действия переменных, объявленных
внутри функции, ограничена этой функцией. Следовательно, область
действия переменной `outputMessage` (объявленной в строке 16)
ограничена только функцией `PrintUpdates()`. Это можно
сформулировать как «`outputMessage` имеет область действия,
ограниченную функцией `PrintUpdates()`» или «`outputMessage`
является локальной переменной функции `PrintUpdates()`».  

Сравните область действия локальной переменной `outputMessage` с
областью действия поля класса `numTimesCalled`, которое имеет
область действия, охватывающую весь класс `FunctionsEx`, и может
использоваться любой функцией в `FunctionsEx`. (Переменная,
область действия которой ограничена всем классом, называется
полем.)
