title: Добавление прокручивающегося фона со звездным небом
description: После всей этой работы с кодом можно сделать кое-что просто ради удовольствия, чтобы игра выглядела немного лучше- создать двухслойный фон со звездным небом, придающий ей больше сходства с открытым космосом.

1. Создайте объект Quad в окне Hierarchy (GameObject > 3D Object > Quad). Назовите его
StarfieldBG.  
    StarfieldBG (Quad) P:[ 0, 0, 10 ] R:[ 0, 0, 0 ] S:[ 80, 80, 1 ]  

Это размещает StarfieldBG в центре поля зрения камеры и полностью его заполняет.  

2. Создайте новый материал с именем Mat_Starfield в папке _Materials на панели Project.
    - a. Установите для Mat_Starfield шейдер ProtoTools > UnlitAlpha.
    - b. В качестве текстуры для Mat_Starfield выберите Space (тип Texture2D) из папки _Materials,
которую вы импортировали в начале этого руководства.
3. Перетащите Mat_Starfield на объект StarfieldBG; позади вашего корабля _Hero должно появиться звездное небо.
4. Выберите Mat_Starfield на панели Project и продублируйте его (Command-D на Mac или Ctrl+D
на ПК).
    - a. Назовите новый материал Mat_Starfield_Transparent.
    - b. Выберите Space_Transparent (в папке _Materials) в качестве текстуры для этого нового материала.
5. Выберите StarfieldBG на панели Hierarchy и продублируйте его.
    - a. Назовите дубликат StarfieldFG_0 (здесь используется цифра 0).
    - b. Перетащите материал Mat_Starfield_Transparent на объект StarfieldFG_0.
    - c. Установите следующие параметры Transform для StarfieldFG_0:  
    StarfieldFG_0 P:[ 0, 0, 5 ] R:[ 0, 0, 0 ] S:[ 160, 160, 1 ]  

Если немного повращать StarfieldFG_0, можно заметить, как звезды на переднем плане смещаются относительно звезд на заднем плане, создавая эффектный параллакс.  

6. Дублируйте объект StarfieldFG_0 и назовите копию StarfieldFG_1. Для реализации приема с прокруткой, который вы собираетесь использовать, вам понадобятся две копии объекта переднего плана.
7. Создайте новый C#-скрипт с именем Parallax в папке *__Scripts* и введите код.  
    Листинг Parallax.cs

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class Parallax : MonoBehaviour {
    [Header("Inscribed")]
    public Transform playerTrans; // The player ship
    public Transform[] panels; // The scrolling foregrounds
    [Tooltip("Speed at which the panels move in Y")]
    public float scrollSpeed = -30f;
    [Tooltip("Controls how much panels react to player movement (Default 0.25)")]
    public float motionMult = 0.25f; // a

    private float panelHt; // Height of each panel
    private float depth; // Depth of panels (that is, pos.z)

    void Start () {
        panelHt = panels[0].localScale.y;
        depth = panels[0].position.z;

        // Set initial positions of panels
        panels[0].position = new Vector3(0,0,depth);
        panels[1].position = new Vector3(0,panelHt,depth);
    }

    void Update () {
        float tY, tX=0;
        tY= Time.time * scrollSpeed % panelHt + (panelHt *0.5f); // b

        if (playerTrans != null) {
            tX = -playerTrans.transform.position.x * motionMult; // c
            //tY += -poi.transform.position.y * motionMult;
        }

        // Position panels[0]
        panels[0].position = new Vector3(tX, tY, depth);
        // Position panels[1] where needed to make a continuous starfield // d
        if (tY >= 0) {
            panels[1].position = new Vector3(tX, tY -panelHt, depth);
        } else {
            panels[1].position = new Vector3(tX, tY +panelHt, depth);
        }
    }
}
```

    - a. В строке // c перемещение объекта playerTrans по оси X умножается на коэффициент motionMult,
чтобы определить смещение панелей по оси X.
    - b. Переменная tY вычисляется как произведение скорости прокрутки (scrollSpeed) и времени,
прошедшего с начала игры; затем к полученному значению применяется операция взятия остатка (%)
от высоты панели. Эта операция ограничивает диапазон значений (Time.time * scrollSpeed)
пределами от 0 до panelHt (в нашем случае — 160); поскольку scrollSpeed ​​отрицательна,
результат операции % будет находиться в диапазоне от -159,99 до 0. Затем к этому числу
прибавляется половина высоты панели (panelHt/2), в результате чего значения tY
всегда попадают в диапазон от -panelHt/2 до panelHt/2. В сочетании с остальным кодом
это позволяет постоянно удерживать поля звезд на экране и выравнивать их так,
чтобы они выглядели как непрерывное изображение.
    - c. Значение tX корректируется с учетом позиции игрока по оси X, как описано в пункте // a.
Строка для tY закомментирована, так как мне не понравился полученный эффект,
но вы можете раскомментировать её и посмотреть, понравится ли она вам.
    - d. После размещения панели panels[0] настраивается положение панели panels[1],
чтобы гарантировать отсутствие разрывов в поле звезд. Если координата Y панели panels[0]
больше нуля, то панель panels[1] размещается под ней, и наоборот.  

8. Сохраните скрипт Parallax и вернитесь в Unity.
9. Прикрепите скрипт Parallax к объекту _MainCamera. После этого:
    - a. Выберите _MainCamera в окне Hierarchy и найдите компонент Parallax (Script) в окне Inspector.
    - b. Перетащите _Hero из окна Hierarchy в поле playerTrans.
    - c. Добавьте StarfieldFG_0 и StarfieldFG_1 в массив panels.  

10. Нажмите кнопку «Воспроизвести», и вы увидите, как звёздное поле движется в ответ на действия игрока.
11. Конечно, не забудьте сохранить сцену.


### Выводы [!toc]

Эта глава получилась объемной, но в ней было представлено множество важных концепций, которые, надеюсь, пригодятся вам в ваших будущих игровых проектах. На протяжении многих лет я активно использовал линейную интерполяцию (или lerp) и кривые Безье для создания плавных и качественных движений в своих играх и других проектах. Даже простая функция плавности (easing function) способна придать движению объекта грациозность, энергичность или, наоборот, вялость — и это мощный инструмент, когда вы настраиваете «ощущение» игры.

Мы научимся считывать данные из JSON-файла, чтобы сформировать полную колоду карт на основе всего лишь нескольких графических ресурсов, а также использовать JSON для компоновки игрового поля. Кроме того, в этой главе будут представлены ScriptableObjects — способ создания экземпляров скриптов в окне Project, которые можно редактировать в инспекторе, не привязывая их к конкретному игровому объекту (GameObject). Поверьте, это гораздо интереснее и полезнее, чем может показаться на первый взгляд. В итоге у вас получится увлекательная цифровая карточная игра, в которую можно будет сыграть.

### Дальнейшие шаги [!toc]

Благодаря опыту, полученному в предыдущих уроках, вы уже знаете, как выполнить многие действия, описанные в этом разделе. Здесь приведены лишь некоторые рекомендации о том, что можно сделать, если вы решите продолжить работу над этим прототипом.  

Настройка переменных  

Как вы уже убедились на примере как настольных, так и цифровых игр, настройка числовых параметров критически важна и существенно влияет на игровой опыт. Ниже приведен список переменных, которые стоит отрегулировать, чтобы изменить ощущение от игры:  

- _Hero: Измените ощущения от перемещения.
    - Настройте скорость.
    - Измените гравитацию, а также чувствительность по горизонтальной и вертикальной осям в Input Manager (меню Edit > Project Settings… > Input Manager).
- Оружие: Сделайте оружие более разнообразным.
    - Дробовик (Spread gun): может выпускать пять снарядов вместо трех, но с гораздо большей задержкой между выстрелами (delayBetweenShots).
    - Бластер: может стрелять чаще (меньшая задержка delayBetweenShots), но наносить меньше урона каждым выстрелом (сниженный damageOnHit).

### Добавить дополнительные элементы [!toc]
Хотя в этом прототипе пока представлены пять видов врагов и два вида оружия,
перед вами открываются безграничные возможности в отношении и тех, и других:  

- Оружие: Добавьте дополнительное оружие.
    - Фазер: Выпускает два снаряда, движущихся по синусоидальной траектории (подобно
движению Enemy_1).
    - Лазер: Вместо того чтобы наносить весь урон сразу, лазер наносит непрерывный урон
со временем.
    - Ракеты: Ракеты могли бы иметь механизм захвата цели и очень низкую скорострельность, но
были бы отслеживать врагов и всегда попадать в цель. Возможно, ракеты могли бы быть другим видом
оружия с ограниченным боеприпасом, которое запускается с помощью другой кнопки (т.е. не
пробела). (Если вы хотите, чтобы что-то точно переместилось из одного места в другое за
определенное время, двигаясь по кривой, кривая Безье — отличный способ это сделать!)
    - Поворотный пистолет: Как бластер, но стреляет по ближайшему врагу. Однако
урон был бы очень низким.
- Враги: Добавьте дополнительных врагов. Для этой игры можно создать бесчисленное множество их разновидностей.
- Добавьте дополнительные способности врагов:
    - Позвольте некоторым врагам стрелять.
    - Некоторые враги могут отслеживать игрока и преследовать его — возможно, действуя подобно самонаводящимся ракетам.

### Создайте полноценный игровой уровень [!toc]
Изначально я планировал рекомендовать создание классов C# для описания волн вражеских кораблей и уровней, состоящих из таких волн, однако в ходе совместной работы с моим студентом Генри Нотарианни в прошлом семестре мы придумали гораздо более простой метод, который назвали «конвейерной лентой»:  

- Создайте пустой игровой объект (GameObject) с именем `ConveyorBelt` и начальной позицией `[0, 0, 0]`.
- Добавьте экземпляры различных врагов в качестве дочерних объектов для `ConveyorBelt`. Разместите первого врага выше верхней границы видимой области экрана и продолжайте расставлять их выше, формируя нужный вам узор появления.
- Создайте класс `ConveyorBelt`, который будет перемещать игровой объект `ConveyorBelt` вниз с заданной скоростью.
- Измените класс `Enemy` так, чтобы при появлении врага на экране (определяемом с помощью проверки границ — `BoundsCheck`) он вызывал для себя метод `transform.SetParent(null, true)` (отвязывая себя от `ConveyorBelt` без изменения текущей позиции). Это позволит врагу перемещаться независимо относительно экрана (и перестать зависеть от движения `ConveyorBelt`). Также потребуется заменить метод `Start()` в различных классах `Enemy_#` на метод `Init()`, который будет вызываться в момент появления врага на экране (а не при создании игрового объекта).
- Для крупных врагов-боссов можно приостанавливать движение `ConveyorBelt` до тех пор, пока босс не будет уничтожен, давая игроку возможность сосредоточиться исключительно на этом противнике.  

Честно говоря, я был поражен тем, насколько этот способ оказался проще моего первоначального подхода и какой простор для контроля он открывает перед левел-дизайнером при создании интересной системы появления врагов. Это лишний раз доказывает, какую огромную пользу приносит работа над проектами совместно с другими людьми!
