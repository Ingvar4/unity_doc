В этом разделе вы научитесь создавать два различных типа оружия с возможностью их дальнейшего расширения. Для этого вы создадите класс `WeaponDefinition`, позволяющий определять поведение каждого типа оружия.

### Перечисление eWeaponType [!toc]

Как описано в главе («Mission Demolition»), *enum* (сокращение от *enumeration* - перечисление) - это способ объединения различных вариантов в новый тип переменной. В этой игре игроки смогут переключать и улучшать оружие, собирая бонусы, выпадающие из побежденных врагов. Также будет предусмотрен бонус, усиливающий щит. Чтобы использовать единый тип переменной для хранения всех возможных видов бонусов, вы создадите перечисление с именем `eWeaponType`. Я обычно начинаю названия типов перечислений со строчной буквы «e», чтобы их было легче выделить.

1. Щелкните правой кнопкой мыши по папке *__Scripts* на панели Project и выберите *Create > C# Script*.
В результате в папке *__Scripts* будет создан файл *NewBehaviourScript*.
2. Переименуйте *NewBehaviourScript* в *Weapon*. В дальнейшем вы напишете скрипт для класса *Weapon* (наследуемого от MonoBehaviour), но пока нас интересует только перечисление eWeaponType.
3. Откройте скрипт Weapon в Visual Studio и введите код из листинга. Объявление public enum eWeaponType следует разместить между строками `using UnityEngine;` и `public class Weapon : MonoBehaviour {}`.  
    Weapon.cs

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

/// <summary>
/// This is an enum of the various possible weapon types.
/// It also includes a "shield" type to allow a shield PowerUp.
/// Items marked [NI] below are Not Implemented in this book.
/// </summary>
public enum eWeaponType {
    none, // The default / no weapon
    blaster, // A simple blaster
    spread, // Multiple shots simultaneously
    phaser, // [NI] Shots that move in waves
    missile, // [NI] Homing missiles
    laser, // [NI] Damage over time
    shield // Raise shieldLevel
}

public class Weapon : MonoBehaviour {
    // For now, please delete everything inside the Weapon class definition.
}
```

Поскольку `eWeaponType` является публичным перечислением (enum), объявленным вне класса `Weapon`, оно доступно для использования любым классом в проекте. Вы будете активно применять его на протяжении всей оставшейся части этой главы, а сами виды оружия определите позже - непосредственно в окне Inspector.
Дополнительную информацию о перечислениях можно найти в Приложении B, в подразделе «Enums» раздела «C# and Unity Coding Concepts».

### Сериализуемый класс WeaponDefinition [!toc]

Теперь вам нужно создать класс, определяющий характеристики различных типов оружия. В отличие от большинства других классов, созданных вами в этой книге, он не будет являться подклассом `MonoBehaviour`, и его не нужно будет прикреплять к отдельному объекту `GameObject`. Вместо этого это будет простой, самостоятельный открытый (`public`) класс, который вы определите внутри C#-скрипта `Weapon` - точно так же, как вы ранее определили открытое перечисление `eWeaponType`.  

Еще одна важная особенность этого класса заключается в том, что он является сериализуемым, благодаря чему его можно просматривать и редактировать в окне Inspector в Unity!
Откройте скрипт Weapon и вставьте код в листинге, между определением `public enum eWeaponType` и определением `public class Weapon`.  
    Листинг Weapon.cs

```c#
…
public enum eWeaponType { … }

/// <summary>
/// The WeaponDefinition class allows you to set the properties
/// of a specific weapon in the Inspector. The Main class has
/// an array of WeaponDefinitions that makes this possible.
/// </summary>
[System.Serializable] // a
public class WeaponDefinition { // b
    public eWeaponType type = eWeaponType.none;
    [Tooltip("Letter to show on the PowerUp Cube")] // c
    public string letter;
    [Tooltip("Color of PowerUp Cube")]
    public Color powerUpColor = Color.white; // d
    [Tooltip("Prefab of Weapon model that is attached to the Player Ship")]
    public GameObject weaponModelPrefab;
    [Tooltip("Prefab of projectile that is fired")]
    public GameObject projectilePrefab;
    [Tooltip("Color of the Projectile that is fired")]
    public Color projectileColor = Color.white; // d
    [Tooltip("Damage caused when a single Projectile hits an Enemy")]
    public float damageOnHit = 0;
    [Tooltip("Damage caused per second by the Laser [Not Implemented]")]
    public float damagePerSec = 0;
    [Tooltip("Seconds to delay between shots")]
    public float delayBetweenShots = 0;
    [Tooltip("Velocity of individual Projectiles")]
    public float velocity = 50;
}

public class Weapon : MonoBehaviour { … }
```

    - a. Атрибут `[System.Serializable]` делает класс, объявленный непосредственно после него, сериализуемым и доступным для редактирования в инспекторе Unity. Некоторые классы слишком сложны для сериализации, но `WeaponDefinition` достаточно прост, поэтому с ним всё будет работать нормально.
    - b. Вы можете изменять отдельные поля класса `WeaponDefinition`, чтобы корректировать характеристики пуль, выпускаемых вашим кораблем. В этой главе мы задействуем не все из них; часть полей останется для использования, если вы решите в дальнейшем расширить функционал игры.
    - c. Если вы работаете над проектом в одиночку, такое обилие атрибутов `[Tooltip]` может показаться излишним, но я добавил их по двум причинам: 1) они заменяют комментарии, которые мне пришлось бы писать для пояснения назначения каждого поля; 2) если бы вы работали над проектом с кем-то еще, кому предстояло бы настраивать оружие, эта информация оказалась бы для него очень полезной.  

        Кроме того, иногда оказывается, что тем самым «другим человеком», для которого я пишу комментарии к коду и подсказки `[Tooltip]`, становлюсь я сам спустя год или около того, когда уже забываю детали реализации игры, - так что в этом плане они тоже весьма полезны.
    - d. В предыдущих версиях Unity, даже если мы устанавливали для обоих цветов значение по умолчанию «белый», в инспекторе они всё равно принимали значение «полностью прозрачный черный» (то есть черный цвет с альфа-каналом, равным 0, из-за чего все пули становились невидимыми!). Я сообщил об этой ошибке разработчикам Unity во время написания книги, и в версии 2020.3 она была исправлена! Напоминаю: всегда сообщайте об обнаруженных вами ошибках.

>На самом деле, теперь кажется, что в Unity 2020.3.20 эта ошибка вернулась. Видимо, всё предусмотреть невозможно.  

Как указано в комментариях к коду, перечисление `eWeaponType` определяет все возможные типы оружия и усилений, а `WeaponDefinition` - это класс, объединяющий `eWeaponType` с рядом переменных, необходимых для описания каждого вида оружия.  

### Изменение метода Main для использования WeaponDefinition и eWeaponType [!toc]

Теперь вам нужно использовать новое перечисление eWeaponType и класс WeaponDefinition в классе
Main. Это делается в классе Main, потому что он отвечает за создание врагов и
в конечном итоге бонусов. (Вы также можете создать для этого ScriptableObject, о котором вы узнаете в главе «Prospector Solitaire-Part 1.»)

1. Откройте основной скрипт C# в Visual Studio и добавьте код.
Помимо `weaponDefinitions`, мы также используем этот листинг для добавления переменной типа `bool` с именем `spawnEnemies`. Если в окне Inspector для `spawnEnemies` не установлена ​​галочка, враги не будут появляться; это пригодится при настройке определенных тестовых ситуаций.  
  Листинг Main.cs

```c#
public class Main : MonoBehaviour {
    …
    [Header("Inscribed")]
    public bool spawnEnemies = true; // a
    public GameObject[] prefabEnemies; // Array of Enemy prefabs
    public float enemySpawnPerSecond = 0.5f; // # Enemies spawned/second
    public float enemyInsetDefault = 1.5f; // Inset from the sides
    public float gameRestartDelay = 2;
    public WeaponDefinition[] weaponDefinitions; // b

    private BoundsCheck bndCheck;
    …
    public void SpawnEnemy() {
        // If spawnEnemies is false, skip to the next invoke of SpawnEnemy()
        if ( !spawnEnemies ) { // c
            Invoke( nameof( SpawnEnemy ), 1f / enemySpawnPerSecond );
            return;
        }
        // Pick a random Enemy prefab to instantiate
        int ndx = Random.Range( 0, prefabEnemies.Length );
        GameObject go = Instantiate<GameObject>( prefabEnemies[ndx] );
        …
    }
    …
}
```

    - a. В верхней части инспектора для основного скрипта (Main (Script)) появится флажок spawnEnemies.
    - b. Не забудьте добавить массив weaponDefinitions.
    - c. Если значение spawnEnemies равно false, эти строки снова вызовут метод `SpawnEnemy()`, а затем завершат выполнение, не создавая при этом никаких врагов. Использование метода `Invoke()` в данном случае позволяет нам впоследствии возобновить появление врагов, установив для spawnEnemies значение true.

2. Сохраните основной скрипт и вернитесь в Unity.
3. Выберите объект _MainCamera в окне Hierarchy. Теперь в окне Inspector для компонента Main (Script) вы должны увидеть массив weaponDefinitions.
4. Нажмите на треугольник раскрытия рядом с weaponDefinitions в окне Inspector и установите значение Size (размер) массива равным 3.
5. Введите настройки для трех элементов WeaponDefinitions, как показано на рисунке. Вы увидите, что перечисление eWeaponType отображается в окне Inspector в виде выпадающего меню (хотя, как и в других случаях в Inspector, названия элементов перечисления записаны с заглавной буквы).

Настройки WeaponDefinitions для бластера, оружия с рассеивающим выстрелом и щита; поля, которые необходимо заполнить, выделены.  

Вы можете найти префабы weapon_Laser и weapon_SpreadShot на панели Project по пути *Assets > Assets by Peter Burroughs > Models* либо в алфавитном списке на вкладке Assets, если нажмете на кружок справа от поля weaponModelPrefab в окне Inspector.  

Как указано в примечании `// d` к листингу кода, цвета в `WeaponDefinitions` теперь должны по умолчанию устанавливаться как белые; однако, если по какой-то причине они принимают значение «прозрачного черного» (`[ r:0, g:0, b:0, a:0 ]`), вам потребуется задать не только сам цвет, но и его альфа-канал (прозрачность), чтобы снаряды стали видимыми. Важно установить значение альфа-канала для каждого цвета равным 255 (полная непрозрачность); в интерфейсе это отображается как белая полоска под образцом цвета. Если кубы бонусов (PowerUp) или снаряды невидимы, это означает, что значение альфа-канала равно 0.  

6. Убедившись, что параметры weaponDefinitions соответствуют показанным на
рисунке, сохраните сцену. Еще раз проверьте значения Color Alpha и ознакомьтесь
с приведенным ниже предупреждением.

<Callout type='idea'>
### Предупреждение [!toc]
**ИНОГДА ЦВЕТА ПО УМОЛЧАНИЮ ИМЕЮТ НУЛЕВОЕ ЗНАЧЕНИЕ АЛЬФА-КАНАЛА.** Когда вы
создаете сериализуемый класс (например, `WeaponDefinition`), содержащий поля типа `Color`,
значения альфа-канала (прозрачности) для этих цветов могут по умолчанию устанавливаться на 0 (ноль, то есть полная прозрачность). Чтобы исправить это,
убедитесь, что белые линии под каждым из ваших определений цвета
действительно белые (а не черные). Если щелкнуть по самому образцу цвета,
откроется панель настройки четырех параметров (R, G, B и A). Убедитесь, что для параметра A
установлено значение 255 (полная непрозрачность), иначе ваши снаряды будут невидимыми.  

Если вы используете macOS и выбрали системный инструмент выбора цвета macOS
вместо стандартного инструмента Unity, то значение A нужно задавать с помощью
ползунка Opacity (непрозрачность) в нижней части окна выбора цвета
(для обеспечения полной непрозрачности этот ползунок должен быть установлен на 100%).
