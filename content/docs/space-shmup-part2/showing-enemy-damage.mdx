Однако для этого необходимо иметь доступ ко всем материалам всех дочерних объектов каждого врага. Получение всех материалов может пригодиться в самых разных играх, поэтому давайте включим этот функционал в класс `Utils` (на языке C#), который вы начали создавать ранее в этой главе.

### Добавление GetAllMaterials в скрипт Utils [!toc]

Я уже упоминал, что в объектно-ориентированном программировании обычно считается правильным создавать несколько небольших классов. Однако, поскольку Utils представляет собой набор разнородных статических методов, я решил позволить этому классу стать довольно объемным - подобно встроенному в Unity классу Mathf.

1. Откройте скрипт Utils в Visual Studio и введите код, выделенный жирным шрифтом в листинге.  
    Листинг Utils.cs

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class Utils : MonoBehaviour {

    //== Bézier Curves =============================================================\\
    …
    static public Vector3 Bezier( float u, params Vector3[] points ) { … }

    //== Materials Functions =======================================================\\

    /// <summary>
    /// Returns a list of all Materials on this GameObject and its children
    /// </summary>
    /// <param name="go">The GameObject on which to search for Renderers</param>
    static public Material[] GetAllMaterials( GameObject go ) { // a
        Renderer[] rends = go.GetComponentsInChildren<Renderer>(); // b

        Material[] mats = new Material[rends.Length];
        for (int i=0; i<rends.Length; i++) { // c
            mats[i] = rends[i].material;
        }

        return mats;
    }
}
```

    - a. Будучи статическим публичным методом, GetAllMaterials() может быть вызван в любой части проекта с помощью конструкции Utils.GetAllMaterials().
    - b. `GetComponentsInChildren<>()` - это метод, доступный для всех объектов GameObject; он перебирает сам объект и все его дочерние элементы, возвращая массив компонентов того типа, который был передан в качестве параметра шаблона `<>` (в данном примере - тип Renderer).
    - c. Этот цикл for перебирает компоненты Renderer в массиве rends и извлекает поле material из каждого из них. Затем полученный материал добавляется в массив mats.

### Использование GetAllMaterials для того, чтобы заставить врага мигать красным [!toc]

Теперь мы сделаем так, чтобы игровые объекты врагов (Enemy) мигали красным цветом при попадании в них снаряда героя (ProjectileHero). Вместо того чтобы усложнять класс Enemy, создадим новый скрипт BlinkColorOnHit, который будет отвечать за эту функцию. Разумеется, это означает, что данный скрипт нужно будет добавить ко всем префабам врагов.  

1. Создайте новый C#-скрипт с именем BlinkColorOnHit и поместите его в папку *__Scripts*.
2. Откройте скрипт BlinkColorOnHit в Visual Studio и введите код из листинга.  
    BlinkColorOnHit.cs

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

[DisallowMultipleComponent] // a
public class BlinkColorOnHit : MonoBehaviour {
    private static float blinkDuration = 0.1f; // # seconds to show damage // b
    private static Color blinkColor = Color.red;

    [Header("Dynamic")]
    public bool showingColor = false;
    public float blinkCompleteTime; // Time to stop showing the color

    private Material[] materials; // All the Materials of this & its children
    private Color[] originalColors;
    private BoundsCheck bndCheck;

    void Awake() {
        bndCheck = GetComponentInParent<BoundsCheck>(); // c
        // Get materials and colors for this GameObject and its children
        materials = Utils.GetAllMaterials( gameObject ); // d
        originalColors = new Color[materials.Length];
        for (int i=0; i <materials.Length; i++) {
            originalColors[i] = materials[i].color;
        }
    }

    // void Start() {…} // Please delete the unused Start() method

    void Update() {
        if ( showingColor && Time.time > blinkCompleteTime ) RevertColors(); // e
    }

    void OnCollisionEnter( Collision coll ) {
        // Check for collisions with ProjectileHero
        ProjectileHero p = coll.gameObject.GetComponent<ProjectileHero>();
        if ( p != null ) { // f
            if ( bndCheck != null && !bndCheck.isOnScreen ) { // g
                return; // Don’t show damage if this is off screen
            }
            SetColors();
        }
    }

    /// <summary>
    /// Sets the Albedo color (i.e., the main color) of all materials in the
    /// materials array to blinkColor, sets showingColor to true, and sets the
    /// time that the colors should be reverted.
    /// </summary>
    void SetColors() {
        foreach (Material m in materials) {
            m.color = blinkColor;
        }
        showingColor = true;
        blinkCompleteTime = Time.time + blinkDuration;
    }

    /// <summary>
    /// Reverts all materials in the materials array back to their original color
    /// and sets showingColor to false.
    /// </summary>
    void RevertColors() {
        for ( int i=0; i <materials.Length; i++ ) {
            materials[i].color = originalColors[i];
        }
        showingColor = false;
    }
}
```

    - a. Атрибут компилятора [DisallowMultipleComponent] сообщает Unity, что каждый GameObject может содержать только один экземпляр этого скрипта. Вы скоро увидите, как это работает.
    - b. Поскольку мы хотим, чтобы параметры `blinkDuration` и `blinkColor` были одинаковыми для всех экземпляров `BlinkColorOnHit`, логично сделать их закрытыми статическими полями (`private static`). Это позволяет использовать одни и те же значения для всех экземпляров `BlinkColorOnHit`, благодаря чему все враги будут мигать одинаково.
    - c. Мы используем здесь `GetComponentInParent<>()`, так как впоследствии этот скрипт будет прикреплен к отдельным частям игрового объекта `Enemy_4`, а не просто к его основному объекту. Также допустима ситуация, когда этот метод возвращает `null` (см. // e).
    - d. Массив материалов заполняется с помощью нового метода `Utils.GetAllMaterials()`. Затем код перебирает все материалы и сохраняет их исходный цвет. Хотя в данный момент все материалы игрового объекта `Enemy` имеют белый цвет, сохранение исходных цветов позволяет назначать им любой желаемый цвет, менять его на `blinkColor` при получении врагом урона, а затем возвращать исходный цвет.  

        Важно отметить, что вызов `Utils.GetAllMaterials()` происходит в методе `Awake()`, а результат кэшируется в переменной `materials`. Это гарантирует, что операция выполняется лишь однажды для каждого врага. Метод `Utils.GetAllMaterials()` вызывает `GetComponentsInChildren<>()` - довольно медленную функцию, требующую значительных вычислительных ресурсов и снижающую производительность. Поэтому лучше вызвать её один раз и сохранить результат, чем вызывать каждый раз при получении игровым объектом урона.
    - e. Если враг в данный момент окрашен (например, в красный цвет) и текущее время превышает `blinkCompleteTime`, вызывается метод `RevertColors()`.
    - f. Как и в случае с получением урона в скрипте `Enemy`, если у игрового объекта, нанесшего удар, есть компонент `ProjectileHero`, мы попытаемся мигнуть красным цветом.
    - g. Отличие этой строки от аналогичной в скрипте `Enemy` (см. листинг кода 32.21 // c) заключается в том, что здесь учитывается случай, когда `bndCheck` равен `null`. Если `bndCheck` не равен `null` и игровой объект находится за пределами экрана, мы не мигаем красным (и скрипт `Enemy` не фиксирует получение урона). В противном случае вызывается метод `SetColors()`.

3. Сохраните все скрипты в Visual Studio и вернитесь в Unity.
4. Выберите объект _MainCamera в окне Hierarchy и убедитесь, что префаб Enemy_0 назначен элементу Element 0 массива prefabEnemies компонента Main (Script). Это гарантирует, что вы будете сражаться именно с врагами типа Enemy_0.
5. Нажмите на имя Enemy_0 в поле Element 0 массива prefabEnemies компонента Main (Script). Это подсветит префаб Enemy_0 в окне Project.
6. Выберите Enemy_0 в папке _Prefabs окна Project.
7. Добавьте скрипт BlinkColorOnHit к префабу Enemy_0, выбрав в главном меню Unity пункт *Component > Scripts > Blink Color On Hit*, и убедитесь в окне Inspector, что скрипт был добавлен.
8. Нажмите кнопку Play в Unity, чтобы протестировать игру.  

Теперь, когда в Enemy_0 попадает снаряд, выпущенный Героем, объект окрашивается в красный цвет на время `blinkDuration` (за счет изменения цвета всех его материалов на красный). По истечении этого времени скрипт `BlinkColorOnHit` возвращает объекту Enemy_0 и его дочерним элементам исходные цвета.  

9. Пришло время применить скрипт BlinkColorOnHit ко всем префабам Enemy_#:  
    - a. Выберите Enemy_0 в папке _Prefabs на панели Project.
    - b. Удерживая клавишу Shift, щелкните Enemy_4 в папке _Prefabs. Это позволит выделить все пять префабов Enemy_#.
    - c. В главном меню Unity выберите Component > Scripts > Blink Color On Hit.  

При этом появится окно с сообщением об ошибке: «Invalid operation. Can’t add 'BlinkColorOnHit' to Enemy_0 because a 'BlinkColorOnHit' is already added to the game object!» (Недопустимая операция. Невозможно добавить 'BlinkColorOnHit' к Enemy_0, так как компонент 'BlinkColorOnHit' уже добавлен к этому игровому объекту). Не волнуйтесь - это хорошо. Если нажать OK и посмотреть в окне Inspector, можно увидеть, что к каждому из префабов Enemy_# (включая Enemy_0) теперь присоединен только один компонент BlinkColorOnHit (Script). Атрибут компилятора [DisallowMultipleComponent] не позволил нам случайно добавить второй компонент BlinkColorOnHit (Script) к объекту Enemy_0, у которого такой компонент уже имелся.  

Теперь гораздо лучше видно, что вы наносите урон вражеским кораблям, однако требуется еще много попаданий, чтобы уничтожить врага. Давайте создадим бонусы (назовем класс PowerUp), которые усилят оружие игрока и увеличат его количество.
