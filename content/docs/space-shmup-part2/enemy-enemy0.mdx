title: Enemy to Enemy_0
description: В предыдущей главе ваш префаб врага назывался Enemy_0, но сейчас для управления им вы используете класс Enemy.
---

Существует несколько ситуаций, когда вам может понадобиться узнать, является ли GameObject именно Enemy_0, а не каким-либо другим типом врага (например, если игрок получает разное количество очков за разные типы врагов), поэтому нам
нужен специальный скрипт для Enemy_0.

1. Создайте скрипт Enemy_0 и прикрепите его к префабу Enemy_0:
    - a. Создайте новый скрипт C# с именем Enemy_0 в папке __Scripts.
    - b. Перетащите этот скрипт Enemy_0 на префаб игрового объекта Enemy_0 в папке _Prefabs. (Если вы используете Plastic SCM, возможно, вам сначала потребуется выбрать префаб Enemy_0 на панели Проект, а затем нажать «Выполнить» в Инспекторе.)
    - c. Выберите префаб игрового объекта Enemy_0 в папке _Prefabs и убедитесь, что компонент
Enemy_0 (Script) был прикреплен (он будет внизу Инспектора).
2. Удалите существующий компонент Enemy (Script) с префаба Enemy_0.
    - a. Выберите префаб игрового объекта Enemy_0 в папке _Prefabs.
    - b. В инспекторе щелкните три вертикальные точки (⋮) в правом верхнем углу компонента Enemy (Script) и выберите «Удалить компонент».

Теперь вам нужно отредактировать скрипт Enemy_0, чтобы он вел себя точно так же, как и его суперкласс
Enemy.

3. Откройте скрипт Enemy_0 в Visual Studio и внесите изменения.  
    Листинг кода Enemy_0.cs

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class Enemy_0 : Enemy { // Enemy_0 extends the Enemy class // a
    // void Start() { } // Delete *everything* inside the class definition! // b
    // void Update() { }
}
```

    - a. Замена `MonoBehaviour` на `Enemy` в этой строке критически важна. Именно это делает `Enemy_0` подклассом `Enemy`.
    - b. Также необходимо удалить методы `Start()` и `Update()`, чтобы они не переопределяли одноименные методы в суперклассе `Enemy`.  

Сделав Enemy_0 подклассом Enemy (см. пункт `// a`), класс Enemy_0 наследует все не являющиеся закрытыми (non-private) методы, поля, свойства и прочие элементы суперкласса (в данном случае - Enemy).  

4. Сохраните скрипт Enemy_0, вернитесь в Unity и нажмите кнопку Play. Вы увидите, что игровые объекты (GameObject) с компонентом Enemy_0 ведут себя точно так же, как и тогда, когда к ним был прикреплен скрипт Enemy.

<Callout type='idea'>
### Предупреждение [!toc]
**А что, если ваш новый класс Enemy_0 ведет себя не совсем так, как Enemy?** Поскольку Enemy_0 является подклассом Enemy, он наследует все открытые (не приватные) методы, поля, свойства и прочие элементы класса Enemy; однако у Visual Studio есть неприятная особенность - она автоматически делает методы приватными (private). Откройте класс Enemy и убедитесь, что перед всеми встроенными методами (например, `Awake()`, `Update()` и `OnCollisionEnter()`) стоит просто void (а не private void). Также обязательно проверьте, что метод `Move()` объявлен как public virtual void `Move()`.  

Еще одна распространенная ошибка, которую я часто встречаю в работах студентов, - это то, что они забывают удалить методы `Start()` и `Update()` из класса Enemy_0. Класс Enemy_0 (как и все остальные подклассы Enemy, которые вы создадите в этой главе) использует метод `Update()` из класса Enemy для вызова `Move()`; если этого не произойдет, Enemy_0 не будет двигаться.
</Callout>
