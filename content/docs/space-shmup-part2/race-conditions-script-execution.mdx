Наберитесь терпения: это важно, и, скорее всего, в будущем вы с подобным столкнетесь. К тому же, это необходимо для работы игры.

1. Добавьте строки из листинга кода в метод `Awake()` скрипта Hero.  
    Листинг кода Hero.cs

```c#
public class Hero : MonoBehaviour {
    …

    void Awake() {
        if (S == null) {
            S = this; // Set the Singleton
        } else {
            Debug.LogError("Hero.Awake() - Attempted to assign second Hero.S!");
        }
        // fireEvent += TempFire;

        // Reset the weapons to start _Hero with 1 blaster
        ClearWeapons();
        weapons[0].SetType(eWeaponType.blaster);
    }
    …

}
```

2. Сохраните скрипт Hero в Visual Studio, вернитесь в Unity и нажмите кнопку Play. Вы можете увидеть
сообщение об ошибке, подобное следующему (а можете и не увидеть):  
`NullReferenceException: Object reference not set to an instance of an object
Main.GET_WEAPON_DEFINITION (eWeaponType wt) (at Assets/__Scripts/
Main.cs:82)`    
`Weapon.SetType (eWeaponType wt) (at Assets/__Scripts/Weapon.cs:92)
Hero.Awake () (at Assets/__Scripts/Hero.cs:37)`  

В этом-то и вся суть «состояний гонки» (race conditions): столкнетесь вы с ними или нет - дело случая, поскольку всё зависит от того, в каком порядке скрипты будут выполнять свои методы `Awake()`. Вот способ гарантированно воспроизвести эту ошибку (пожалуйста, выполните шаг 3, даже если ошибка у вас уже возникла):  

3. В главном меню Unity выберите *Edit > Project Settings…*.
    - a. В левой части окна Project Settings (Настройки проекта) выберите пункт Script Execution Order (Порядок выполнения скриптов). На этом экране можно задать последовательность выполнения конкретных скриптов. Вы увидите пункт Default Time (время выполнения по умолчанию, когда срабатывает большинство скриптов), а также (возможно) несколько других скриптов, относящихся к TMPro (TextMesh Pro) и системам GUI и Event в UnityEngine.
    - b. Нажмите кнопку «+» в правом нижнем углу списка скриптов и выберите из списка Hero. Это поместит класс Hero в самый низ стека выполнения (со значением 100), что гарантирует его выполнение после всех остальных скриптов.
    - c. Нажмите на поле в правой части строки Hero в стеке и установите значение -50. Это переместит его в стеке чуть выше пункта Default Time, а значит, он будет вызываться раньше большинства скриптов.
    - d. Нажмите кнопку Apply (Применить), чтобы сохранить настройки порядка выполнения скриптов, а затем закройте окно Project Settings.
    - e. Теперь при нажатии кнопки Play (Запуск) вы гарантированно увидите ошибку.  

Теперь, когда вы наверняка увидели ошибку, давайте её разберем.  
    `NullReferenceException: Object reference not set to an instance of an object`  

Мы получили исключение NullReferenceException; это означает, что мы пытаемся обратиться к значению объекта, который равен null. В следующей строке указано, где именно возникла ошибка.  
  `Main.GET_WEAPON_DEFINITION (eWeaponType wt) (at
Assets/__Scripts/ Main.cs:82)`  

Это означает, что (в моем коде) это произошло на строке 82 скрипта Main.cs (номер строки
в вашем коде может быть другим, но сама строка должна быть той же). Если вы
дважды щелкнете по ошибке в верхней половине панели консоли, вас должно перенаправить непосредственно на строку,
содержащую ошибку. Давайте посмотрим:  

```c#
if (WEAP_DICT.ContainsKey(wt)) { // b
```

Единственный объект, к которому здесь происходит обращение, - это WEAP_DICT; следовательно, он, должно быть, еще не был инициализирован на момент вызова `Hero.Awake()`. Но где же тогда задается WEAP_DICT? Это происходит в методе `Awake()` класса Main... и именно в этом заключается проблема. Из-за настроек порядка выполнения скриптов (Script Execution Order), заданных нами на шаге 3, метод `Hero.Awake()` выполняется раньше этапа Default Time, тогда как метод `Main.Awake()` - наряду с методами `Awake()` всех остальных скриптов, для которых не установлен явный порядок выполнения, - срабатывает именно в рамках Default Time. Таким образом, Hero пытается получить значение `WEAP_DICT` до того, как Main успевает его задать.  

Чтобы исправить это, нужно обеспечить выполнение Main перед Hero. Можно было бы просто переместить Hero в стеке после Default Time, но я предпочел бы гарантировать, что Main выполняется раньше всех остальных элементов нашего кода, воспользовавшись настройками Script Execution Order, показанными на рисунке.

Настройки порядка выполнения скриптов: для Main и Hero задано выполнение перед Default Time.  

4. В главном меню Unity выберите *Edit > Project Settings…*
    - a. В левой части окна Project Settings нажмите на пункт Script Execution Order.
    - b. Нажмите кнопку «+» в правом нижнем углу списка скриптов и выберите из списка Main. Это поместит скрипт Main в самый низ стека порядка выполнения (со значением 100).
    - c. Нажмите на поле в правой части строки Main в стеке и установите значение -75.
Это переместит его в стеке непосредственно над скриптом Hero.
    - d. Нажмите кнопку Apply, чтобы применить настройки порядка выполнения скриптов, а затем закройте окно Project Settings.  

В результате всего этого окончательные настройки порядка выполнения скриптов должны выглядеть как на рисунке.

(Если вы не видите записи TMPro на своем компьютере, не беспокойтесь. Они
устанавливаются автоматически TextMesh Pro, если они вам когда-либо понадобятся. Единственными важными элементами порядка выполнения скриптов на данном этапе являются позиции Main, Hero и Default Time.)  

Когда вы нажмете «Играть», ошибка больше не будет появляться, потому что Main определит
WEAP_DICT до того, как Hero попытается прочитать из него. Вы также заметите, что добавленные нами строки в
`Hero.Awake()` приводят к тому, что у игрока в начале игры будет только один бластер,
независимо от того, что было установлено в префабе оружия. В любом случае, нам, вероятно, следует это исправить.

5. Остановите воспроизведение. Затем выберите префаб Weapon в папке _Prefabs и сбросьте значение поля Type компонента Weapon (Script) обратно на None.
