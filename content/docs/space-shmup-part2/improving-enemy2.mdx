Однако добиться того, чтобы вращение соответствовало нашим замыслам, используя лишь математическую формулу (подобную той, что мы применяли для позиции), будет весьма непросто. На рисунке *a* показана математическая кривая, используемая нами для линейной интерполяции положения корабля, а на рисунке *b* - кривая, которую я пытался применить для обеспечения плавного вращения... но результат, честно говоря, выглядел ужасно: корабль совершал гораздо больше колебаний, чем мне хотелось бы. Когда требуется более гибкое управление кривой, чем это возможно с помощью уравнения, отличным решением становится использование `AnimationCurve`. `AnimationCurve` представляет собой набор точек на графике, позволяющий управлять преобразованием одного значения (в диапазоне [0..1]) в другое - так же, как мы это делали с помощью математических формул, но гораздо проще и удобнее. Благодаря экспериментам с математическим описанием кривой (рисунок b) у меня уже было представление о том, какая именно форма `AnimationCurve` мне нужна; при этом оказалось, что получить желаемую кривую в окне Curve Editor гораздо проще, чем подбирать математические параметры.

(a) Синусоидальная кривая плавности (easing curve), используемая для движения Enemy_2; (b) моя неудачная
попытка использовать синусоидальную кривую плавности для управления вращением Enemy_2; (c) AnimationCurve,
решившая проблему с вращением Enemy_2  

Внесите в скрипт Enemy_2 следующие изменения, чтобы использовать AnimationCurve:  

1. Откройте скрипт Enemy_2 в Visual Studio и внесите изменения.  
    Листинг кода Enemy_2.cs

```c#
public class Enemy_2 : Enemy {
    [Header("Enemy_2 Inscribed Fields")]
    public float lifeTime = 10;
    [Tooltip("Determines how much the Sine wave will ease the interpolation")]
    public float sinEccentricity = 0.6f;
    public AnimationCurve rotCurve; // a
    …

    public override void Move() {
        // Linear interpolations work based on a u value between 0 & 1
        float u = (Time.time - birthTime) / lifeTime;

        // If u>1, then it has been longer than lifeTime since birthTime
        if (u > 1) {
            // This Enemy_2 has finished its life
            Destroy( this.gameObject );
            return;
        }

        // Use the AnimationCurve to set the rotation about Y
        float shipRot = rotCurve.Evaluate(u) * 360; // b
        if (p0.x > p1.x) shipRot = -shipRot; // c
        transform.rotation = Quaternion.Euler(0, shipRot, 0);

        // Adjust u by adding a U Curve based on a Sine wave
        u = u + sinEccentricity * (Mathf.Sin(u * Mathf.PI * 2));
        …
    }
}
```

    - a. Это добавляет публичное поле типа AnimationCurve, которое можно редактировать в окне Inspector.
    - b. Чтобы использовать AnimationCurve для преобразования значения, мы вызываем метод Evaluate(u) для исходного значения u (то есть значения u до применения кривой плавности типа «синусоида»). Полученное значение в диапазоне [0..1] затем умножается на 360, обеспечивая полный поворот на 360°.
    - c. Если Enemy_2 движется справа налево (а не слева направо), измените направление вращения на противоположное, чтобы движение выглядело более естественным.  

Вращение `shipRot` будет выполняться вокруг оси Y игрового объекта `Enemy_2`, благодаря чему корабль будет естественно крениться. Однако перед этим необходимо задать кривую анимации `rotCurve` в инспекторе Unity.  

2. Сохраните скрипт Enemy_2 и вернитесь в Unity.
3. Выберите префаб Enemy_2 в папке _Prefabs на панели Project. Вы увидите темный
прямоугольник рядом с полем rotCurve в разделе «Enemy_2 Inscribed Fields»
компонента Enemy_2 (Script) на панели Inspector.
    - a. Щелкните по темно-серому прямоугольнику, чтобы открыть окно Curve Editor (редактор кривых).
    - b. В окне Curve Editor щелкните по второй маленькой кривой, отображаемой в нижней части
окна (той, что выглядит как прямая линия, идущая из левого нижнего угла в правый верхний).
Это поместит данную кривую в окно, создав точки с координатами [ 0.0, 0.0 ] и [ 1.0, 1.0 ].
4. Теперь нужно добавить еще четыре точки. Для каждой точки дважды щелкните по линии
в окне Curve Editor, чтобы создать точку, а затем перетащите ее в нужное место. Если
удерживать клавишу Command (или Ctrl в Windows), точки будут привязываться к сетке
с шагом 0,1 единицы, что значительно упрощает задачу. У каждой точки будут
маркеры (ручки) по бокам, позволяющие задать касательную кривой в этой точке;
располагайте все маркеры на той же высоте (координате Y), что и точка, к которой они
относятся (то есть делайте все касательные плоскими и горизонтальными). Все эти
точки показаны на рисунке *c*. Вы можете изменить размер окна Curve Editor, если
изначально оно кажется слишком маленьким.
    - a. Разместите точку в координатах [ 0.1, 0.0 ].
    - b. Поместите точку в координаты [ 0.4, 0.5 ].
    - c. Поместите точку в координаты [ 0.6, 0.5 ].
    - d. Поместите точку в координаты [ 0.9, 1.0 ].
5. Закройте окно Curve Editor; вы увидите, что уменьшенная копия созданной вами кривой теперь отображается в поле rotCurve (в прямоугольнике) в окне Inspector.
6. Нажмите кнопку Play в Unity: теперь корабли Enemy_2 должны наклоняться (выполнять крен) при смене направления движения - это выглядит гораздо лучше и позволяет эффектно продемонстрировать 3D-модели.

### Дальнейшее улучшение AnimationCurve для Enemy_2 [!toc]

Всё идет отлично, но мы можем улучшить результат, если развернем корабль Enemy_2 по направлению его движения и заменим вращение вокруг глобальной оси Y на вращение (тангаж) вокруг локальной оси X самого корабля. Для этого потребуется внести небольшие изменения как в код, так и в префаб Enemy_2. Начнем с кода.  

1. Откройте скрипт Enemy_2 в Visual Studio и внесите изменения в код.  
    Листинг кода Enemy_2.cs

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class Enemy_2 : Enemy {
    …
    [SerializeField]
    private float birthTime;

    private Quaternion baseRotation; // a

    void Start () {
        …
        // Set the birthTime to the current time
        birthTime = Time.time;

        // Set up the initial ship rotation // b
        transform.position = p0;
        transform.LookAt(p1, Vector3.back);
        baseRotation = transform.rotation;
    }

    public override void Move() {
        …
        // Use the AnimationCurve to set the rotation about Y
        float shipRot = rotCurve.Evaluate(u) * 360;
        // if ( p0.x > p1.x ) shipRot = -shipRot; // c
        // transform.rotation = Quaternion.Euler(0,shipRot,0); // c
        transform.rotation = baseRotation * Quaternion.Euler(-shipRot, 0, 0); // d

        // Adjust u by adding a U Curve based on a Sine wave
        u = u + sinEccentricity * (Mathf.Sin(u * Mathf.PI * 2));
        …
    }
}
```

    - a. Кватернион `baseRotation` хранит ориентацию объекта `Enemy_2`, когда он находится в точке `p0` и смотрит (то есть направлен) на точку `p1`.
    - b. Этот фрагмент кода размещает `Enemy_2` в точке `p0`, разворачивает его в сторону `p1`, а затем сохраняет полученную ориентацию в `baseRotation`. Вызов `transform.LookAt(p1, Vector3.back)` направляет ось `transform.forward` данного объекта на точку `p1`. Второй параметр, `Vector3.back`, указывает методу `LookAt()`, что после поворота на `p1` локальная ось Y (ось «вверх») объекта должна быть направлена ​​назад вдоль глобальной оси -Z (то есть в сторону главной камеры).
    - c. Обязательно закомментируйте обе эти строки.
    - d. Здесь выполняется умножение `baseRotation` (сохраненного на этапе // b) на новое вращение на угол `-shipRot` вокруг локальной оси X корабля. Мы обсудим это в ближайшее время.

2. Сохраните скрипт Enemy_2 и вернитесь в Unity.  

Если сейчас нажать кнопку Play в Unity, результат будет выглядеть не совсем корректно. К счастью, это легко исправить.  

3. Дважды щелкните по префабу Enemy_2 в папке _Prefabs на панели Project, чтобы открыть его в режиме редактирования префаба (Prefab Editor).
4. На панели Hierarchy внутри редактора префаба нажмите на треугольник раскрытия рядом с Enemy_2, чтобы увидеть дочерний объект enemy2 (исходную модель этого корабля).
5. Выберите модель enemy2; вы увидите, что ее поворот (Rotation) установлен как [ 90, 180, 0 ]. Это было необходимо для того, чтобы направить положительную ось Z (ось «вперед») модели вниз относительно корневого объекта префаба Enemy_2. Однако теперь, когда мы используем метод `transform.LookAt()` для ориентации положительной оси Z объекта Enemy_2 в сторону точки p1, нам нужно убрать этот поворот дочернего объекта enemy2.
6. Установите поворот (Rotation) компонента Transform объекта enemy2 в значение [ 0, 0, 0 ]. Теперь модель enemy2 должна быть ориентирована вдоль оси «вперед» объекта Enemy_2 (направлена ​​от камеры редактора префабов).
7. Нажмите кнопку Scenes в верхней части панели Scene, чтобы выйти из режима редактирования префаба.
8. Сохраните сцену и нажмите кнопку Play в Unity.  

Теперь движение кораблей Enemy_2 должно выглядеть гораздо эффектнее: они будут влетать в кадр, выполнять широкую петлю и улетать за пределы экрана.  

Умножение кватернионов выполняется аналогично умножению матриц 4x4, поэтому порядок перемножения определяет, будет ли преобразование локальным или глобальным. В данном случае нам требуется локальное вращение корабля вокруг его собственной оси X, поэтому мы применяем поворот по оси X после базового поворота (baseRotation).  

9. Если вы хотите увидеть разницу между локальным и глобальным вращением, можно изменить строку
`// d` в листинге кода, чтобы поменять порядок вращения на обратный:

```c#
transform.rotation = Quaternion.Euler(-shipRot, 0, 0) * baseRotation; // d
```

Если изменить эту строку, корабль Enemy_2 будет вращаться вокруг глобальной оси X вместо своей
локальной оси X (и выглядеть это будет гораздо хуже).  

10. Обязательно верните строку `// d` в листинге кода к исходному виду, сохраните файл и убедитесь в правильности работы, прежде чем переходить дальше.  

Возможность выбирать между локальным и глобальным вращением, просто меняя порядок перемножения поворотов, - это огромное преимущество подхода, при котором вращения во всех современных игровых движках хранятся в виде кватернионов. Чтобы запомнить, какой порядок соответствует глобальному, а какой - локальному вращению, можно воспользоваться мнемоническим правилом «Last is Local» («Последний - локальный»): если требуется локальное вращение, соответствующий поворот должен применяться к игровому объекту (GameObject) последним.
