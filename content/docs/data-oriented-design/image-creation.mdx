1. В папке *Assets > Scenes* панели Project откройте сцену
сцену *Scene_OOP*. В ней должны быть все изменения, которые мы внесли в
разделе «Настройка сцены».
2. Выберите *Quad* в иерархии.
3. Создайте и добавьте новый скрипт *Perlin_OOP* на C# к Quad:
a. В нижней части инспектора Quad Inspector нажмите кнопку *Add Component*.
b. Введите *Perlin_OOP* в поле поиска во всплывающем окне «Добавить компонент».
c. Нажмите *New script*.
d. Нажмите *Create and Add*.  

Теперь в панели «Проект» должен отображаться скрипт *Perlin_OOP*, а в инспекторе квадов — компонент
*Perlin_OOP (Script)*.  

4. Сохраните сцену.
5. Дважды щелкните скрипт *Perlin_OOP* на панели «Проект», чтобы
открыть его в Visual Studio.
6. В Visual Studio полностью замените скрипт *Perlin_OOP* кодом из
листинга:

```c#
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

[RequireComponent( typeof(MeshRenderer) )] // a
public class Perlin_OOP : MonoBehaviour {
    [Header( "Inscribed" )] // b
    public int textureSize = 1080;

    [Header( "Inscribed / Dynamic" )] // b
    public float noiseScale = 10;
    public Vector2 noiseOffset = Vector2.zero;
    public Vector2 offsetVel = new Vector2( 1, 0 );

    Material _mat;
    Texture2D _tex;

    void Start() {
        _mat = GetComponent<MeshRenderer>().material;

        InitTex();
        _mat.mainTexture = _tex;
    }

    void InitTex() {
        _tex = new Texture2D( textureSize, textureSize, TextureFormat.RGBA32, false ); // c

        UpdateTex();
    }

    void Update() { // d
        noiseOffset += offsetVel * Time.deltaTime;
        UpdateTex();
    }

    void UpdateTex() { // e
        // Generate the array to fill
        Color[] pixels = new Color[textureSize * textureSize]; // f

        // Precalculate some math // g
        float noiseMult = noiseScale / (float) textureSize;
        int ndx = 0;
        float x, y, u;
        float minusHalf = -textureSize * 0.5f;
        for ( int v = 0; v < textureSize; v++ ) {
            for ( int h = 0; h < textureSize; h++, ndx++ ) { // h
                x = ( ( minusHalf + h ) * noiseMult ) + noiseOffset.x; // i
                y = ( ( minusHalf + v ) * noiseMult ) + noiseOffset.y;

                u = Mathf.PerlinNoise( x, y ); // j

                pixels[ndx] = new Color( u, u, u, 1 ); // k
            }
        }

        _tex.SetPixels( pixels ); // l
        _tex.Apply( false );
    }
}
```

- a. Этот атрибут RequireComponent сообщает Unity, что для работы
кода на этом GameObject требуется компонент MeshRenderer. Quads уже поставляются с
MeshRenderer, так что все в порядке. Я включаю такие проверки для
того, чтобы в случае, если MeshRenderer каким-то образом не был
присоединен к Quad, он был бы присоединен с помощью
этого атрибута.
- b. Эти два разных атрибута Header различают поля, которые нельзя
изменить во время воспроизведения («Inscribed»), и те, которые
можно настраивать во время работы игры («Inscribed /
Dynamic»).
- c. Этот вызов конструктора Texture2D на самом деле представляет собой
одну строку. Я разделил его здесь, чтобы он поместился на странице
книги. Если вы опустите разрыв строки, код все равно будет работать
нормально.
- d. Метод `Update()` перемещает noiseOffset на основе скорости и
времени, чтобы сдвинуть изображение, что позволяет нам увидеть
частоту кадров.
- e. `UpdateTex()` — который вызывается в конце `InitTex()` и один
раз в каждый кадр — генерирует новый массив Colors для хранения
пикселей создаваемого изображения. Он использует метод шума
Перлина (Perlin noise) Unity для заполнения каждого пикселя.
- f. Unity ожидает, что необработанные данные изображения будут
храниться в виде массива цветов, которые располагаются в
одномерном массиве: сначала левый нижний пиксель, затем
остальные пиксели нижней строки, а каждая последующая строка
(последовательно вверх) добавляется в конец массива.
- g. Здесь я заранее вычисляю несколько значений, одинаковых для всех
пикселей. noiseMult учитывает размер пикселя изображения и
noiseScale (устанавливаемый в Inspector) для рендеринга
изображения размером 10x10 единицы шума Перлина. Параметр `minusHalf` смещает изображение
таким образом, что при изменении значения `noiseMult`
масштабирование происходит вокруг центра изображения (а не левого
нижнего угла).
- h. Это первый раз в этой книге, когда я использую интересную
особенность операторов `for`. Как в блоке инициализации, так и в
блоке итерации цикла `for` можно выполнять несколько операторов,
разделенных запятой. Здесь блок итерации выполняет как `h++`, так и
`ndx++`. Аналогично, в блоке инициализации несколько инициализаций
можно разделять запятыми.
- i. При размере изображения по умолчанию (1080) этот математический
выраз сгенерирует координаты x и y для каждого из 1 166 400 пикселей
(то есть 1080*1080). Включение noiseOffset смещает координаты
центра изображения в каждом кадре (если offsetVel не лежит в
диапазоне [0, 0]).
- j. Здесь вызывается метод `Mathf.PerlinNoise()` с
сгенерированными нами координатами, возвращая значение от 0 до
1. Честно говоря, мне действительно не нравится метод
`PerlinNoise()` в библиотеке Mathf. Один из аспектов, который
мне в нём нравится меньше всего, заключается в том, что для всех
координат, где `x` и `y` являются целыми числами, результат всегда будет
равен `0,5`, а это означает, что если передать сетку координат, все
элементы которой являются целыми числами, результат в каждой
точке будет равен `0,5`, что приведёт к получению очень серого
изображения или очень плоского ландшафта. Согласно документации, результат может быть чуть меньше 0 или чуть больше 1, что
является ещё одной причиной не любить эту реализацию шума Перлина.
- k. Значение `u`, сгенерированное `PerlinNoise()`, передается в
параметры red, green и blue конструктора Color (четвертый параметр
— альфа, поэтому мы передаем 1, чтобы сделать изображение
полностью непрозрачным).
- l. Наконец, пиксели назначаются в Texture `_tex` все сразу. Это
значительно быстрее, чем поочередный вызов `SetPixel()` для всех
более чем миллиона пикселей. Обратите внимание, что затем
необходимо вызвать `_tex.Apply()`, чтобы фактически обновить
текстуру на видеокарте.  

7. Сохраните скрипт *Perlin_OOP* в Visual Studio и вернитесь в Unity.
8. Нажмите «Play» в Unity, и вы должны увидеть нечто похожее на

Выглядит неплохо, но можно и лучше. Как видно в статистике на рисунке, на моем ноутбуке игра работает со скоростью 10 кадров в секунду (fps),
что не очень хорошо. Кроме того, картинка выглядит как размытый беспорядок. Давайте сделаем шум на изображении более интересным, используя октавы.  

>Линии симметрии, которые вы видите (т. е. изображение, отраженное относительно координаты [ 0, 0 ]), также являются артефактом метода Mathf.PerlinNoise в Unity.  

>Если вы хотите посмотреть частоту смены кадров на вашем компьютере, нажмите кнопку
*Stats* в верхней части панели «Игра».  

9. Но сначала сохраните сцену!
