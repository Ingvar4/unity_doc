Начнем с добавления Unity Gradient в класс `Perlin_DOTS`.  

1. Откройте *Perlin_DOTS* в Visual Studio и внесите изменение, как показано в листинге:

```c#

public class Perlin_DOTS : MonoBehaviour {
    [Header( "Inscribed" )]
    public int textureSize = 1080;
    public Gradient colorGradient;

    [Header( "Inscribed / Dynamic" )]
    …
}
```

2. Сохраните файл *Perlin_DOTS* в Visual Studio и вернитесь в Unity.  

Выберите Quad в иерархии, и вы увидите
поле `colorGradient` в компоненте *Perlin_DOTS (Script)* инспектора Quad, как
показано на рисунке, но у вас оно пока будет полностью белым.  

3. Щелкните поле colorGradient справа от надписи (в данный момент
оно полностью белое), чтобы открыть окно Gradient Editor

<img src="/unity_doc/images/ex44.jpeg" alt="1" style={{  height: 'auto' }} />

colorGradient, отображаемый в инспекторе и окне Gradient Editor  

4. В окне «Редактор градиента»:
        - a. Убедитесь, что для параметра «Режим»(Mode) градиента выбран вариант
«Смешивание»(Blend) (под курсором мыши на рис.). Это должно быть
значением по умолчанию и обеспечит плавный градиент.
Каждый пятиугольный значок-маркер внизу прямоугольника градиента в
редакторе представляет отдельный цвет. Вы можете щелкнуть под
прямоугольником, чтобы добавить еще один. (Маркеры над
прямоугольником представляют альфа-канал (т. е. прозрачность), как вы
видели в предыдущей главе.)
        - b. Щелкните под прямоугольником градиента, чтобы добавить
пятиугольные маркеры для цветов в местах, аналогичных
показанным на рисунке (не беспокойтесь о точном
расположении).
        - c. Щелкните каждый цветовой маркер, а затем щелкните образец цвета
ниже, чтобы настроить цвета градиента примерно так, как показано на
рисунке. Необязательно добиваться полного совпадения. Вы также
можете сохранять градиенты в качестве пресетов, используя область
«Пресеты» в редакторе градиентов. Эти пресеты хранятся на вашем
компьютере в настройках Unity.
        - d. Когда вы будете довольны своим градиентом, закройте окно
редактора градиентов.  

В ООП можно вызвать `colorGradient.Evaluate( u )` со значением u
в диапазоне [0..1], чтобы получить цвет из градиента (в colorGradient,
u=0 — это синий крайний слева, а u=1 — белый крайнем правом углу). Однако мы не можем сделать это в рамках задания,
поэтому нам нужно преобразовать градиент в другие данные.  

GIF-изображения могут быть очень маленькими, поскольку в них
используется так называемая таблица перевода цветов (CLUT). GIF хранит
один байт (значения [0..255]) для каждого пикселя, а также массив из 256 24-
битных цветов. При просмотре GIF-файла, если байт пикселя равен 45,
компьютер отображает 45-й цвет в CLUT. Здесь мы сделаем нечто очень
похожее, преобразуя байт, который мы использовали для создания
изображения в оттенках серого, в цвет с помощью NativeArray из Color32.
Создание нашей CLUT происходит немного медленно, поэтому мы будем
делать это только при необходимости: один раз в `Start()`, а затем снова
всякий раз, когда вы проверяете булево значение `regenCLUT` (что
необходимо сделать, если вы изменяете `colorGradient` во время
воспроизведения).  

5. Откройте файл *Perlin_DOTS* в Visual Studio и внесите изменения, показанные в листинге

```c#
public struct PerlinImageJob : IJobParallelFor {
    [ReadOnly] public NativeArray<Color32> pixels;
    …
    [ReadOnly] public float numOctaves, lacunarity, persistence;
    [ReadOnly] public bool vignette;
    [ReadOnly] public bool colorize; // a
    [ReadOnly] public NativeArray<Color32> clut;

    public void Execute( int ndx ) {
        …

        // Apply to the pixels
        byte b = (byte) ( 255 * u );
        if ( colorize ) { // b
            pixels[ndx] = clut[b];
        } else {
            pixels[ndx] = new Color32( b, b, b, 255 ); // c
        }
    }
}

[RequireComponent( typeof(MeshRenderer) )]
public class Perlin_DOTS : MonoBehaviour {
    [Header( "Inscribed" )]
    public int textureSize = 1080;
    public Gradient colorGradient;
    public bool regenCLUT = false; // d

    [Header( "Inscribed / Dynamic" )]
    …
    public PerlinVars perlinVars;
    public bool vignette = true;
    public bool colorize = true; // e
    
    Material _mat;
    Texture2D _tex;
    Color32[] clut; // Color LookUp Table // f

    // Start is called before the first frame update
    void Start() {
        …
        _mat.mainTexture = _tex;

        GenerateCLUT(); // g
    }

    void GenerateCLUT() {
        // Generate the Color LookUp Table
        clut = new Color32[256];
        float step = 1f / 255f;
        Color32 col;
        float u = 0;
        for ( int i=0; i<256; i++, u+=step ) { // h
            col = colorGradient.Evaluate( u );
            clut[i] = col;
        }
        regenCLUT = false;
    }

    void Update() {
        // Regenerate clut when regenCLUT is checked
        if ( regenCLUT ) GenerateCLUT(); // i

        noiseOffset += offsetVel * Time.deltaTime;
        UpdateTex();
    }

    void UpdateTex() {
        …
        jobData.vignette = vignette;
        jobData.colorize = colorize;
        jobData.clut = new NativeArray<Color32>( clut, Allocator.TempJob ); // j

        // Schedule the job
        JobHandle handle = jobData.Schedule( jobData.pixels.Length, 1080 );

        // Wait for the job to complete
        handle.Complete();

        // Clean up the jobData.clut memory allocation
        jobData.clut.Dispose(); // k

        _tex.Apply( false );
    }
}
```

- a. Это добавляет булево значение colorize в структуру
PerlinImageJob, а также массив `NativeArray<Color32> clut`.
Как и в случае с пикселями NativeArray, это позволяет системе заданий
очень эффективно работать с `clut`.
- b. Если colorize равно true, b-цвет выбирается из нашей таблицы
цветов CLUT.
- c. Обратите внимание, что это та же строка, что и раньше, но теперь она
находится в блоке `else` нового оператора `if`.
- d. Это добавляет флажок regenCLUT в Инспектор.
- e. Это добавляет флажок colorize в инспектор.
- f. Таблица цветов представляет собой массив Color32, который легко и
быстро преобразуется в `NativeArray<Color32>`, когда это
необходимо.
- g. `GenerateCLUT()` вызывается в конце `Start()`, чтобы
убедиться, что `clut` инициализирована до того, как она
понадобится.
- h. Это еще одно место, где я использую два оператора в блоке итератора
цикла `for` (как `i++`, так и `u+=ustep`). При каждом проходе цикла u
увеличивается на 1/255 часть пути от [0..1], а затем вычисляется
`colorGradient`, возвращая Color для присвоения `i` элементу массива `clut`. Наконец, regenCLUT устанавливается в `false`, чтобы `GenerateCLUT()` вызывалась только один раз (см. // i).
- i. Если установлен флажок regenCLUT, будет вызвана функция
`GenerateCLUT()`, которая снимет флажок regenCLUT.
- j. Здесь массив `Color32[] clut` преобразуется в `NativeArray jobData.clut`. NativeArrays, как правило, не предназначены для
длительного использования, поэтому параметр Allocator.TempJob
указывает системе заданий предупредить нас, если память для
jobData.clut не будет освобождена в течение нескольких кадров.  

Как разработчик на C#, вы, вероятно, не привыкли вручную
освобождать память (обычно этим занимается сборщик мусора C#), но
при работе с NativeArrays и системой заданий управление памятью
ложится на нас. В данном случае, если бы мы выделяли NativeArray в
каждом кадре и никогда не освобождали его, это привело бы к утечке
памяти, которая могла бы вызвать переполнение стека. Строка // k
безопасно освобождает память NativeArray.
- k. Когда задание PerlinImageJob завершилось, нам больше не нужен
NativeArray jobData.clut, поэтому мы вручную освобождаем его,
позволяя C# освободить эту память. Без этой строки мы в конечном
итоге создали бы утечку памяти, так как в каждом кадре выделялась
новая копия jobData.clut.  

6. Сохраните файл *Perlin_DOTS* в Visual Studio, вернитесь в Unity и нажмите
«Play», чтобы увидеть нечто похожее на архипелаг, показанный на
рисунке

Окончательная версия раскрашенного архипелага  

Пока воспроизводится файл *_Scene_DOTS*, вы можете включать и отключать
виньетку и раскраску, чтобы увидеть эффекты. Вы также можете настроить
что угодно в области *Inscribed / Dynamic*  

>Для полной ясности: частота кадров моей версии DOTS значительно колебалась во время
написания этой главы (у меня одновременно были открыты текстовый редактор, два браузера,
редактор изображений и потоковая музыка), но при первом запуске воспроизведения я часто
получал производительность до 42 кадров в секунду, которая затем снижалась до 25–30 кадров в
секунду после некоторого времени воспроизведения.  

Если вы хотите больше разделить острова или сделать их единым массивом
суши, вы можете настроить colorGradient во время воспроизведения,
чтобы увеличить или уменьшить площадь воды, хотя вам нужно будет
отметить regenCLUT, чтобы изменения обновились в панели Game. Конечно,
изменения, внесенные во время воспроизведения, теряются при выходе из
режима воспроизведения, но находясь в этом режиме, вы можете щелкнуть
на три вертикальные точки ( ⋮ ) справа от заголовка компонента *Perlin_DOTS (Script)*
и выбрать *Copy Component*. После остановки режима
воспроизведения, снова нажмите на три точки и выберите *Paste Component Values*, чтобы вставить значения, скопированные во время воспроизведения.

создать более сложную версию нашей процедурной генерации изображений,
работающую со значительно более высокой скоростью, но есть один важный
компонент Unity DOTS, о котором мы еще не говорили.
