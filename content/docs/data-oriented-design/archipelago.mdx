Мы не будем
утруждать себя выполнением этой части в версии с ООП; она и так уже
достаточно медленная.  

Здесь есть два ключевых момента:  

- **Применение виньетки к изображению в оттенках серого**: это умножит
изображение в оттенках серого на круговой градиент, белый в центре и
черный по краям.
- **Окрашивание изображения**: преобразование значения u из диапазона
[0..1] в различные цвета.

### Добавление виньетки к изображению [!toc]

Самой сложной частью виньетки было вычисление эффективной
математической формулы для преобразования значений `h` и `v` в `Execute()`
в красивый круговой градиент. Я использовал Google Sheets, чтобы вычислить
и протестировать формулу на сетке 20x20, которую я применяю в Unity к
полному изображению 1080x1080. На рисунке вы можете увидеть версию круга виньетки из Sheets слева (где красным цветом обозначены области, где 0) и эффект виньетирования изображения в оттенках серого справа.  

>В левой части рисунка вы можете увидеть несколько красных значений, которые меньше 0.
Они станут значениями `u`, но это не будет проблемой, поскольку наш код Unity ограничивает
значение `u` диапазоном [0..1], что означает, что эти значения, меньшие нуля, становятся равными `0`.

        u = ( u + 1 ) * 0.5f;
        // Apply the vignette after moving u to the range ≈[0..1]
        if ( vignette ) {
            loc.x = h / (float) textureSize; // b
            loc.y = v / (float) textureSize;
            loc.x = ( loc.x - 0.5f ) * 3f;
            loc.y = ( loc.y - 0.5f ) * 3f;
            loc.x = 1 - ( loc.x * loc.x );
            loc.y = 1 - ( loc.y * loc.y );
            u *= ( loc.x + loc.y ) * 0.5f;
        }
        if ( u < 0 ) u = 0;
        if ( u > 1 ) u = 1;

        // Apply to the pixels
        byte b = (byte) ( 255 * u );
        pixels[ndx] = new Color32( b, b, b, 255 );
    }
}

- a. Это добавляет переменную bool `vignette` в структуру
`PerlinImageJob`.
- b. Эти вычисления для виньетирования были определены в основном
методом проб и ошибок с использованием таблицы Google Sheet,
показанной на рисунке. Я постарался сделать их максимально
эффективными, повторно используя переменную `float2 loc`, избегая
вычисления квадратного корня и умножая `loc.x * loc.x` вместо
вызова `math.pow( loc.x, 2 )`. 

Если рассматривать только ось x, эти выражения устанавливают `x` в
значение из диапазона [0..1], отражающее расстояние, на которое h
пересекает изображение. Это преобразуется в диапазон [-1.5..1.5], а
затем 1-x2 преобразует его в диапазон
[-1.25..1..-1.25] (имеющий форму перевернутой параболы). Значения `x`
и y усредняются (генерируя градиентный круг, показанный на рисунке) и, наконец, умножаются на `u`, после чего `u` ограничивается диапазоном [0..1].
- c. Эта строка добавляет флажок виньетки в Инспекторе.
- d. Значение виньетки передается в `PerlinImageJob` каждый кадр,
так что установка или снятие флажка в инспекторе включает или
выключает ее в следующем кадре.

### Совет [!toc]
Я упоминаю, что следует избегать извлечения квадратного
корня (о чем студентам-информатикам часто говорят, что это
неэффективно), но если число, из которого вы хотите извлечь
квадратный корень, находится в ОЗУ, то извлечение его из
ОЗУ может занять в 10 раз больше времени, чем само
вычисление квадратного корня. Просто имейте это в виду,
когда думаете об избегании операций, которые в
информатике считаются медленными.  

Всегда проводите тестирование, чтобы выяснить, что на
самом деле вызывает проблемы с производительностью.
Одним из лучших инструментов для этого является Profiler от
Unity. В этих статьях нет места для его подробного
рассмотрения, но вы можете найти несколько учебных
материалов в Интернете, выполнив поиск по запросу «Unity
profiler tutorial»
</Callout>
