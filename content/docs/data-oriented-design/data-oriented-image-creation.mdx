Поскольку новые функции Unity инкапсулированы в пакеты, нам необходимо
импортировать эти пакеты в наш код. Эти шесть строк `using` импортируют
весь код для пакетов C# Job System и Burst Compiler. Далее мы создадим ваш
первый Job, но прежде чем это сделать, я расскажу вам немного о
предыстории.  

**Избегаем данных на основе ссылок**  

Один из основных способов, с помощью которых Unity DOTS повышает
производительность, заключается в ограничении использования любых
данных на основе ссылок. Как обсуждалось ранее, все классы хранятся по
ссылке, поэтому в результате в DOTS нельзя использовать классы! Вместо
этого DOTS использует структуры(*structs*). Структура похожа на класс, но не
включает в себя наследование или полиморфизм, и в результате все данные в
структуре могут храниться вместе в памяти, в одном месте, при условии, что
каждое поле в структуре является *blittable*. Есть еще многое, что нужно узнать
о том, что делает данные *blittable*, но самый простой способ, который я нашел,
чтобы об этом думать , заключается в том, что данные являются *blittable*, если
их можно хранить одним блоком в одном месте. Таким образом, имеет
смысл, что структура, состоящая только из *blittable* данных, сама по себе
также является *blittable*.  

>Более точное (но менее полезное) определение типа blittable, которое я нашел, звучит так: Тип переменной является
blittable, если он хранится одинаково как в управляемой, так и в неуправляемой памяти. Управляемая heap
memory автоматически выделяется в C#, а затем автоматически освобождается сборщиком мусора;
с управляемой памятью проще работать, но она становится фрагментированной и работает медленнее, чем
неуправляемая стековая память.  

Поскольку классический Unity C# почти полностью состоит из классов, а
классы не являются blittable, лишь очень небольшая часть классического Unity
C# может быть частью blittable-типов. В результате Unity написала много
новых библиотек, которые могут заменить привычные нам классы Unity.
Классические типы данных Unity Vector2, Vector3 и Color в DOTS
заменяются более простыми структурами float2, float3 и Color32.
Новая библиотека Unity.Mathematics включает в себя math - структуру со
множеством математических функций, аналогичных тем, что используются
при написании шейдеров для графических карт. Unity.Mathematics также
включает функцию `noise.cnoise()` в качестве замены объектно -
ориентированного метода `Mathf.PerlinNoise()`.  

>Типы Unity C# Vector2, Vector3 и Color на самом деле всегда были структурами (а не
классами), но каждая из них содержит много специфической функциональности (например,
Vector3.magnitude), которая не нужна для большинства операций. Я полагаю, что именно
поэтому от них отказались в пользу более простых float2, float3 и Color32.  

1. Откройте файл Perlin_DOTS в Visual Studio и добавьте новую
структуру `PerlinImageJob` между строками `using` в верхней части
и классом `Perlin_DOTS`. 

```c#
using System.Collections;
…
using Unity.Burst;

public struct PerlinImageJob : IJobParallelFor { // a
    [WriteOnly] public NativeArray<Color32> pixels; // b
    [ReadOnly] public int textureSize;
    [ReadOnly] public float2 noiseOffset;
    [ReadOnly] public float noiseMult;
    [ReadOnly] public float minusHalf;

    public void Execute( int ndx )
        { // c
            int h = ndx % textureSize; // d
            int v = ndx / textureSize;

            float2 loc;
            loc.x = ( ( minusHalf + h ) * noiseMult ) + noiseOffset[0];
            loc.y = ( ( minusHalf + v ) * noiseMult ) + noiseOffset[1];

            float u = noise.cnoise( loc ); // returns [-1..1], not [0..1]! // e
            u = ( u + 1 ) * 0.5f;
            if ( u < 0 ) u = 0;
            if ( u > 1 ) u = 1;

            // Apply to the pixels
            byte b = (byte) ( 255 * u ); // f
            pixels[ndx] = new Color32( b, b, b, 255 ); // g
        }
    }

    [RequireComponent( typeof(MeshRenderer) )]
    public class Perlin_DOTS : MonoBehaviour { … }
```

- a. PerlinImageJob реализует интерфейс IJobParallelFor,
что позволяет системе заданий C# параллельно планировать
выполнение PerlinImageJob на нескольких ядрах процессора.
- b. `NativeArray<Color32> pixels` - это плотно упакованный
массив 4-байтовых элементов Color32, предназначенный для DOTS.
Каждое из общедоступных полей структуры PerlinImageJob
помечено атрибутом, указывающим, как оно используется в
параллельном режиме (например, [WriteOnly] и [ReadOnly]).
Эта информация помогает системе заданий C# более эффективно
планировать задания.
- c. Единственный метод, требуемый интерфейсом IJobParallelFor, -
это `Execute()`, который можно рассматривать как аналог метода
`Update()` для данного задания. Передаваемый в метод `Execute()`
параметр `int ndx` представляет собой номер задания, что в нашем
случае означает индекс массива пикселей NativeArray, вычисления по
которому мы выполняем.
- d. Поскольку ndx - это одномерное целое число, представляющее номер
отдельного пикселя в массиве пикселей, мы берем его остаток по
модулю (%) от textureSize, чтобы получить горизонтальное
положение в изображении (h), и делим (/) его на textureSize,
чтобы получить вертикальное (v). Например, если изображение имеет
размер 100x100, и нам передали ndx 321, то h = 321 % 100 = 21, а v = 321
/ 100 = 3, что дает нам 21-йпиксель в 3-й строке.
- e. Метод `noise.cnoise()` из DOTS заменяет `Mathf
.PerlinNoise()`, однако возвращает другие значения ([-1..1] вместо
[0..1]). Из-за разницы в возвращаемых значениях нам нужно
преобразовать u в диапазон [0..1], а затем убедиться, что оно
ограничено [0..1].
- f. Число типа float `u` преобразуется в байт, который представляет собой
значение беззнакового целого числа от 0 до 255. Если значение байта
становится меньше 0 или больше 255, оно переходит в начало диапазона
(т. е. 256 становится 0), поэтому `u` ограничено условием 0 ≤ u ≤ 1.
- g. Создается Color32, состоящий из четырёх байтов: красного, зелёного,
синего и альфа-канала (точно так же, как Color, используемый в ООП,
но с байтами из диапазона [0..255] вместо чисел с плавающей запятой из
диапазона [0..1]). Затем этот Color32 присваивается позиции ndx в
NativeArray пикселей.  

Система заданий будет использовать экземпляры PerlinImageJob для
распределения работы между несколькими ядрами процессора и вызовет
`Execute()` для каждого Color32 в массиве pixels NativeArray, но нам
все еще нужно написать класс MonoBehaviour Perlin_DOTS, который
будет планировать работу PerlinImageJob так, чтобы он запускался в
каждом кадре.  

2. Снова откройте файл Perlin_DOTS в Visual Studio и внесите в класс
Perlin_DOTS изменения. Вы увидите, что его структура во многом напоминает Perlin_OOP.
После этого вы сможете увидеть, как работает код DOTS.

```c#
[RequireComponent( typeof(MeshRenderer) )]
public class Perlin_DOTS : MonoBehaviour {
    [Header( "Inscribed" )]
    public int textureSize = 1080;

    [Header( "Inscribed / Dynamic" )]
    public float noiseScale = 10;
    public Vector2 noiseOffset = Vector2.zero;
    public Vector2 offsetVel = new Vector2( 1, 0 );

    Material _mat;
    Texture2D _tex;

    void Start() {
        _mat = GetComponent<MeshRenderer>().material;
        _tex = new Texture2D( textureSize, textureSize, TextureFormat.RGBA32, false );
        _mat.mainTexture = _tex;
    }

    void Update() {
        noiseOffset += offsetVel * Time.deltaTime;
        UpdateTex();
    }

    void UpdateTex() {
        // Prepare the job, including precalculating some math
        PerlinImageJob jobData = new PerlinImageJob(); // a

        jobData.pixels = _tex.GetRawTextureData<Color32>(); // b
        jobData.textureSize = textureSize;
        jobData.noiseOffset = noiseOffset;
        jobData.noiseMult = noiseScale / (float) textureSize;
        jobData.minusHalf = -textureSize * 0.5f;

        // Schedule the job
        JobHandle handle = jobData.Schedule( jobData.pixels.Length, 64 ); // c

        // Wait for the job to complete
        handle.Complete(); // d

        _tex.Apply( false ); // e
    }
}
```
- a. Именно здесь код Perlin_DOTS начинает отличаться от версии с ООП.
Здесь мы создаем единственный экземпляр структуры
PerlinImageJob. Затем в следующих строках мы присваиваем
значения всем общедоступным полям с атрибутом [ReadOnly].
Как атрибут, [ReadOnly] является директивой для системы заданий (а
не ключевым словом, как private), поэтому, хотя он и блокирует
значения после запуска задания запущена, он не мешает нам задавать значения заранее (на самом деле,
мы обязаны это делать). Так мы передаем любые данные, одинаковые
для всех экземпляров задания.
- b. Вызов `GetRawTextureData<Color32>()` здесь указывает
jobData.pixels на то же место в памяти, где находится
изображение Texture2D. Формат изображения
TextureFormat.RGBA32 имеет точно такое же расположение
байтов, как и Color32, поэтому запись в pixels будет записывать
в изображение Texture2D _tex в правильном формате!
- c. Теперь, когда мы настроили jobData для нашего PerlinImageJob, мы
можем запланировать его выполнение. Первый параметр сообщает
системе заданий, сколько отдельных экземпляров задания необходимо
запустить (по одному для каждого пикселя), а второй параметр - это
рекомендация по количеству экземпляров, которые следует назначить
потоку в блоке. Более высокое значение второго параметра может
повысить эффективность, но Unity рекомендует максимальное
количество 32 или 64. Этот вызов возвращает дескриптор
JobHandle типа , который можно использовать для последующего
обращения к запланированному заданию.  

>Если вы запускаете несколько различных типов заданий, Unity рекомендует размещать
вызов `Schedule()` как можно дальше от вызова `Complete()`, чтобы система
заданий могла эффективно планировать их все, но при наличии только одного задания
это не является проблемой.
- d. Вызов `handle.Complete()` сообщает системе заданий, что вы
хотите, чтобы она подождала, пока задание handle не будет
завершено, прежде чем продолжить работу в этом методе. Если,
например, вызов `Schedule()` произошел в `Update()`, а вызов
`Complete()` - в `LateUpdate()`, возможно, что система заданий
уже завершила задание к моменту вызова `Complete()`. Однако в
этом случае она просто останавливает все, пока задание не завершится.
- e. Как и в версии с ООП, изображение Texture2D не изменится, пока не
будет вызван `Apply()`.
